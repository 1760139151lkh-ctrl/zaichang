# 主体、动作与镜头连续性

这些是导演规划和验收方法，不是 Gemini 网页提供了骨骼、IK、根运动或相机轨迹字段。把需要稳定的东西写成可观察的关系；硬控制应由实际支持它的工具实现。

## 人物微动与接触

**先锁身份，再限制动作幅度。** 从参考图选少量关键锚点：脸部轮廓、发型、服装、颜色、明显配饰和持物手；描述“同一个人”之外还要明确这些可见细节。参考图之间若服装、角度或年龄冲突，先消除歧义。身份一致要看全片，不能只比较开头与结尾。

待机可以只选轻微呼吸、衣摆微动或自然眨眼中的少数几项。眨眼是有闭合再睁开的事件，应避开剪辑边界；不要求完全不眨眼，也不把每圈突然眨一次当作自然随机动作。呼吸闭环要接相同相位与趋势，不只是肩膀高度相似。不要用“回到原位”掩盖途中换脸、服装花纹沸腾或头部比例变化。

涉及手和脚时写关系：

| 动作 | 提示与检查重点 |
| --- | --- |
| 站立微动 | 双脚位置固定、重心轻微变化、脚底与地面接触，阴影随姿态自然变化。 |
| 持杯或工具 | 指定哪只手、握哪里、物体朝向；检查手指穿透、杯柄换边、物体突然悬空。 |
| 放下再拿起 | 先接触台面再松手，重新抓稳后才抬起；手、物体、影子和遮挡顺序一致。 |
| 看向目标 | 头和视线朝同一对象，目标位置稳定；不要让眼睛瞬移或双眼方向分叉。 |
| 原地步行 | 身体不整体向前漂移，脚与虚拟地面的相对运动合理，步态相位闭合。 |
| 向前走路 | 世界位移与步幅、脚接触匹配；走出去一次通常不是原地循环。 |

这些关系受启发于 [Godot 的 Root motion 说明](https://github.com/godotengine/godot-docs/blob/master/tutorials/animation/animation_tree.rst)和 [Unity 的 LookAt / IK 示例](https://github.com/Unity-Technologies/animation-jobs-samples)。它们说明实际动画系统如何管理位移和约束；将术语写进网页提示不会自动启用这些算法。

## 产品：谁动，谁固定

| 镜头意图 | 应明确的关系 |
| --- | --- |
| 产品转台 | 产品绕自身轴转；相机、摄影棚与光源位置固定。 |
| 相机绕拍 | 产品静止；相机沿一条弧线改变视角，说明高度、距离与大致角度。 |
| 推轨 dolly | 相机向主体移动，焦距保持；会改变透视和视差。 |
| 变焦 zoom | 相机位置固定，改变视角范围／焦距，取景变大或变小。 |
| 拉焦 rack focus | 机位与构图不变，焦点在前后对象间转移；避免无意推动相机。 |

一个短镜头先选一个主要运动，避免同时要求绕一周、推近、变焦、主体再反向旋转。所写的“30 度”“恒定半径”只是消除自然语言歧义，不是可复现的机位数据。

固定灯光不意味着旋转中的金属／玻璃高光保持像素不变；应要求反射随视角连续变化，不能同时要求真实转动和冻结反光。包装文字、接口数量、透明结构、阴影与反射都需检查。正面照无法确定背面；不要为缺失视图编造商品事实。

精确相机路径可以参考 [CameraCtrl](https://github.com/hehao13/CameraCtrl) 的轨迹输入；确定的产品转台可参考 [WebRotate Blender 项目](https://github.com/webrotate360/turntable-animator-for-blender)。这里借鉴任务分解，不安装它们、不宣称 Gemini 网页拥有相同字段。

## 分镜、时序与跨镜头衔接

先把内容压成“准备—主要变化—结果”，每镜明确一个主要表达。复杂广告可以分镜制作，循环底片则通常先尝试单一连续镜头。自然语言时间段帮助节奏规划，不能承诺动作恰好发生在指定帧；精确时长、节拍和停留用剪辑核对。

需要多个镜头时，先建立简短资产说明：人物／产品关键外观、空间布局、光线方向、道具状态和声音。各镜只更新动作与视角，复用必要参考；每镜都重写一套外貌容易产生漂移。

切换时特别看：画面运动方向、视线朝向、左右手、持物状态、光源方向、动作完成到哪一步。不要上一镜刚放下杯子，下一镜未经动作就又拿在另一只手。动作接切可选同一动作不同阶段；匹配剪辑可以利用形状或构图，但不能把视觉相似当作事实连续。

[Scene Machine 的原作者工作流](https://github.com/google-marketing-solutions/scene-machine/blob/main/docs/walkthrough.md)将分镜、候选片段、裁剪、时间线和叠加层分开；它自述不是 Google 正式支持产品，其界面／配置不等于 Gemini 网页。 [LTX 的 conditioning 文档](https://github.com/Lightricks/LTX-2/blob/main/packages/ltx-pipelines/docs/conditioning.md)展示按帧定位引导所需的真实接口，反过来说明“上传几张图”并不自动成为精确时间关键帧。

## 编辑已有视频

针对观察到的问题一次集中改少数因素：例如“只让相机保持静止，人物动作和场景保持原样”。不要为改颜色重写整段剧情。编辑后重看未要求变化的部分，尤其脸、Logo、手部、背景和音轨；“其他不变”仍需验收。

需要严格的可读品牌字、逐帧人物动作或机械装配关系时，选择真实素材、稳定叠加层或可控动画，不靠无限叠加否定词解决。
