# 在场：从网页动态样片到可交互角色

项目共同规范：[角色动态制作](../../../docs/design/CHARACTER_MOTION_PIPELINE_2026-10-25.md)、[心智—状态—动效—在场](../../../docs/design/PRESENCE_SYSTEM_2026-10-25.md)。

## 1. 生成前必须拿到的材料

经审核的角色身份护照、场景家族、姿态接触关系、同景母版、当前故事与用途。若没有这些，先完善设计，不把多个互不兼容的角色/家具图拼成参考输入。

导演包写清相机、光向、服装、支撑、手与物件遮挡、文字安全区、建立/预备/主动作/停留/收束，以及用户打断时希望停在哪个状态。精确文字和真实业务数据留给代码绘制。

## 2. 网页能力照实使用

先观察当前入口与控件，再选参考素材、画幅和编辑方式。历史 Pro 状态不保证当前额度；聊天模型名不等于实际视频后端版本。未提供硬首尾帧控件时，上传两张图不等于硬约束。

3–5 秒是可选剪辑长度，不是网页参数。保持默认网页路线，不将本项目生产需求改写成未经授权的 API 接入，也不把生产生成自动变成产品中的后台工具。

## 3. 三类优先样片

1. **共同注意**：看向当前选区，收到“下一行”纠正，先停旧手势再转向新位置。
2. **递出与让位**：准备把纸转给用户，用户开始写，手把纸留在桌边，安静停住。
3. **归来与收束**：看一眼已保存的路线，再回到陪坐姿态；没有胜利表演，不默认用户要看成绩。

一条样片只验证少数动作假设。首中尾的身份、接触、阴影与物件数量一致；镜头固定优先。没有可信手部素材时改用目光、肩颈与桌面动作。

## 4. 交付给代码端

交付实际视频/关键帧、提示词与可见设置、生成日期、参考版本、完整观看结论、用途分类、可用停留姿态、失败点与降级。标注 reference-only 的片段不能被当作运行功能完成。

代码端把目标映射到真实 sourceAnchor/对象版本；同一动作的眼神、手、纸、灯和声音协同，但每通道只有一个 owner。动画结束不写日历、不确认学校成功、不把上屏记作理解。

## 5. 验收与扩展

完整观看视频，循环至少看三次；联系表仅辅助定位。入场后验证用户输入、目标变化、撤回、隐藏、静音、低动态与资源失败。不能观看时明确动态连续性待验。

样片通过再扩十角色、场景与四主题，覆盖状态分开记录。两轮同类结构性失败就回到构图/姿态/实现路径，不无止境调提示词。失败资产隔离，不进入产品自动加载目录。
