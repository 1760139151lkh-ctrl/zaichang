# 在场事件、观察与前后端联调

这是待实现契约的详细设计。已有代码入口和新增概念分开列出；不要因为文档写了字段就声称它已经上线。共同规格见 [PRESENCE_SYSTEM](../../../docs/design/PRESENCE_SYSTEM_2026-10-25.md)。

## 1. 从已有契约扩展

| 现有入口 | 已有作用 | 扩展方向 |
| --- | --- | --- |
| `src/shared/companion-activity.ts` | 九种活动、run/message/revision 关联及有效回复选择 | 加入可呈现意图适配，保留新用户消息阻断旧提示的规则 |
| `src/shared/companion-continuity.ts` | 原话锚点、话题/共同短语/表达反馈与人格关系 | 把共同注意与纠正绑定真实对象，不把新角色当成旧经历亲历者 |
| `src/shared/source-bookmark.ts` | 资料/笔记/对话的稳定来源引用 | 当前选区与返回位置继续复用来源协议 |
| `src/shared/scene-transfer.ts` | 已有场景地址的跨区传递 | 不携带复制正文，不创建第二 Owner |
| `src/renderer/companion-variants.ts` | 活动与外观映射 | 外观变化与人格变化分别失效相关 cue |
| `src/renderer/companion-scenes.tsx` | 场景登记、支撑、光照与校准 | 增加受控过渡/通道映射，兼容现有 scene schema |
| `src/main/runtime/conversation-rhythm.ts` | 公开草稿与工具前后续接 | 发布、纠正、撤销与动作/音频使用同一有效性依据 |

以上是读取到的现有入口；实现时继续核验具体类型，不根据文档中的别名创建重复服务。

## 2. 建议事件信封

PresenceCue 最少携带 cueId、run/message、sceneInstance、actor/persona/appearance、kind、目标 owner/id/revision/anchor、basis、事实状态、privacy epoch、有效期、中断条件与替代行为。目标版本和角色身份是因果关系的一部分。

用户观察事件建议携带 observationId、deviceId、sceneInstance、目标引用、动作种类、发生时间、expectedRevision 和当前 epoch。只有明确行为进入共享上下文；每帧坐标与未提交输入留在本地交互层。

不要让 renderer 提交“用户已理解”“用户现在难过”之类断言。能够提交的是“用户把该选段移到陪学纸”“用户说下一行”“用户撤回了提案”。

## 3. 生命周期是两条链

**事实链**：proposed → ready → committed / failed / unknown。具体状态映射以原服务为准。

**呈现链**：eligible → preparing → visible → settled，任一阶段可进入 cancelled / superseded / hidden / unavailable。

呈现回执用于调度与诊断，不能修改事实链。视频播放完不是成功；UI 未显示也不代表宿主事务失败。业务先提交而动画未播完时，用户仍能立即使用新状态。

## 4. 去重、乱序与重放

- 以 cueId 与关联事实版本去重；同一事实重复传输不重复递纸或播音。
- 更新同一目标时拒绝低版本写回；跨对象不比较无意义的全局数值大小。
- 恢复页面先取当前快照，再消费仍有效的增量；禁止补播所有后台期间积压 cue。
- 不以“最大事件序号”冒充记忆整理连续完成水位；缺口未处理时保留原文覆盖层。
- 离线设备重连先应用屏障与 tombstone，再恢复内容和主动机会；服务器时间与设备时间用途分开。

## 5. “这里”如何进入心智

用户选择文本或明确指向时，生成实际 owner/id/revision/anchor。PDF 页码、文本偏移、手写对象 ID 与相机矩阵分别记录，不能把截图中的一块矩形永久当作原文身份。

模型可获得当前选区、可见上下文与必要截图的受限组合；外部模型读取遵循既有授权。用户滚动不自动提交整页历史，更不持续录像。新的指向到来后，旧解释引用先失效或标旧，再决定是否继续。

若用户只说“这里”但没有可解析指向，允许用一句自然澄清或让用户点选。诚实地缺一个锚点，比手指精准地指错行更重要。

## 6. 输入与隐私的接管

IME composing、手写 stroke active、拖拽 active 是本地让位信号，不是用户心理诊断。开始输入即可收起非必要呈现；结束后不自动恢复过期提案。

forget/retract/correction 的影响范围不同，依现有 policy 决定。撤回源事件后，依赖它的待播语音、卡片快照、背景计划与模型输出一并失效。当前宿主即时阻断新消费；物理清理、备份及离线设备状态单独追踪。

## 7. 角色与场景切换

换外观：保留人格、称呼、共同经历，重新核验资产兼容性。

换人格：保持公共对象引用，但采用已有 personaRelation 规则；不能让另一人格说“我们昨晚一起写的”而没有相应授权与关系依据。

换页面：sceneInstance 更新，旧页屏幕坐标无效；对象身份仍可跨页。共同对象可在新页重新投影，不能把旧手势搬到错误位置。

## 8. 五条必测因果轨迹

1. PDF 第三行已指向，用户改说第四行，迟到的第三行回答不得重新点亮旧目标。
2. 日程提案已展开，用户开始打字，动作停住但提案数据保留，输入焦点稳定。
3. 运动提交超时，前端不盖成功印章；inspect 后沿真实结果继续，动作 ID 不变。
4. 原话被撤回，队列中还有该句 TTS，取消发生在音频播放前，旧缓存不能恢复。
5. 用户换人格再返回，当前作品与书签仍在，亲历叙述不串角色。

每条记录真实输入、Owner 状态、cue 生命周期和用户可见结果。失败修复针对最早分叉，不通过追加人机话堵住表达。

## 9. 时间、曝光与历史角色身份

进程内动作/间隔使用单调时钟，跨进程重启重新建立基准；日程和来源时效使用明确时区的事实时间。每一来源分别保留获取/发生/适用时刻，不能让刚刷新的天气替旧位置续鲜。

生成、投递、OS接纳、渲染、实际播放、用户报告读过、理解、采纳、完成各有证据。回执缺失保持unknown；跳播与长文局部显示记录范围集合，不用最大游标推定连续曝光。消息、准备材料、通知有独立身份与投影关系，点通知回原对象，不重复执行业务。

角色配置与受限历史分开；切角色保留历史消息的actor/persona版本，当前草稿、TTS与通知重新核称呼和来源。不能把保存的人格配置被旧默认值覆盖的问题交给另一个改写Agent。文本锚点沿原Owner的Unicode码点约定，DOM UTF-16偏移显式转换。
