# 04 · 灵动交互、OpenUI 作品化与文案降噪层：可打断弹簧拖拽与「让布局自己说话」

> **核心位置**：第四优先级（灵动交互与体验跃升层）。融合 `product-design-director/references/motion.md`、`copy.md` 与「在场」OpenUI 动态机制，把设计稿中的每一个创意转化为可触摸、可把玩的鲜活作品。

---

## 一、SwiftUI 级可打断弹簧动效法则（Interruptible Spring Physics）

死板的软件用线性动画（Linear）或不可打断的固定时长过渡；鲜活的「在场」必须遵循**物理动量守恒与即时接管原则**：

1. **三组标准物理弹簧参数（Spring Tokens）**：
   - **轻巧微交互（Hover / 按钮按压 / 胶囊点选）**：`stiffness: 420, damping: 28, mass: 0.8`（约 `160ms–200ms`，清脆利落，毫无拖泥带水）。
   - **空间退让与分屏展开（工作台滑入 / 角色伴读移位 / 书签托盘弹出）**：`stiffness: 280, damping: 26, mass: 1.0`（约 `280ms–340ms`，柔和沉稳，无过冲眩晕）。
   - **拖拽吸附与落座（角色换锚点落座 / 日程块磁吸落位 / 地图收拢）**：`stiffness: 320, damping: 24, mass: 0.9`（带微妙的物理缓冲感）。
2. **随时可打断与即时接管（Instant Interruption & Velocity Handoff）**：
   - 当面板正在展开或角色正在移动时，如果用户指针按下并开始反方向拖动，**必须立即中止当前过渡并直接沿用当前位置与初速度跟随指针**，严禁“等动画播完才响应”或“瞬间跳回起点再闪现”。
3. **无障碍与减少动态支持（Reduced Motion Respect）**：
   - 当系统开启 `prefers-reduced-motion: reduce` 时，将大位移弹簧自动降级为柔和的透明度渐变（`150ms ease-out`），同时完整保留拖拽試放与数据状态反馈。

## 二、全场景五阶段直接操作契约（The 5-Stage Direct Manipulation Contract）

在场中的所有拖拽与直接操作，绝不能只是“鼠标拖个虚影然后突变”，必须完整实现以下五个阶段，并确保**草稿与键盘焦点零丢失**：

| 阶段 | 状态名称 | 视觉、物理与业务行为规范 |
| :--- | :--- | :--- |
| **Stage 1** | **接收 (Pickup)** | 按下瞬间元素轻微浮起（`scale(1.02)` + 柔和暖影加深），原位置保留淡化锚点，指针手型切换为 `grabbing`。 |
| **Stage 2** | **试放 (Preview)** | 移动到目标区域时，目标槽位实时推开邻近元素让出空间，显示半透明试放幽灵块（Ghost Slot）；**注意：试放阶段绝不直接写入后端数据库**。 |
| **Stage 3** | **确认 (Commit)** | 松手落在合法槽位，元素按弹簧曲线平滑落入目标坐标，触发后端带 `expectedRevision` 的原子提交，并显示温和回执。 |
| **Stage 4** | **取消 (Cancel)** | 按下 `Esc` 或拖出有效区松手，元素沿弹簧轨迹平滑飞回原位，目标区恢复原状，正在编辑的输入框草稿纹丝不动。 |
| **Stage 5** | **异常恢复 (Recovery)** | 若因版本冲突或校核未通过导致提交未生效，元素温和回弹并给出说人话的具体原因与一键重试/调整选项，绝不静默吞掉操作。 |

### 六大必落地的核心拖拽与创意交互场景
1. **角色跨家具锚点自然拖拽**：
   - 拖动窗边角色时，角色沿着房间内真实的家具支撑轨迹（如：床沿左端 ↔ 床沿右端 ↔ 书桌前木椅 ↔ 飘窗软垫）平滑移位并切换对应坐姿，绝不悬空乱飞。
2. **工作台与陪伴区无级分屏拖拽**：
   - 拖动中间分隔线可自由调节学习/PDF 工作台与右侧陪伴区的宽度比例（`55%:45%` ↔ `75%:25%`），并带默认黄金比例磁吸点。
3. **日程时间轴拖拽排程与留白保护**：
   - 从对话流中的建议卡片直接拖入日程时间轴，自动计算并高亮显示**准备时间、路途转场（联动校园地图步行耗时）与休息缓冲带**；遇到已有安排时温和提示冲突并给出备选空窗。
4. **PDF 讲义与对话选段拖拽摘录**：
   - 选中 PDF 某段公式/文字或聊天中的某句关键点，直接拖进右侧笔记或底部书签托盘，自动生成带颜色圆点与精确回跳锚点（点击即可翻回 PDF 原页码原高亮处）的笔记卡。
5. **三角钢琴与声学波形互动卡（OpenUI 标杆落地）**：
   - 还原设计稿 `U04–U06` / `U28` 中的经典创意：在讲解物理声学、傅里叶级数、乐理或函数变换时，生成可真实点击弹奏的**三角钢琴键位卡**与**可拖拽调节频率/振幅控制点的实时波形图**，用户拨动参数即可实时听见/看见变化，并将操作状态回流给角色。
6. **聊天流内联校园地图拖拽与全幅无缝展开**：
   - 还原设计稿 `U14–U15` / `U22–U24`：聊天提及教学楼、食堂或琴房时，气泡内直接内嵌可拖拽的手绘立体校园地图，带暖金发光路线与步行时间胶囊；点击展开时平滑放大至主工作台，收起时原视角归位。

## 三、文案消融测试与彻底清零工程黑话（Copy Ablation & Human Voice）

吸收 `product-design-director/references/copy.md` 的最高准则：**“The best interfaces need almost no words because the layout does the explaining.”（最好的界面几乎不需要多余解释，因为布局自己会说话。）**

1. **三秒文案消融测试（The Ablation Test）**：
   - 检查页面上的每一行副标题、说明小字（Helper Text）与空状态提示：如果把它删掉，用户依然能看懂这个区域是干什么的，**立刻删掉它**！
   - 严禁出现：“在此处输入消息与角色对话”、“点击下方按钮切换主题”、“这是您的日程管理面板”等废话文学。
2. **工程术语与调试标签清零清单（Zero Engineering Jargon）**：
   - 全站 UI 严禁出现以下词汇及其变体：
     - ❌ `已接通` / `未接通` / `待验证` / `返回未接入` / `模拟数据`
     - ❌ `3/3` / `Step 1 of 4` / `覆盖率 100%` / `队列中`
     - ❌ `SceneSnapshot` / `PresentationView` / `OpenUI` / `CAS` / `Revision` / `BGE` / `Hermes` / `Luna` / `Sidecar`
     - ❌ 任何文件 SHA-256 哈希串、内部 UUID 或原始 JSON 字段名。
3. **角色化自然微文案（Persona-Infused Microcopy）**：
   - 空状态、加载态与异常提示必须符合当前角色的温和口吻，且给出**具体事实 + 影响 + 可继续路径**：
     - ❌ 错误示范：`[Error 409] Agenda revision mismatch, commit rejected.`
     - ✅ 正确示范（以海铃/祥子口吻）：`刚才那段日程好像刚刚变动过，我先把新方案停在预览区了，你看一眼要不要放在下午四点后？`
