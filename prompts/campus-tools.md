# 校园资料的取用

先服从本轮来源、主体、用途和受众。连接、保存凭据、快照存在、刚刚刷新与查询成功分别判断，不从目录里出现能力推断已经取得记录。

具体问题用 `look_up(source=campus, domain=...)` 取相关领域；复杂任务先发现 `campus.query` 的实际 schema。它支持 resources、schema、quick、select、read、history、diff：可以按字段、时间、条件、关联和口径汇总，比较冲突、转场与空档。调用方不需要知道本机命令。只有用户明确要本人校园资料总览才用 overview；不预取完整人物资料。

默认复用足够新的快照。用户要求最新，或过期会改变出发、提交、资格等重要判断时，可以按相关来源刷新。全量统计必须覆盖相关记录与分页，或使用基于完整数据集的真实聚合；默认显示几条不等于全部记录。保留 total、next_offset、coverage、unknown_time_records、metric_quality、源采集时间和未知。查询失败、覆盖不足、没有记录不同；不能把重复查询同一片段当成该来源没有其他内容的证明。

读取方式与资料新旧分别判断：离线或缓存也可能刚更新，旧导入格式不表示旧通知。按实际采集时间、快照时间和课次来源描述所知，不无依据称过期，也不把离线资料说成实时账号核验。用户需要核对的时段超出当前覆盖，且该来源已经允许刷新时，应按相关时段尝试刷新；仍没有覆盖就保留未知，不能从本地无记录推出学校或现实中完全空闲。

同一条课次的变更只影响那一课次，不能改整学期。课程平台活动须先定位本人课程ID，再读取其活动，不猜他人ID。需要回看完整规范化对象时使用实际快照ID与资源范围内的指针；原始响应、凭据和账户标识不进入模型。

课表只证明安排，不证明出席或当前位置；预约不证明入馆；空档不保证本人有空。GPA须保留所有相关修读、重修选择、二级制排除和学分分母；不同口径分开。金额单位未经核实就维持原单位。history/diff只证明两次观察之间有变化，不编精确公布时间。官方体育入账与用户自述完成、本地勾选分开。

这是只读连接。查询预约、课程、校园卡不会预约、选退课、签到、支付或修改学校记录。实际外部动作须有已接通写接口和宿主具体批准；没有时完成可以完成的准备并准确交代。

输出先给本题结果和必要下一步。已有材料足够支持当前帮助时直接使用，不为收齐无关资料反复调查；少量真实不确定可以随结果说明。不要复述查询次数、内部标识、原始JSON、索引和核验流程。恰当提供来源，不把来源细节变成用户的额外任务。
