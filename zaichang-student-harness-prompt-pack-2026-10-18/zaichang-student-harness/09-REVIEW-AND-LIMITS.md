# 本轮打磨、证据与限制

## 1. 实际进行了哪些工作

本包围绕用户要的 Codex 实施交付完成。通过 GitHub 插件读取固定提交，选择 110 份文件建立源码证据并核对 Git blob；沿主循环、控制、记忆、主动关注、日历、地图、供应商和相关测试入口审阅。完整阅读所附 2904 行记忆讨论；研究 20 个一手来源条目；形成十二维人/环境模型、128 条合成场景和 12 条连续轨迹、实施方案与主提示词。

当前源码的 `localCloudRestriction` 进行了六输入本地函数探针，结果与可移植包装器一并保留。除此之外，本轮没有执行产品模型、Electron、校园接口、Android、npm test 或上游运行时测试。

## 2. 可追踪的打磨过程

以下是实际完成的不同审阅环节，不是宣称做过多轮用户实验。独立审阅发现与文件哈希分别在 evidence 中保留。

| 环节 | 暴露的问题 | 本包怎样修正 |
|---|---|---|
| 附件完整审阅 | 早期提案与后期用户反对的关键词/前置结构化冲突；旧例子被误写成人物事实 | 用户最后纠错优先；示例与本人资料分离；旧报告不当当前证据 |
| 当前源码核对 | “只做地图”与现有日历/记忆/子代理不符；主语义路径已有修复 | 沿用已有引擎和存储；不照旧批评重建，给出当前具体断点 |
| 研究与版本核对 | Hermes 当前文档和锁定接口不同；上游 memory 冻结不是项目原生记忆行为 | 使用 pinned 源码；明确宿主关闭 native memory/background review；区分产品承诺与公开机制 |
| 场景语义抽查 | S001 等将可选候选与明确提醒混用，可能为保护专注擅改闹钟 | 修正 8 条相关情境；全局区分固定提醒、授权派生提醒和主动候选 |
| 独立架构审阅 | 到期队列与发现预算关系不够明确；只防双执行未防跨渠道重复；主设计对缓存/委派链接不足 | 04 补近截止优先、错失原因、统一呈现记录和 05 的明确职责链接 |
| 独立实施审阅 | 混合 guidance 可能泄露；行为证据可能冒成用户明确设定；遗忘范围过宽；重规划写入边界含糊 | 私有 legacy 分流、authority 分离、按对象遗忘、proposed diff 与授权提交分离 |
| 主提示词回读 | 人格比较可能要求同一工具序列；探针措辞可能像全应用复现 | 比较事实和业务效果、不要求同一轨迹；精确输入与静态/探针证据分开 |
| 连续时间线复核 | 用户原话旁附有地点/授权/日期等预判标签，可能绕过真正的语义理解 | 清理 18 处注释到 evaluator_only；自然语言消息只给原话，真实 UI/来源事实独立保留；工具回执等真实调用后才释放 |
| 打包核对 | 目录关系、JSON 字段、编号、引用、合成标识和可移植性 | 用实际核对结果生成 `evidence/package-validation.json`；不把它叫应用验收 |

独立审阅详见 [research-review.md](evidence/research-review.md) 与 [implementation-review.md](evidence/implementation-review.md)。它们记录了真正的发现和修订，没有以“多代理一致”代替证据，也未给未运行的产品打分。

## 3. 证据能证明什么

- 固定提交链接和读取 manifest 可以定位所审源码；选取文件并不等于审完所有仓库行。
- 函数探针可以复查局部词面判断；整轮如何使用其结果来自静态调用链。
- 128 场景验证材料结构和覆盖取舍，不证明真实大学生活已被穷尽，也不证明 Harness 已会处理它们。
- 12 时间线包含目标状态和 fixture。只有后续将其接入真实宿主/模型、逐步执行，才产生行为结果；未来信息不能作为当前模型输入。
- 引用论文/开源框架支持设计取舍和评测维度，不证明在场的情商、GPA 效果、长期信任或通知收益。
- 静态地图/Windows 定位/城市天气不能代替手机、校园分钟级天气和现场可通行验证。

## 4. 仍需实施时验证的范围

第一，T0–T7 是将来的实际代码工作，本包不是已经合并的 PR。尤其背景就绪判定、批量变化出口的用户影响、长段条件召回、时机判断和人格自然性，需按各自层次运行。

第二，完整动态课表、学校假期/调休/考试例外的覆盖取决于具体学校来源；领域 schema 不是覆盖证明。邮箱、钉钉、健康、预约写入和手机持续采集同样需要真实连接与适用授权。

第三，手机离开电脑后的持续运行是产品关键里程碑。当前包给端口和验证路线，不承诺 Electron/Python 已可在手机全天候常驻。远程宿主选择及私人资料部署须在具体方案上落实当时授权。

第四，模型协议与身份接入随版本变化。DeepSeek 当前实际生产选择、Luna 测试代用、官方 ChatGPT 登录分别核验；目录或登录成功不等于所有模型可调用，更不等于真实工具任务已完成。

第五，“完整建模一个人”在这里是系统化理解人的维度、状态、条件、理由、变化与未知。它保留个人自主和空白；不声称准确读取未表达的内心，不把合成场景或人口属性写进真实人格。

## 5. 后续怎样继续打磨才有效

首先跑一个真实可用闭环，找出最早分歧；修共用机制后加未见改写和单条件反事实，再看不同角色与打扰时机是否合适。真正进入小范围使用后，观察是否帮助人完成自己重视的事、有没有打扰或错失，而不是把通知数、记忆条数、工具数或场景数作为目标。

本包足以让 Codex 从实际入口开始实施。遇到新证据可以修改设计，但要保留清楚的因果：哪项观察说明哪里不成立、改了什么、实际行为有什么变化。
