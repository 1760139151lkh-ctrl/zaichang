# 05 · 工程契约、主从代理协同与真机闭环验收层：单一 Owner 与零「买家秀」交付

> **核心位置**：第五优先级（工程底座与终局验收层）。确保前端的惊艳创新建立在坚不可摧的单一事实底座之上，并通过主代理与子代理的高效协同，把每一页都打磨到与黄金设计稿 1:1 媲美。

---

## 一、前后端单一权威 Owner 与数据流转契约

前端打磨绝不能破坏「在场」严谨的系统架构，也绝不能为了图省事在前端伪造一套孤立的假数据：

1. **单一实现与受控通信边界**：
   - `src/` 是唯一产品代码树。
   - **Electron Main** 独占持有：SQLite 数据库、API 凭据、工具执行、文件读写、系统通知与主模型循环（`harness.ts → runtime/hermes.ts → runtime/hermes/sidecar.py →` 锁定的 Python `AIAgent`）。
   - **Renderer** 仅通过 `src/main/preload.ts` 暴露的受控 Bridge / IPC 接口读写状态与订阅流式事件。
2. **各业务域唯一权威 Owner（Single Source of Truth）**：
   - **本人长期记忆**：归 `MemoryService` 与原存储；`recall_experience` 与原生 `memoryInquiry` 是读取调查入口（唯一规范见 `prompts/memory-inquiry.md`）；前端 `localStorage` 只存窗口分屏比例、当前主题代号等纯外观偏好，绝不冒充用户长期记忆。
   - **笔记与摘录**：归 `NotesService`（保留原话、Unicode 范围、真实对话/PDF 来源锚点）。
   - **资料与 PDF**：归 `MaterialService`（保留真实文件引用、页码、分块偏移，预览摘要不等于已读全文）。
   - **日程与提醒**：归 `NativeAgenda`（支持 `planRef`、短票据、完整含准备/转场/休息的时间块及 `expectedRevision` 并发保护）。
   - **校园地图与寻路**：Desktop 与 `apps/review-web` 共用 `src/renderer/map`、`src/main/mapService.ts`、`src/shared/map-routing.ts` 与 `assets/map-v2`。
3. **跨模块拖拽与流转的身份证制度**：
   - 当用户把一道题、一段 PDF 引文、一个地图地点或一条待办跨模块拖到另一区域时，前端传递的 Payload 必须包含：`{ entityId, entityType, expectedRevision, sourceAnchor }`，绝不复制生成无头无尾的孤立对象。

## 二、全分支功能级深度融合规范（Deep Functional Synthesis Across Branches）

1. **先盘点，不盲目覆盖**：
   - 动手前先核查 `git status`、未提交改动、全部本地分支与 GitHub 远端分支。
   - 保护已有的健康工作成果，严禁使用 `git reset --hard` 或用空合并抹掉其他分支中已实现的优秀前端组件或后端接口。
2. **有机功能融合**：
   - 理解各分支背后的产品意图（例如：某一分支实现了更好的 PDF 标注，另一分支实现了更完整的日程试放或角色演出），将它们的数据流、Bridge 接口与视觉样式统一融汇到本技能确立的**九大场景网格与暖灰金四主题体系**下。

## 三、主代理掌舵 + 最大规模子代理并行作战机制

以下分工用于实际执行十二阶段研发，每阶段固定八个子代理，先由主代理理解完整输入、项目全貌与阶段目标，再按独占文件组织；A–D是可覆盖的领域，不另增四组团队。解释、评审和文档审修不因读取本技能自动启动八人。

### 主代理（Main Agent）不可替代的四大亲历职责
1. **亲自看图**：按本次页面与问题查看相关标杆，亲审拟采用的新资产与集成画面，不以子代理汇报代替判断，也不为普通任务强制重看全部历史候选。
2. **掌管审美与创新拍板**：亲自拟定生图标准、空间标尺、十角色动作矩阵及超预期创新点。
3. **跨模块架构统合**：把控全局 `tokens.css`、主壳层布局（Shell Layout）与跨模块状态流转，防止各子代理改出五花八门的局部样式。
4. **亲自实机操作验收**：亲自启动应用、逐页切换、亲手拖拽、并排比对原图与真实渲染画面。

### 子代理（Subagents）并发调度矩阵（按独立职责与文件边界切分）
> **铁律**：严禁派子代理去做“统计文件数量、计算哈希、列目录清单”等毫无创造力的机械杂务！每个子代理都必须承担高价值的实质性创作或工程攻坚任务，且互不争抢同一文件：

- **Subagent Group A（多角色跨场景同景生图与原景分离组）**：
  - 按本技能 `02-visual-matrix-and-imagegen.md` 的四步管线与标准 Prompt，并行生成 `sakiko`、`mutsumi`、`anon`、`tomori` 等十角色在不同场景与四主题下的同景原图、同画布分离图层与标准头像矩阵，交由主代理亲看筛选。
- **Subagent Group B（学习工作台、PDF 共读与 OpenUI 动态作品组）**：
  - 负责 `S2 学习` 与 `S3 资料` 页面精修，落地三角钢琴互动卡、动态波形/函数控制卡、PDF 划选拖拽摘录及无级分屏弹簧交互。
- **Subagent Group C（日程时间轴试放、笔记手账与内联校园地图组）**：
  - 负责 `S4 日程`、`S5 笔记`、`S6 地图` 页面精修，落地时间轴幽灵试放块、转场留白计算、底部胶片书签托盘及聊天内联立体校园地图的无缝展开/收起。
- **Subagent Group D（居室舞台、十角色性格微动作与四主题光学对齐组）**：
  - 负责 `S1 首页`、`S7 角色`、`S8 主题`、`S9 恢复` 页面精修，实现 `Stage` 同坐标绑定、角色沿家具切线拖拽、暖杏/晨雾蓝/暮色紫/夜雨暖金四主题全场景柔光过渡及全局工程黑话清零。

## 四、消灭「买家秀 vs 卖家秀」真机闭环验收清单（Final Verification Checklist）

在宣布任何前端打磨任务完成前，主代理必须逐项完成以下实机检验（缺任何一项实证均视为未完成）：

### 1. 1:1 视口并排视觉核验（Side-by-Side Viewport Check）
- [ ] 将实际运行界面截图与对应黄金设计稿（`U01–U31`）并排放在一起，主代理用 `read_file` 亲眼比对：
  - 磨砂玻璃卡片通透度、圆角比例、阴影柔和度是否达到设计稿质感？
  - 角色的具体姿态、支撑、肢体与遮挡是否成立？全身图是否意外截足，半身构图是否自然？缩放时接触是否稳定、无可感滑移，而非仅以0像素数字自证？
  - 顶部胶囊、底部输入栏、右侧伴读槽位在 `S1–S9` 切页时是否稳如磐石、毫无跳动？
  - 那些原本已经对齐良好的区域是否完好无损？

### 2. 常速连续交互与打断测试（Real-Time Interaction & Interruption Check）
- [ ] **角色拖拽**：拖动角色沿床沿/椅面移动，中途快速反向拉回或松手，弹簧过渡是否丝滑且立即跟手？
- [ ] **日程试放与取消**：拖入日程块查看试放幽灵块与冲突留白，按 `Esc` 取消或松手提交，数据库版本校核与撤回是否正常？
- [ ] **OpenUI 活组件**：弹奏钢琴键、拖动波形控制点、在聊天内联地图中拖拽并展开全屏再返回，状态是否真实流转且原视角保留？
- [ ] **PDF 与笔记联动**：从 PDF 拖一段文字到笔记/书签托盘，点击笔记来源胶囊能否瞬间跳回 PDF 原页码原位置？

### 3. 工程质量与真实模型验证（Build, Test & Live Model Check）
- [ ] 运行 `package.json` 中的既有 `check`（TypeScript 类型检查）、`test`、`build` 全部零报错通过。
- [ ] 真实对话与记忆/工具链验证使用已授权的 **Luna (`gpt-6-luna`)** 通道实测响应，确认角色语气鲜活自然、无客服模板腔、无内部状态词泄露。
