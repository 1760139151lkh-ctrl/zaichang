# GPT Image、Gemini 网页版与前端代码的制作移交

权威制作细则见 [角色动态制作规范](../../../../docs/design/CHARACTER_MOTION_PIPELINE_2026-10-25.md)。本页规定前端执行顺序和交付检查，避免生成端与代码端各做一半。

## 1. 先读的 Skill

读取 [Gemini 视频生成 Skill](../../../../核心技能/Gemini视频生成/SKILL.md)，再按任务读取 web-capabilities、prompt-controls、continuity-and-direction、postproduction-and-review；循环片段另读 seamless-loops。角色图像制作同时遵循当前可用的图像生成技能。用户明确指定网页时不能私自改 API。

## 2. 制作前开一张工单

工单不进入产品界面，至少记录：

- 当前阶段与用户故事、所解决的动作缺口；
- character/persona/appearance、scene family、activity、pose topology、theme、画幅；
- 使用的合格身份参考、母版及版本；
- 这次保持不变的内容、仅允许变化的内容；
- 实际网页可见能力、生成批次预算、退出条件；
- 产物用途：reference-only、静态、分层、环境循环或角色受限片段；
- 代码负责人入口、打断与低动态方案、验收状态。

不要只写“帮我做一段可爱自然的动画”。每条生成需求只验证少数明确假设，例如“用户纠正目标时能不能先收手再转向”。

## 3. 角色矩阵的检查顺序

身份一致 → 场景家族一致 → 姿态接触成立 → 光照匹配 → 遮挡成立 → 动作首中尾连续 → 代码可接管 → 真实页面可用。

前一项不成立就停止扩矩阵。角色坐在桌旁的新母版不能混用旧窗台背景；同名 reading 也不代表相机一致；头像不足以证明全身姿态可用。

现有 `*.scene.json` 与 `companion-scenes.tsx` 是迁移起点。新清单先写转换规则和兼容读取，再增字段；不要让运行时同时读两套互相冲突的角色—场景表。

## 4. 分镜语言的具体要求

先写她是谁、在意对方什么、此刻为什么想说又收住，再写每几秒眼神、手指、衣袖与停顿怎样变化。文学性的表达要落在可见动作里，不用“灵动高级温柔”替代表演，也不用重心、穿透检查代替性格。

生成提示写具体的人与物，例如“她望向画外左侧那页讲义，察觉你翻到了下一行，刚想展开的手势便收小了”；不用“目标、锚点、状态切换”等工程简称描述画面。底层支撑与遮挡另在制作记录和验图中逐项核查。时间轴包括建立、预备、主动作、停留与收束；停留应当像一个人正在等你，而不是必须循环活动才能维持的姿态。完整分秒示例沿权威制作规范第5节。

描述眼神、头、肩、手、物件、光与声音之间的先后关系，同时写哪些部分不动。固定机位是共同注意和代码重建的默认起点，复杂运镜留给明确需要的叙事段落。

提示词中的时间标记是软导演指令。实际生成时长、模型和可用编辑能力以网页实测记录为准；切出 3–5 秒动作不等于生成器支持该秒数参数。

## 5. 视频审核不能被截图替代

先完整观看，再用首/中/尾与接触变化帧排查身份、手指、阴影与穿插；循环至少看三次，检查位置、速度、光线与声音接缝。无法播放时只能声称完成静态帧审查，动态仍待验。

失败分类与重做路径必须记录。两轮同类结构性错误时改变构图、姿态或实现路线；不能无限给同一废片加形容词。每次生成的临时资产放隔离目录，不让运行时 glob 误加载。

## 6. 代码移交分三类

| 类别 | Codex 要做的事 | 验收重点 |
| --- | --- | --- |
| 视觉参考 | 提取幅度、节拍、方向与停留，使用现有动画/布局系统重建 | 用户随时打断，目标可变，业务状态真实 |
| 受控资产 | 接入同画布分层、可控制 rig 或审核片段 | 通道单 owner、接触稳定、可暂停和降级 |
| 展示片 | 用于非交互演示或适合的环境内容 | 明确用途，不冒充可交互功能 |

不要把正文、按钮、动态日期和真实数据烘焙进视频。角色伸手的位置来自当前对象坐标；视频中的手指只能提供动作参考。复杂手—物件关系超出资产能力时改用可信的纸面交互，不造假的抓取。

## 7. 首个纵向样片与扩展门槛

首样片选“这里—下一行—用户开始写—她收手等待—回来继续”：

1. 宿主给出真实对象与锚点。
2. 前端映射到共同注意 cue。
3. 合格角色资产完成看向与收手，纸面高亮由代码控制。
4. 用户中途改目标，旧 cue 被撤销。
5. 低动态与缺素材路径仍能完成同一任务。

通过后才横向扩十角色与四主题。扩展时共享运行机制，分别审核身份与节拍；不能只证明一个角色而声称矩阵全部完成。

## 8. 资产来源与状态

清单记录生成日期、工具实际名称、参考来源、编辑链、母版关系、审核人及范围；不记密钥、账号敏感信息或私有聊天原文。记录 approved/shared-compatible/static-fallback/not-applicable/missing，分开报告。

图片和视频是制作材料；原话、事实和权限仍由原服务管理。资产被撤回或不再允许使用时，停止后续生成与播放，进入明确替代，不从旧缓存悄悄复活。
