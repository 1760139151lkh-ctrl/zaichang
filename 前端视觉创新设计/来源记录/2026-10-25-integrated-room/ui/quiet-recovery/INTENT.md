# 原动作旁的小恢复

希望保住的感受：动作刚才没完成，但桌面、文字和人的注意仍安稳。错误只取得继续所需的注意，不占据欢迎画面。

比较过三个关系：全局 toast 容易失去对象；缩小长条仍会把输入变成告警区；原控件旁一行短状态与真实恢复动作，可以把原因未知、等待、来源变化和结果未确认分别表达。采用第三种，并只在真正需要时补一句人话。头像由角色专线独立创作，本图不用角色掩盖故障。

四个视图是不同时间或对象，不能全部同时堆进产品：

- 夜间欢迎态：附件原动作边只有“刚才没打开 / 重试”，保原草稿、原焦点。重试只有真实可执行时存在，未知原因不擅称网络问题。
- 日间原文纸角：来源变化后撤旧高亮，原书签旁“资料有变化 / 回原处”。回原处沿原owner对象与版本，不能用文字匹配猜新位置。
- 同一夜间composer两拍：网络等候为“还在连接 / 取消”；发送回执未知为“这条还没确认 / 查看结果”。两者按真实事实替换，不叠加；后者先核原attempt，不能盲重发。
- 日间笔记保存：原草稿实际保留并可编辑才写“未保存 · 原稿还在 / 重试”。不能据动画、localStorage偏好或旧回执谎称资料已保存。

输入接收、事实回执、表演分别计时。点原动作即有局部响应；等待留在原点；取消或继续编辑立即接管；失败只显对应小状态；实际完成后撤掉临时状态，不抢焦点、不重新欢迎。减少动态保静态图形与同一动作。键盘可达的恢复、关闭和原始焦点恢复由真实组件实现。

图只允许干净文学空房作为输入；用户故障截图已亲看用于定位，不作生图输入。图中正文均布局例子，不作用户原文或运行截图。生成后由主代理亲看，再交Spatial落真实QuietNotice。PNG不进入runtime当大背景或整页贴图，静态稿不能代签交互。

## 亲看后的取舍

v1 未确认发送处仍有飞机形发送按钮，可能诱发重发，且生成了额外侧栏、工具与欢迎副文案，故不作最终稿、不作生图输入。v2 重新仅以两张干净空房生成，已撤未确认状态中的发送箭头，保两拍同一草稿。主图的微提示和纸角恢复关系成立。

v2 内失败处的金色开环是静态缺口图形，不能循环转圈冒充等候；仅真实连接等候可以轻动，减少动态时不转。普通欢迎输入的发送入口被生成器省掉，不采纳此省略，保运行现有发送能力。图稿不授权改输入几何、替换原PDF文字、添加按钮、隐藏失败或把所有错误都塞进同一composer。各owner依真实起点绑定原动作、保原稿与焦点后实操。
