# 同一个房间里的十位伙伴

本轮按用户2026-10-23原话生产，基线 `ddc5403`。此处记录设计与原始生成来源；图片存在、设计者看过、主代理亲审、程序采用、运行操作是五件不同的事。

## 已有图的取舍

设计者已逐张打开当前151个A/B/C PNG：133个沿新catalog的canonical路径，18个早期同字节图先沿同步前原路径打开；另外看过早期2号图的历史文件，但该图不作新输入。SVG/ICO品牌按其原用途保留，不把品牌数算人物场景。当前8张自然母图与N001均只代表原类别，不能替代新的侧坐、抱膝或望窗。

早期晨光/雨夜最值得继承的是木座、书杯、毛毯、窗光与注视同属一个空间。PDF/数学标杆让原文和推导成为主体；笔记标杆证明专注时允许完全没有大角色。相同长文不能通过换杯/换书或缩小整幅房间来假装新空间姿态。

## 空间标准的定版边界

画布为1536×1024，人物/空景/alpha/接触影/遮挡均使用完整同尺寸画布，禁止裁bbox后猜位置。只变外层Stage坐标变换，不分别拉伸背景和人物。

镜头为平视偏坐姿高度、温和透视；窗四边完整连成同一对象。右侧窗榻与书桌/椅是两个真实锚点，前面留完整地面与可理解通道。左后小桌、书架、少量植物和窗影提供生活层次；正文安全区约束人物/前景植物及实时文字对比，不能机械扩成左65%永久空墙。前景不能靠白渐变掩盖空间错误。

主代理已逐张亲看v1/v2/v3/v4，正式选择`room-apricot-candidate-v4.png`用于人物母图原型（[亲审记录](room-selection.json)）；完整窗框、左后完整小桌/轻书架/画、大窗视野、右桌椅/窗榻和地面同时成立。v1/v2/v3不作为覆盖计数或运行注册。晨雾蓝、暮色紫、夜雨v2三张空房也仅获完整照明母图输入批准，见[主题亲审](theme-plate-primary-reviews.json)，不代表角色已覆盖主题。

祥子暖杏8类完整母图已由主代理横向亲看：`reading`第一版因身体关系近似chat被退回，新的真正侧靠/斜向双腿v2另审通过。批准范围见[母图亲审](primary-prototype-reviews.json)。用户要求的单角色跨8类母姿态已形成，其他九位暖杏母图可以按同一空间顺序扩展；人物层/匹配空景/实际Stage的准入和运行证据继续各自核验。不能把母图扩展许可写成320格、图层或产品运行已经通过。

## 生成与分离

每种主要姿态从不含人物的合格空房建立，以文字描述角色身份、青春神态、衣服、骨架与家具支承。错误母图不能作为身份或光影参考。先单角色跨8类；主代理亲看完整画面、脸、手、髋—膝—踝—鞋与支承，合格后再扩其他人物与完整主题。后续完整主题还可使用主代理已经批准的正确完整母图，重新生成全环境照明并锁定原姿态与家具；这不是独立贴人物或纯滤镜。每次如实保存实际输入与SHA。祥子现有24张非暖杏母图实际均只输入对应空主题plate，这段历史不改写成母图改光。

同景分离只提取已经合格的母图，不修骨架。真正RGBA人物填`figure`；仅有alpha轮廓或白/黑RGB工件填`mask`，由原母图RGB合成。完整发尾、发饰、衣摆、持物与双鞋四周留空气；浅/深两底审毛边、彩边、地板残块、半透明衣物和鞋底。接触影明确included/separate/none，避免重复CSS阴影。

主代理收到用户2026-10-23明确答复“允许精确原景分层（推荐）”，限定允许Python确定性蒙版校准、原RGB提取、背景噪声清除与配准；不能重画人体、脸或姿态。`extract-scene-layers.py`是可独立用Python/Pillow/NumPy执行的资产生产工具，不是测试runner。它保留整张mother的RGB字节，仅将经人工检查的soft alpha用于可见性；显式参数记录输入SHA、alpha来源/门槛、局部保留/排除区域、identity transform、输出hash。全透明人物提取曾发生放大/移位，失败工件不入运行；黑白同位mask只能作为luminance输入，不能将其全255 alpha误当人物轮廓。

<=8去浅噪、>=250落实白、其余保软边是当前候选参数，不是所有资产必须相同的验收规则。不全局侵蚀或硬阈值割断细发，不把最大连通体当所有持物的总闸。桌椅若在母图中发生合理动作变化，matching背景必须从该母图取得；可以保留母图原RGB外围，只在人工核过的人物清除区采用同母图生成空景并小幅配准。地板脱鞋、桌上卡/纸等环境物件不随人拖走，手中真正握持的书/笔才归人物层。

## 交给运行层的唯一校准

同目录每张资产一个`<stem>.scene.json`，`schemaVersion:1`。字段对齐现有`companion-scenes.tsx`：`id, character, activity, light, palette, width, height, mother, background, figure|mask, shadow?, foreground?, seat, ground, bodyBounds, safeTextBoundary, support, contactShadow, contourComplete, hitPolygon, travel, slope, perspective, review`。

图片字段直接为basename，禁止目录穿越与stem猜测；全部文件同目录。所有坐标归一化0..1，仅width/height为真实像素。每张独立校准，不复用默认坐面或热区。手落桌面时限制合法行程，不能拖离桌边；跨家具只通过对应完整姿态与锚点转换。

`review.approvedByPrimary`只由主代理亲看后写true。设计者不得代签。来源manifest仅映射scene路径、Prompt、输入/输出hash与五阶段证据，不再复制第二套运行校准。缺图保持缺图，不以别角色、别活动、别主题回退计覆盖。

完整360个预期key的当前目录是[matrix-coverage.json](matrix-coverage.json)，由原`build-matrix-catalog.py`沿本目录及[10月24日来源](../../2026-10-24-matrix)中的实际source/Prompt/PNG字节生产，原320格来源和审签继续保留。新来源可明确给出`character/activity/palette`或`key=角色/活动/主题`；`sceneCategory:S9_RESUME`只映射明确的恢复活动，不从文件名推断身份。支持同目录路径与仓库相对路径，源文件可为`.json`或`.source`；聚合路径清单和只有作者自评的记录不能替代精确Prompt与输出来源。

每格分别列生成母图、主代理图与Prompt审阅、图层准入/scene校准/代码使用位，以及真实运行证据；未出图、退稿待替换、未亲审或未运行都保留pending。[本轮主代理逐图记录](../../2026-10-24-matrix/primary-direct-review.json)只有`kind:mother`、`decision:accepted-mother-only`且文件SHA与当前字节一致的条目才补充母图批准，背景和界面关系不计母图。新记录保留旧母图审签的`priorReview`，不会抹去旧Prompt审签；`source`文字中的`primary-approved`等不签发任何批准。

Prompt审阅单列，只有主代理原审签条目明确`promptReviewed:true`才准入；可用`promptSha256`固定亲读版本，母图批准不会自动补签Prompt。父输入同时保留生成记录SHA与当前文件实际SHA，不凭路径存在证明字节相同。目录作者不签审，也不从fallback、source作者自评或scene存在推定运行成功。运行通过仍只沿原`primary-runtime-reviews.json`的精确母图、图层bundle、Stage实现与实机证据，不接受本轮母图/设计关系记录中的运行推断。

主代理可以明确委托录入其已发生的逐图审阅；此时数据作者只按精确版本、SHA与实际Prompt映射代录，不扩大到相邻文件或别的版本。历史作者标记`rejected/returned/not_eligible/needs-redraw`、嵌套`review.designerStatus`及显式`replacedBy`均排除当前覆盖。候选先取已审版，再按声明版号/生成记录时间/文件名稳定选择，不按本机文件mtime决定当前版本。声明的Prompt SHA若与当前实际文本不符，保留异常与pending，不能把改后的文本悄悄当作当次调用。

图层准入同时核对当前`companion-scenes.tsx`注册合同、主题light及声明PNG的完整同画布字节。每格`layers.scene.bundleSha256`固定实际消费的scene校准内容与采用PNG SHA：去除整个review与production来源指针，JSON空白/排版不影响；使用figure时不把未采用mask纳入可见指纹，非separate影也不纳入。真实图层、坐面、支承行程或实际遮挡改变会得到新指纹。

`.scene.review`只管图层准入，运行审阅唯一归`primary-runtime-reviews.json`。主代理独立记录`key, motherSha256, bundleSha256, runtimeAccepted:true, evidence`后，目录才列该格运行通过；缺少真实证据、bundle变化或准入撤回均保持pending，并保留旧记录的引用。不能把scene里的第二个runtime布尔当成另一份验收，也不能因签字时间进入hash而制造循环。

正常资产制备入口（项目根运行；Pillow/NumPy已在本机可用）：

```sh
python 前端视觉创新设计/来源记录/assets-design-generated/2026-10-23-companion-matrix/extract-scene-layers.py <本格参数JSON>
python 前端视觉创新设计/来源记录/assets-design-generated/2026-10-23-companion-matrix/build-matrix-catalog.py
```

图层处理保存完整同画布RGB哈希、alpha变更范围、处理脚本SHA与依赖版本。`localColorMatteRefinement`仅为显式局部不确定带的候选alpha方法（需已安装OpenCV，固定随机种子）；祥子study实看发现其削细铅笔/发丝，未采用该分支为最终层。不能因算法或hash漂亮而接受坏边缘。接触影仅在逐格原坐标掌/坐面/鞋底薄ROI求解正常RGBA残差，禁止整图差分、multiply或带木地板纹理的贴片；原位和有限行程端点仍须亲看，动态归位另在真实Stage操作。

确有同母技术matte一处错误时，可用`matteRegionOverrides`按输入SHA与同画布原坐标取另一轮同母技术matte的正确区域；接缝必须落在真实连续衣物/人体内部，不能把不同轮廓在细发中硬切。暮色chat尝试过的宽天空色键、局部硬边和GrabCut候选因削高光/断发而退回，不能作为合格方法算覆盖。新增`contactShadowEdgePixels`可把接触残差进一步限在真实figure边缘几像素内，仍须逐图看端点，不能取代薄ROI的人工选择。
