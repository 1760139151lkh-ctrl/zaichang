## 亲看成立的关系

完整房间仍可感知：左侧木桌、椅子、书架、植物与陶瓷灯之间有空隙，纸面仅局部承载文字；窗景和右侧人物共同保留近机位的亲密尺度。祥子的脸、刘海、拿书双手、坐姿和完整头鞋没有看到明显变形。此处是视觉观察，不是逐像素相同证明；未来实现仍引用精选原母，不用这张带 UI 的提案替换原图。

顶部只有小品牌、聊天/今天/留下和一个头像。消息上下错位表达说话者，不加姓名/时间/状态小字；主输入只保留附件和发送。样例句子可辨，图中没有场景导演、天气看板、教程、营销标题、轨迹或额外快捷卡片。

## 需要落实的减法

生成图里的消息文字约 28–30 px，头像约 56 px，输入条约 800 px 宽，纸面也偏实。它们可用于判断关系，不应原样成为组件标尺。下一步采用时：

- 在 1536 px 参考宽度下，聊天正文先以 20 px、约 1.65 行高观察；品牌约 23 px，导航约 16 px，头像 36–40 px。正文使用项目现有可读字体栈，文学感主要交给房间和段落节奏，不要求整套 UI 换成大号书法/宋体。
- 以左侧约 64 px 为输入锚点，输入宽约 600–660 px、高约 64–72 px，底部约 72 px；与人物及鞋部保留明显间隔。消息各自按实际文本收宽，用户消息向阅读列右侧对齐，助手向左。不要另造一个包含整片左房间的白色父壳。
- 消息圆角先在 16–18 px 观察，可去掉图中的气泡尖角；输入圆角约 24–28 px。减少像贴纸的边缘装饰，继续靠错位和留白识别说话者。
- 上方木桌、灯和窗景继续露出。较长聊天应在同一左侧阅读列内滚动或展开，不把新消息摊过角色、书与鞋。长答案、窄屏、缩放和键盘焦点均须由后续实际实现验证，本单页图不证明这些状态。

以上是实现起点，不是以数值代替光学检查或已批准的几何。既有输入焦点、草稿和滚动位置应保留，不因布局切换重建另一个输入。

## 表面与 token 起点

以下为建议值，没有写入源码，也不是从生成 PNG 精确取色：

| 职责 | 日间起点 | 使用关系 |
|---|---|---|
| 消息纸面 | `rgba(255,249,239,.84)` | 仅局部文字承载面；背景层可配约 14 px 克制模糊，文字本身保持不透明 |
| 输入纸面 | `rgba(255,249,239,.92)` | 比消息稍扎实，让落笔位置稳定，不再套外框 |
| 主文字 | `#392E24` | 暖深墨色，保持中文可读 |
| 次文字 | `#796B5D` | 仅占位等次要内容；不借降低整个容器 opacity 压低文字 |
| 轻边缘 | `rgba(104,80,56,.16)` | 有需要才保留一层边缘，不叠内外多圈 |
| 发送强调 | `#927254` / `#FFF8ED` | 小面积暖木色与浅色箭头，不做全页金色装饰 |

顶部在原图木色区域使用克制的暖浅色文字，选中靠字重与短下划线；不做高白横条。是否需要局部轻底需在实际字体、尺寸与批准环境图上观察，不以一组透明度保证所有背景可读。

夜间沿同一空间和职责降低亮度，可接现有暖暗基调 `#2D2824` / `#352F29`、主文字 `#F0E7DB`；不是将日间白纸浮在黑窗前。本轮没有生成或查看夜间 UI，不能记为夜间通过。

## 既有功能的去处

只读核对了 `Navigation.tsx`、`App.tsx` 与 `ComposerActions.tsx`：

- 三导航继续沿原聊天、安排、记事/资料入口。头像仍是原陪伴/偏好菜单；历史、新对话、地图等沿既有 handler 在按需菜单可达，不因默认减按钮丢失能力。
- 输入沿原 textarea、草稿、附件与提交逻辑。图中 `接着说…` 是现有占位；样例对话为构图虚构内容，不取自私人聊天，也不是实际模型回复。
- 本图是非 busy 的聊天状态。停止回复/发送补充继续由原真实 busy 与草稿状态决定，不能把这一张图的默认两按钮当作删掉原控制权的依据。
- 没有新增天气选择、场景切换或其他业务功能。此稿只供 root 判断整体构图和阅读层级，尚未实现任何交互。
