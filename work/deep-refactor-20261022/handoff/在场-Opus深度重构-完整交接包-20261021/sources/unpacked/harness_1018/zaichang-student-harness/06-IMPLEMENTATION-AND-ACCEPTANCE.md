# Codex 实施顺序与验收

本文件规定完成什么、接在哪里、怎样证明。它不是本轮应用已测试通过的报告。请以执行时 checkout 的实际代码、AGENTS.md 和环境为准；本包审阅基线为 `ba73b049089af718d337076364c6db0f98776d4f`。

## 1. 工作原则与阶段边界

先做能串起真实体验的纵向功能，再把共用机制整理出来。保持真实 Hermes 引擎、现有地图、日历、版本化记忆与执行回执；不为文档中的每个逻辑名建立独立服务。没有数据源时用明确合成夹具验证机制，同时交付真实可用的本地输入路径。

本轮核心实施范围为 T0–T7。T8 是后续移动/外部连接生产里程碑，当前应完成端口约束和一份可复核的可行性结果，不虚构所有插件接通。若运行环境缺 API、Windows、Android 或注册资格，继续完成不依赖它们的改造与验证，并将该特定验收标为 blocked；不能把整个核心任务停在计划。

实施者在已有授权范围内完成可逆本地改动与测试；对外发布、真实发信、付费、写学校系统或部署私人数据须有对应授权。本轮设计包本身不携带任何个人账号、模型密钥或外发许可。

## 2. 工作单

### T0｜建立准确基线，修复已定位的断点

**入口**：`runtime/turn-controls.ts`、`policy.ts`、`harness.ts`、`coordinator.ts`、`storage/domains.ts`、`model-selection.ts`、`shared/model-contract.json`、项目文档。

**实施**：记录实际 commit、未提交改动和锁定 Hermes；不覆盖用户改动。对照 [02](02-REPOSITORY-AUDIT.md) 重查变化。修复词面云端限制误判，明确发送前本地传输控制与禁止网页搜索的区别；不增加生活场景关键词门控。将 domain changes 的全部 upsert/tombstone 纳入可续读事件出口。复现并修正 `reviewOpportunities` 与恢复路径对已选 model transport 的可用性判断不一致；用统一就绪判定保留生产/测试标识。修正文档中 DeepSeek contract 与实际常量的漂移。

**验收**：真禁止上云在零外发下生效；谈论云技术正常处理；禁止搜索仍可用已授权模型和给定材料。一次十条变更含取消，第九/十条和 tombstone 均在消费账本中出现，重试不重建同一事件。没有 DeepSeek key 但合法测试 transport 就绪时可执行背景测试，不冒称生产可用。

**避免**：删除所有控制、盲目升级 Hermes、把 dormant `routeSpeechActs` 再当生产 bug，或用三个新正则只修已知三句话。

### T1｜接通版本化情境和最小记事本

**入口**：`storage/repository.ts`、`storage/domains.ts`、`memory/*`、`materials/service.ts`、`runtime/context.ts`、现有 IPC/工具与 LifePanels。

**实施**：复用现有事务与表，增加必要的来源事件/连续消费水位、业务语义指纹、依赖版本和未知覆盖。让当前原话、已确认目标、具体课程/日程、地点/天气质量与最新纠正可形成有界情境。笔记支持保存、读取、检索、编辑、版本冲突与撤销；原文是用户可见持久对象。

**验收**：重启后笔记原文及编辑版本还在；“记下这个想法”不自动排时段；日程未知与确实空闲不同。长段末尾的条件可回查，当前纠正先于旧摘要影响答复。乱序和重复来源事件不倒退当前状态。

**迁移**：给旧对象补默认元数据时明确 unknown/legacy，不伪造来源时间或旧授权。使用合成旧库 fixture 测迁移与回滚；保留原始资料，避免全表再提取覆盖手改内容。

### T2｜让广义托付产生新的主动机会

**入口**：`runtime/attention.ts`、`coordinator.ts`、`runtime/work.ts`、`actions/reminders.ts` 与 main 调度入口。

**实施**：增加/扩展广义托付、范围内派生关注、来源变化依赖、陌生事件的有预算语义发现、窗口唤醒、停止条件和机会依赖。沿现有 prepare/wait/ask/notify/none 及材料要求实现；将未来相对查询绑定正确 occurrence 或运行时窗口。

**验收**：说一次“这周留意考试和出行”，之后调课触发有效准备，用户没有说地图技能也能获得路线；未关联新来源可被发现；相同数据仅刷新时间不反复提示；用户撤回目标，之后重启/重试不复活；来源未变但预约窗口开放会复核。静默不丢失明确的定时提醒。

**持久与成本**：待处理事件有 cursor/ack 和失败原因，近截止机会先处理，低优先来源不饿死。没有新事实/节点时不空烧主模型。明确用户提醒继续走原调度边界，不被机会队列预算吞掉。

### T3｜把日程、路线和可行规划串成真实动作

**入口**：`actions/local-calendar.ts`、`availability.ts`、`calendar.ts`、`runtime/spatial.ts`、`capabilities/spatial.ts`、`mapService.ts`、`mapLocation.ts`、`capabilities/builtin.ts`。

**实施**：扩展目标/方案与原日历对象的关系，区别固定承诺和可调整块；模型提出少量选项、已有区间计算验证；地点/资源/精力自述作为条件。天气请求参数化并报告覆盖；路线材料使用现有地图稳定 ID、起点质量、版本和估计范围。已接受安排受影响时先修订同一对象的方案；当前指令或既有授权覆盖自动调整才提交，否则保留 proposed diff 待用户选择，已授权则不重复询问。

**验收**：朋友约饭、课程换楼和天气更新的连续场景能走完；方案点击接受后真的写日历，重新查询一致；移动后无重复事件或旧提醒；有其他可用运动窗口时不说“今天必须跑”；定位过期可换手动起点，不能编造手机位置；公共地图 review 不含个人叠加。

**体验**：路线上屏后用户能实际看/操作；后台准备不抢镜头。保持当前灰金与共享地图风格，避免另建一排“天气/健康/画像/工具状态”仪表卡。技术覆盖信息只在影响用户选择时出现。

### T4｜人格可编辑，记忆自动适应可纠正

**入口**：`shared/interaction.ts`、`store.ts`、`SettingsPanel.tsx`、`harness.ts` 系统上下文构建、记忆更新/遗忘链。

**实施**：按 [05](05-MEMORY-CONTEXT-PERSONA.md) 增加版本化角色核心、用户设定与自动归纳的分离、当轮覆盖、三个可修改预设、同场景预览、保存/撤销。旧 guidance 原文留在私有 legacy，五轴与确定纯角色内容无损迁移；纯角色注入不依赖个性记忆开关，混合私人内容仍遵守原用途。更正/忘记按对象范围传播到相关派生状态。

**验收**：同一任务、授权、主动设置下仅切换表达风格时，事实和业务效果一致、口吻可辨，不要求工具轨迹逐项相同；主动偏好改变可有合理行为差异；关闭相关记忆仍保留用户选定角色；混合 guidance 的合成私密 canary 不进入纯角色预览/导出/受限上下文；“今天别开玩笑”只覆盖合适范围；自动提取不能改角色名字或授权；用户删除推断后压缩、缓存、子代理结果不恢复它，保留聊天要求仍被尊重；示例文件中的虚构人不进入本人画像。

### T5｜上下文、缓存和子代理接在实际协议上

**入口**：`runtime/context.ts`、`provider.ts`、`luna-provider.ts`、`runtime/model-usage.ts`、`runtime/hermes.ts`、`sidecar.py`、`runtime/cooperation.ts` 等现有父子工作结构。

**实施**：稳定人格/工具版本前缀，实时情境按需追加；工具缓存键包含地点、时间、用途、来源/权限版本与覆盖；共享读取有独立等待者取消。复用真实 delegate，对独立复杂任务接合适工具范围、输入版本、共享预算、取消和父代理消费；普通单步不强行委派。

**验收**：同一合法读取可合并，不同地点/时段不串用；一个取消不误伤另一个等待者；晚到结果不改已取消计划；父代理确实读取子代理结果并解释冲突；压缩后原目标和关键条件仍能展开；provider usage 若无 cache 字段记 unavailable，不编出命中率。

**兼容**：Hermes 锁定接口为准。宿主已关闭原生 memory/background review，不能额外开启产生第二份用户事实；私有 hook 改动用现有真实引擎测试验证。生产模型 ID/thinking/工具续接/usage 与测试代用路线分别记录。

### T6｜投递、恢复、撤销与多入口一致性

**入口**：`actions/reminders.ts`、`actions/runtime.ts`、`runtime/attention.ts`、`runtime/release-*`、`main.ts` 和存储层。

**实施**：统一机会修订的呈现记录，选择前台/应用内/OS 渠道；保留不同回执等级。持久 job/lease/fencing/幂等与外部 unknown 后回查复用现有状态，准备/发布/执行前做当前版本检查。当前桌面进程退出限制准确呈现。

**验收**：聊天已展示的同一机会不再无故 OS 重推；新的实质变化可以更新；重启不重复已知成功动作；提交超时不盲重试；取消或撤权之后无新受限调用和旧材料发布；unknown/delivered/seen 不互相冒称。合成双设备测试能验证 owner/fence，但不得因此称手机已上线。

### T7｜真实纵向联调、体验修整与交付

**实施**：按下节验证，修正最早真实断点。让笔记、人格、地图、接受计划、等待和取消走实际渲染及操作；不止改后端类型。更新导航与当前状态文档，说明用户能做什么、仍依赖哪些来源。每个步骤输出实际变更、测试证据和剩余问题。

**完成定义**：T0–T6 的必要行为均有结果证据，至少一条现有能力支持的连续学生生活闭环用真实主模型完成。外部未接工具有真实可用的降级路径和明确 blocked 范围；不能以 mock success 填补实际动作。UI 操作已查看真实渲染，无明显遮挡、死入口或状态误报。

### T8｜后续手机与外部生产连接里程碑

不要把所有校园/邮箱/健康插件接齐作为核心完成前提。后续依次验证：动态课程来源的具体 occurrence/例外覆盖；Android 位置/通知/后台恢复与持续 Hermes 宿主；官方 ChatGPT 登录 provider；健康、邮件/钉钉与外部写动作。每项必须有来源配置、授权、真实读取/写入、失效和撤销测试。

现在为手机路线做有边界的可行性验证或阻塞报告：代码耦合清单、必要端口、Android 系统约束、目标运行拓扑、关闭电脑后任务由谁执行。若有 Android 环境，跑最小通知/位置/进程终止恢复；没有则给可复用命令/步骤与未验证项。不能把设计图或桌面 fake GPS 记为手机测试通过。实际远程部署另需在可审阅方案基础上落实授权。[04 §8；07 R19/R20]

## 3. 验收层次：不要把文件数量当能力

| 层次 | 证明的内容 | 不能证明的内容 |
|---|---|---|
| 静态审查/类型与构建 | 调用路径、接口、可编译、依赖状态 | 主模型理解对、真实用户相处舒服 |
| 确定性状态和故障测试 | 版本、幂等、时间算术、恢复、取消、隐私边界 | 开放语义是否正确、外部服务实时覆盖 |
| 真实 Hermes + 合成 provider | 真实引擎与宿主工具回写、委派、取消/压缩链 | 生产模型质量或真实服务执行成功 |
| 实际模型 + 合成生活事实 | 语义理解、工具选择、主动判断和未见变体 | 手机/学校/邮件已经接通 |
| 实际来源与可见操作 | 指定接入范围的真实结果与用户路径 | 所有校园、所有设备、长期可靠性 |
| 经用户同意的小范围真实使用 | 是否有帮助、是否舒服、错失和打扰体验 | 未观察人群的普适效果 |

`128` 表示设计覆盖，不是 128 项已通过测试。每条场景中的参考台词不可当字符串 oracle；验收看原始输入、选择、来源、状态变化和后续修订。不可把场景目录或期望答案放入生产系统提示或关键词分支。

### 3.1 运行现有必要门槛

执行前读实际 `package.json`、AGENTS.md 与 lock，使用要求的 Node/npm/Python。当前脚本名为：

```bash
npm run check
npm test
npm run test:hermes
npm run build
```

这些命令应按依赖和具体改动顺序运行，不无谓重复整套。新 checkout 需要依赖/运行时准备时按仓库现有 setup 文档执行，不能由本包保证网络或平台条件已具备。记录实际 exit code、环境、提交、测试路径；失败或缺条件明确记录，不用“应该通过”替代输出。

### 3.2 最小有意义的回归集合

所有新的确定性机制必须有对应的风险测试：批量十条及 tombstone、乱序/重复、时间窗跨日与时区、固定提醒/候选区别、版本冲突、unknown 后回查、撤权/取消在途结果、跨渠道去重、缓存范围与人格迁移。测试规模由这些真实风险决定，不为每个 getter 写镜像测试。

12 条连续轨迹见 [timelines.json](scenarios/timelines.json)。逐步提供截至该时刻的 `available_input`；未来步骤和 `evaluator_only` 只给评测器。一次决策必须在提供下一个事件之前留存结果，避免借未来信息得到漂亮答案。范围包含本地核心和明确标注的未来 adapter fixture；后者通过不能升级为真实接入完成。

128 场景全部做需求覆盖与能力归类；真实模型评测先覆盖所有 16 领域中与现有能力有关的代表案例、用户指定的考试/运动/约饭/人格/地图/记忆用例及必要反例。新增或失败机制扩测未见的语义改写与改变一个关键事实的配对样本。未接来源采用标注 fixture 验证推理，实际接入留待对应里程碑；不为凑数花费大量相同调用。

### 3.3 比较是否真的改善

同一批截至当前的事实、同一 provider/model/thinking、相同工具能力与预算下，比较：现版 Harness、修改版、尽可能薄的 Hermes 参考路径。薄参考路径可用于发现包装损失，不要求绕过产品必需权限或将私人资料暴露给更宽工具。无法保持条件一致就明确混杂因素，不报精确提升百分比。

固定可重复输入后保留未见变体。模型输出存在波动时，对有争议的关键样本做少量重复以辨别偶然；无需给每条场景盲跑多轮。每次修复指向最早分歧：原话丢失、工具不可见、数据没回、协议续接错、判断不当、材料没保存还是投递误报。修机制后再跑相邻反例，不向系统提示追加一条专用台词。

### 3.4 记录什么

每条有：case/版本、能力和资料覆盖、模型/传输/thinking、当前输入与实际工具调用、关键依据版本、主/子代理物理调用数、耗时和 usage、选择的参与方式、工具回执、持久结果、取消/失效传播、用户侧呈现。日志使用合成或获准脱敏资料，不能进入公共地图包或提交私人会话。

衡量机会发现、误打扰、错失/过晚、正确静默、可行计划、真实完成、更正恢复、表达合适程度和成本。时间以实际可行动窗口评估；分母区分“资料齐全且具备能力的机会”和“由于来源/设备缺失无法完成”。不开空白的“成功率 100%”表，也不用通知多、点击多替代用户受益。

## 4. 实施完成后的交付格式

提供简明变更说明、实际改动文件、迁移/回滚方式、已跑验证及结果、当前可用的学生闭环、仍 blocked 的真实接入。截图只用于说明已实际渲染的界面，不能替代操作验证。把最终工作落在当前项目中，不另交一份巨大的未来计划就结束。

允许 Codex 根据新代码与测试发现改进本方案，但需解释哪条证据使设计改变，保留用户意图、单主循环、工具可发现性、真实回执和可纠错性。未知问题不以更多字段、更多代理或更多确认弹窗自动解决。
