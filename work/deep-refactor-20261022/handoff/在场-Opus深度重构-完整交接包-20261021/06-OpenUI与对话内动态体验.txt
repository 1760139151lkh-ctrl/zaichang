06 · OpenUI、对话内动态内容、地图与界面连续性

请完整回读《在场-对话内地图与动态界面-Codex完整提示词-20261018.txt》《地图动效.txt》、仓库图片来源对话、图像与页面对应，以及当前 CONVERSATION_SCENES。早期源码缺口有些已经修好，体验意图继续有效；以当前代码重新核对。

一、目标是主助手自然选择怎样表达
用户说自己的问题，助手选择文字、表格、图表、地图、时间带、可操作的小实验或其他适合的形式。需要时直接在这段话附近展开，用户可以指着它继续说。它从同一个理解与执行循环里长出来。

请保留短答案的自由；一句就能说清，不需要每次都画一张卡。复杂问题值得丰富呈现，也不要因“简洁”只能输出文字。OpenUI 的价值在于能表达、能交互、能继续，不在于组件数量。

二、先核实当前实现，避免两个极端
现有项目使用 @openuidev/react-lang 的 defineComponent、createLibrary、Renderer，已经有 MapScene、WeatherScene、CampusScene、PlanningScene、EnvironmentScene、DiscussionScene、StudyScene、CuriosityScene、RehearsalScene、NoteScene 和 SceneStack 等注册。
已有 present_view、Scene 来源和稳定引用，有真实数据与展示路径，不是从零接库。
另一方面，当前工具及组件集合表达有限；已注册不等于主模型可以生成任意新学习工具，也不等于正常自然对话已经稳定触发全部场景。

请读实际安装版本及必要上游源码，再决定是否升级。官方新文档提供基于组件 schema 和说明的生成方式，可保留现有聊天和后端；这不要求更换 Hermes、采用另一家模型网关或重建整个输入区。上游示例与仓库 1.0.1 的 API 差别请实测。

三、让模型真正走通这条链
能力可发现
→ 主模型从当前问题决定需要哪种表达
→ 取得足够、合法、当前的事实或建立清楚的计算假设
→ 生成/选择可验证的呈现结构
→ 宿主绑定来源、稳定对象与版本
→ 渲染可信的第一帧
→ 用户直接操作
→ 有语义的选择回到同一交流
→ 下一轮读取和改变同一对象
→ 历史、取消和重开仍能解释。

请逐段观察输入和输出。手动给模型塞进标准答案、直接调用渲染组件、fixture 预置场景，能验证组件，不能证明 Agent 自主产生它。模型的 tools response 里真的拿到 SceneRef，也还要看后续有没有采用。

四、从固定教学样例走向可扩展内容
当前 quadratic 声明能准确重算值、曲线和切线，这部分精确性值得保留。用户补充的波形图需要不同的表达：公式、变量、时间、相位、波形相加、滑条与动态图相互一致。现有限定不能直接承担这类内容。

请用陌生问题比较几条候选路线：
A. 扩展有类型的表达式、绘图、参数和时间模型，适合精确数学/科学与受控交互。
B. 用 OpenUI 组件语法组合图、公式、表、输入、时间控件与说明，业务组件继续引用真实 owner。
C. 对确实无法声明的创作型交互，研究隔离的可执行产物及窄桥接，和主应用、真实数据、凭据与行动分开。
D. 保留领域专用组件处理成熟业务，但不把每个新例子都写成专名分支。

具体选哪种或怎样组合，由你依据真实需求、维护成本、可验证性、模型生成可靠性和性能决定。可受控不等于只允许一个固定函数；表达自由也不等于让任意生成脚本获得 Electron 或系统权限。

请让数学和物理语义独立核算：公式、单位、坐标、参数含义、定义域、动画时间、初始值与图像一致。图片上的标签也可能需要纠正，不能因为是用户参考图就把视觉当计算 oracle。
例如改变相位时，公式和曲线一起变；暂停时间后还能拖动参数；询问“为什么这里抵消了”能引用当前参数和所选位置，而不是重新生成一张与当前图无关的图。
测试扩展能力时换一种函数、换一个变量关系或新的数据图，而不是只验证原波形图已被硬编码。

五、共同状态简洁，但身份清楚
领域数据由原服务负责；当前讨论对象与方案由已有 Work/frame 等负责；呈现有自己的稳定 view/scene 身份；镜头、折叠、试看的日期或参数归观看/交互状态。
这些责任不需要各造一套数据库，但请不要用一大段 DSL 文本同时充当事实库、用户意图和行动批准。

用户拖动、缩放、排序、播放和暂停可以本地立即响应，不每帧调用模型。
点选地点、课程、时间段、公式位置、原文片段或一版方案，形成精确的当前引用；输入附近轻轻显示、允许取消，保住已写草稿。
需要新资料、新判断或实际动作时，再回宿主。
试算和试看不变成已接受计划；点击看一门课不变成长期兴趣；动画播放不变成现实经历。

六、地图是一段共同看懂空间的交流
请复用现有共享地图 surface、MapService、路网和 CameraOwnership，保住 MapLibre 与平面兼容路径，避免对话、独立地图和未来其他界面各养一份数据。

第一帧就回答眼前问题。问来不来得及时，起点、终点、道路和时间关系先清楚；不每次从城市上空飞入校园。只有课表时，说明按上一节课教室出发，别把它当新鲜 GPS。
路线沿真实几何，镜头可以领先、侧移或保留地标，二者分开。只有岔路、桥头、入口等确实有解释价值的位置才靠近。金色引导当前重点，周边不过度抢眼。
熟路、重复查看和赶时间时更直接；自由探索可以舒缓。动画时长由信息和手感决定，不把固定秒数当验收真理。

“先回 A 拿电脑，再去 B，然后回 A”：
地点 A 保持同一身份，停靠实例不同，有向路段不同。
真实回程重新按约束生成，不假定去程倒放总成立。
重合路线保留方向和当前段的重点，不两条线同时闪烁。
“镜头回 A 看看”只改观看；“先回 A 再出发”可能改行程。由完整原话与当前引用理解。

用户拖动、滚轮、触摸或说“等等先看这里”，旧相机和自动强调立即交出控制，晚回调不能抢回去。新观看请求可以从眼前状态自然接上，无需先完成旧动画。
使用现有权属/版本机制串起开始、阶段完成、取消、替换和销毁，不另写一份独立相机控制器；按引擎真实结束信号推进，不靠数个 setTimeout 猜完成。

用户点建筑再说“这里”，绑定稳定地点与当时选择；到达信号用真实观察或用户自述，不把路线游标到终点当人已经到。
入口、估计接入、条件通路、未知室内细节按真实来源保留。再漂亮的镜头也不证明门真的开着。

七、内嵌、聚焦和返回像同一张地图
日常在相关文字附近展开；地图够大，能读道路和端点。复杂比较时可以放大聚焦，保留选中对象、镜头意图、交流前情和合适输入入口。
收起回到原对话位置，重新展开继续看，历史回看不重播开场。
尺寸变化可以重新拟合，不机械追求同一 zoom 数值；关键是用户仍认得刚才看的东西。
桌面滚动不要轻易误缩放内嵌地图；触摸和双指、键盘、减少动态效果都要保留可用路径。

模型流式增加文字或局部 patch，不频繁重建 WebGL、重置相机、丢选中或顶走聊天滚动。OpenUI 的 statement 名字与 React 实例身份并不天然等同，请按当前源码验证。
历史地图采用合理快照和恢复策略，别让几十个离屏实例同时渲染、轮询定位。平面回退用同一事实与选择，准确表达其视角限制。

八、这些生活场景请各自认真接完整
日程与时间：显示课前课后、路程、准备、收尾、休息和真正可用的片段。移动候选地点或试排时段，空间和时间结果一起更新；“空着就好”有自然位置。
天气与空气：按问题选择日/小时范围，当前来源能支持到哪就到哪；选中“那天下午”可接后续商量。装饰光线不冒充现场观测，缺测不用晴天图标补全。
成绩与学分：单门直接答，整学期有表，趋势再用图；保留课程/学期/来源/GPA口径、单位、分母和缺失。点课后计算影响时读同一课程，缺分不按零补。
图书馆：比较真实可用时长与路程，预约读取不冒充新建预约；有可靠座位几何才画精确座位图。已有预约直接接路线、签到和原材料。
运动：学校认定次数、本人记录、手机测量分别对待；当前规则和截止有来源，休息是合理选择；地图动画不证明活动或学校打卡。
笔记：保留自由写作与完整原页；建筑、课程、书名和预约可以被引用；“下次到附近”成为有范围的机会，暂停和已看过能接着处理。
整个下午：同一旅程的地图与时间带互相引用；调整一站时只改变受影响部分，给真正不同的从容/多去一处等选择。
无任务探索：认识校园、慢慢看看、在附近坐一会儿，可以有空间叙事与人物陪伴，不虚构安静、空位、营业或现场天气。
讨论与共做：把具体原话、可比较选项和下一小步放到自然纸页，用户可直接接话，不强迫选择按钮或登记任务。
陪学：保留原题、本人尝试、已给提示和停点；用户可指一行继续讲，提示与完整答案遵从这次意愿；演示参数不写成本人事实。
共同创作：回到原作品章节和版本，人物第一人称不串进本人记忆；原取景地图的冻结入口是否恢复由真实价值和能力决定。
来信与好奇：内容具体可读，来源能回看，可以收好、放下、换一个或自由回复；读过不自动建立订阅和长期偏好。
关系排练：保住本人想表达的意思，模拟的回应不当作现实对方态度；整理成草稿不等于发出。
手机和平板：同一事项与选择能接续是远景；单手、键盘、方向和边走边看要按平台设计。先保留数据与事件接口，真实同步和后台分别实现。

这个清单让共同基础有广度，不要求把所有服务伪装为本轮已上线。旧包 128 场景与 12 条时间线仍是补充阅读，不由此缩成一组固定页面。

九、历史、局部更新与实际动作
昨天的天气和旧成绩快照保持当时意思，不静默换成今天；重新采用旧方案时核查当前依赖，在有意义的位置说明变化。
保存场景的版本、库版本和必要观看状态；恢复不等于刷新，刷新不等于改写历史。
按钮对应已有受控动作，重放、双击、旧 revision 和用户取消都进入原动作链。生成一个按钮不能凭空获得外发或预约权限。
更正、删源、换任务和关闭视图后，旧回调不继续执行或把新内容推回旧状态。
把公共呈现与私聊数据投影分开；实际来源、审批和回执仍归宿主。

十、把设计图用到真实产品中
仓库树中有 45 张前端视觉目录里的位图，其中包括 39 张页面/补充图和 6 张人物、窗景素材；assets/design 下另有 69 张位图，src/renderer/assets 下有 18 张位图。计数按固定树中的路径，不自动去重，也不把 SVG 算进这三个数。
同一树中全部图像后缀含 SVG 共 136 项。请看 evidence/repository-image-inventory.json，不只盯前二十张。

本轮已读图像来源与页面对应文本、查看了上传截图；当前 GitHub 文本接口没有成功返回这些大图的二进制，所以本包没有声称逐张看过它们。请在实际 clone 中逐图打开，对照当前渲染：设计意图、已采用部分、未做部分、做偏的部分以及仍有价值的动效。图片目录清单只能帮你找，不能替你观察。

请延续暖灰、米白、克制金色和窗边自然光的方向。原早期材料曾建议蓝靛等候选，不覆盖后来明确的窗边方向。人物可以可爱、有存在感，也请给正文和数据留位置。当前截图里的遮挡是具体待修问题。

新增完整页面按已有图像先行约定做设计；现有路径的清晰小修不强迫每次重画。请把图稿与实际效果放在同等内容、窗口和主题条件下比较，观察字体、留白、透明叠层、长文、数学、表格、窄窗、焦点和等待过程。

十一、验证最有辨别力的关系
选择能够检验当前改动的完整路径：
模型自主呈现，随后用户选中并续问；
地图运动中接管，再用原话改向；
往返新增停靠，内嵌放大返回；
同一场景流式局部增加内容，不丢焦点和草稿；
陌生的可交互数学关系，公式与图独立核算；
旧画面恢复、重新采用前刷新；
失败、取消、离屏、低性能/平面回退和减少动态。

截图证明构图，动画和接管需要时间过程。若本轮环境不允许某种真实交互观察，准确保留缺口；不以截图集、百分比打分或更多产物证明完成。具体验证方式遵循 08 的现有授权与 Computer Use 限制。
