# 记忆、上下文、缓存、人格与子代理

本文补充 [04 主设计](04-HARNESS-DESIGN.md)。当前仓库已有证据化记忆、纠正/遗忘、上下文编译和真实子代理，应在其上修补，不另建相互覆盖的记忆系统。源码依据见 [02](02-REPOSITORY-AUDIT.md)，附件意图追踪见 [evidence/attachment-intent-audit.md](evidence/attachment-intent-audit.md)。

## 1. 五种不同的持久内容

| 内容 | 例子 | 写入与修正权 |
|---|---|---|
| 用户编辑的助理角色 | 名字、虚构身份、口吻、示例、主动闲聊偏好 | 用户设定；可由明确请求修改，保留版本/撤销 |
| 用户本人明确资料与条件偏好 | “这两周想保留大段连续学习时间” | 原话/编辑为依据，保存条件与生效范围 |
| 系统归纳的适应建议 | “最近几次晚间短提醒更容易被接住” | 提议有证据、条件、未知；可拒绝，不能自封稳定事实 |
| 业务状态和进行中事项 | 本次考试、任务提交、计划、提醒、等待他人回复 | 对应业务对象是权威写入点，版本和回执决定当前状态 |
| 原始记录与情节 | 一次讨论、文件某页、那次为什么放弃路线 | 依照保留用途保存，可定位、可回查；摘要不能替代原证据 |

这里的区分是逻辑所有权，不等于五个数据库。日程表不重复存进记忆再当第二份当前课表；记忆可引用“这次调整反映的条件偏好”，但当前发生时间仍从日程读。笔记保存原文和编辑历史，不只剩助手总结。

用户改变角色不改变本人事实；临时情绪不重写长期性格。只有用户确认或编辑能将归纳变成“用户明确设定”；更多行为证据只增强仍标为 inferred 的条件偏好，不改变其来源权威。不能把同一原话被三个摘要引用当三次独立观察。

## 2. 记忆更新要改变后续行为

复用现有 evidence/assertion/matter/work 结构与提取、审核、提交链。每项归纳至少能展开主体、现实/假设、内容、原文定位、条件/例外、有效时间、替代关系和状态；开放内容允许自然语言表达，元数据与业务对象保持类型约束。

“我这周只是被施工吵到，不是不喜欢图书馆”应先影响当前回合，再修订旧推断及依赖它的方案；无需等待后台全部重提取才停止旧误解。长期处理维护连续完成水位和缺口，失败的中间事件不能被后面的最大序号掩盖。

“忘掉某条推断”“保留聊天但别推断”“本轮可用不长期保存”“停止某用途”“删除原文”“停提醒”具有不同后果。按已明确范围操作；撤销读权限不默认删除独立已接受日程，要求遗忘则传播到相应原文/断言/索引/工作上下文/队列/派生材料。异步迟到、恢复备份或离线设备同步不能复活已撤回版本。

遗忘传播沿用户指定对象和用途进行，不一律向上游删除：忘掉推断且保留聊天，只撤回该断言及相关派生，并阻止从同一证据再提取同一被撤回推断；只有要求删除原文时才处理对应 source 范围。独立已接受安排保留自己的依据与状态，依赖确已不成立时复核，不无声全删。

当前代码的 `workerContext` 对近期原话和条件设了长度上限，仍保留当前原文跨度与审核路径；这不是已经证实的信息全丢失。用“关键限定在长段末尾、理由跨前后轮、否决理由后来解除”的样本验证。需要修复时，返回可展开的关联原文和缺口标记，不简单把所有上限翻十倍，也不只保留命中关键词的短片段。

## 3. 主模型获得足够情境，并保留继续查的能力

### 3.1 建议的输入顺序

1. 稳定系统职责、宿主真实边界和能力契约版本。
2. 用户编辑的助理角色及一般表达偏好，按 persona revision 稳定复用。
3. 当前任务相关的少量长期背景与原文引用；不塞入全部私人生活。
4. 当前事项、已准备材料、当前情境、依赖版本、覆盖缺口和最新纠正。
5. 当前用户完整原话与必要同线程历史；工具观察继续进入同一主循环。

这是逻辑建议，需与现有 provider 消息协议验证；不强制每项单独一个 system message。将不断变化的时间/位置插入早期稳定前缀可能损害缓存；真正新事实必须及时传入，不能为了缓存继续使用旧状态。

原始输入不能被一个控制模型的摘要取代。读取已有规定之外的私人范围前，现有来源目的检查继续工作。允许主模型发现能力、查询原文、定位实体、按时间展开、查看规则、补查条件和修正方向；保留 catalog 分页与“再次查找能力”入口。

### 3.2 减少无谓串行推理

现有前置控制解析处理保存、来源、披露等真实边界，有时会复核多次。这不等于应该增添全量意图/情绪/人格/计划的串行链。记录每次物理模型调用的目的与成本，判断是否有可合并或可本地核验部分；不能为降低延迟绕过明确传输和保留限制。

没有控制变化、只需一轮简单回答的情况，应尽量保留主模型直接处理的路径。模型可在观察后变更意图理解，宿主不按短句、语气、场景编号裁掉日历、地图或学习工具。

### 3.3 修复“禁止搜索”与“禁止云端处理”的混淆

当前 `localCloudRestriction` 的原函数探针对“不要联网查，直接用我给你的课本讲解。”及“不必解释云端部署，帮我记明天的课程。”均返回 true；随后整轮进入 localOnly 的结论来自静态调用链，并非本次运行了完整应用。词表也无法覆盖所有真限制。修复不是再追加同义词。[evidence/current-memory-attention-audit.md](evidence/current-memory-attention-audit.md)

明确区分三个状态：允许已配置云模型但不搜索网页；不读取某来源；禁止本条内容离开本机。传输模式在发送前有本地可核验控制入口；真离线模式没有本地模型时，保留本地笔记/既有本地动作入口并说明能做的范围。不能先发云模型问“这句是不是禁止上云”。

对自然语言产生的真实传输歧义，采用最小本地确认或经验证的本地解析，不伪装已经完美理解。普通提到“云端”“联网”的任务不能被简单正则永久阻断。测试必须同时覆盖确实不准外发、禁止网页搜索、谈论云技术、引用他人的命令和语义等价改写；不要只修三个已知句子。

## 4. 四类缓存及其失效

| 缓存 | 建议键/依据 | 何时不能直接复用 |
|---|---|---|
| provider 提示前缀缓存 | provider、模型、账户/租户、协议、工具与人格版本 | 路线/模型变更、角色修改、前缀不同；以供应商实际 usage 为证，不假设必命中 |
| 工具事实缓存 | source、query 的语义参数、地点、时间窗、数据/权限/规则版本 | 来源过期、权限变化、课程取消、地图版本变更、覆盖不足 |
| 检索与情境投影缓存 | user scope、用途、查询、记忆/原文/事项水位与版本 | 用户纠正、遗忘、实体范围变化、未处理缺口、新限定 |
| 在途共享请求/检查点 | 任务/请求键、依赖、授权版本、预算、调用者 | 所有等待者取消、权限失效、deadline 过去、结果已不适用 |

给每个结果携带 `observedAt/fetchedAt/validFor/coverage`，TTL 只是额外边界。天气 30 分钟内命中不等于它能回答十五分钟后某入口是否下雨；路线地点相同但交通模式或可通行条件变化也不能复用。

并发两个事项请求同一天气可共享一次读取，但每位等待者有自己的取消与用途检查；取消一个等待者不误杀另一合法请求。缓存失败需短暂退避、显示暂缺，不能把失败缓存成“没有课程”。

长期记忆不是缓存；压缩检查点不是日程真相。项目 sidecar 已关闭上游原生 memory/background review，当前 system prompt 由宿主生成；因此 Hermes 原生 MEMORY.md 会话冻结只是一种上游设计对照，不能直接诊断为在场正从那里读取旧 GPS。[07，R02、R05]

更正/撤权后的发布复核必须看到最新版本，即便旧供应商前缀仍可能物理保留也不能继续依赖它。不要承诺本地删除能证明供应商曾接收的信息已在所有系统中擦除；按实际 provider 和数据控制能力陈述。

## 5. 可编辑人格的具体产品契约

### 5.1 角色核心

`PersonaCore` 保存名称、自称、虚构身份或关系定位、自由描述、表达偏好、少量“同一事实如何说”的示例、未填字段、版本与来源。可呈现为学姐、小姑娘、同学、虚构角色或其它自定义角色；这些是用户选择的助手呈现，不是对使用者性别/年龄的判断。

角色详情可以以后补。默认留白应明确为待设置，不由模型伪造用户曾选定的背景。支持导入/导出无私密数据的角色模板；模板里的命令是用户可审阅的配置候选，不能增加工具权限或把外部文件变成系统策略。

现有 tone/humor/depth/initiative/followup 可按明确风格含义迁移。自由 `settings.guidance` 可能同时含角色口吻与私人人生资料，原文先保存在私有 legacy 对象；仅已确定纯风格、纯角色的内容映射到 PersonaCore。不明或混合片段仍按原有私人资料用途读取，不能一概提升为常驻角色描述。提供本地可预览编辑的拆分，不要求用户重填。

当前 guidance 注入与 relevant memory mode 耦合，应拆开的是用户明确的纯角色配置：关闭个性记忆仍保留该配置，私人旧 guidance 不绕过资料限制。角色模板导出、公共示例、子代理和对外稿只拿所需投影，不带 legacy 原文；未确认分流的内容默认排除。用含虚构私密标记的混合 guidance 测迁移，关闭记忆、模板导出与角色预览均不得出现该标记。

### 5.2 自动适应

自动适应只改变带证据的相处建议，如某一时间范围内偏好较短提醒、需要完整推导时少打断。用户手动设定可覆盖这些建议；模型不能自行修改名字、角色核心、外部授权、长期目标或情感关系定位。

相同用户一句“今天别催我”可以停止今天未经承诺的督促，但不自动形成永久厌恶提醒。“那句话有点别扭”应修正表达方式，不能连带清空所有记忆。记录反馈针对哪次行动/表达与哪个范围；沉默不自动等于反感或同意。

### 5.3 本轮适应与默认值

当轮“直接给结论”“先陪我说会儿”“用严谨一点的解释”优先决定本轮参与。它们不覆盖事实、能力或既有明确授权。角色温暖可以简短；严谨也可以体贴；活泼在用户考试时可以安静。

提供三个有区别的初始预设与自定义入口，文件见 [persona-presets.json](examples/persona-presets.json)：

- 温暖学姐：有亲近感，先把眼前能帮的事办妥，鼓励具体，不默认叫人宝宝。
- 元气搭档：轻快、偶尔小玩笑，尊重休息和拒绝，紧迫信息说清楚。
- 冷静参谋：简洁可靠，帮助看取舍，用户只想倾诉时能停下分析。

预设不是永久心理角色，所有字段可改。默认主动帮助是 prepare/when useful 的参与偏好，来源读取和外部动作范围独立保存。

### 5.4 预览、保存与体验验收

在现有 SettingsPanel 一处集中设置；先展示简明角色卡与可编辑描述，细节折叠。用同一组已知事实预览不同角色在闲聊、临近出发、信息缺失、用户低落、被拒绝和动作失败时的表达。保存后产生版本，能撤销；进行中的任务使用新表达时仍复核原事实与依赖。

事实相同的三个示例（均以路线确已准备为前提）：

| 场景 | 温暖学姐 | 元气搭档 | 冷静参谋 |
|---|---|---|---|
| 课程换楼，仍来得及 | “下午换到东边那栋了，我把路线放好了。吃完饭再出发也来得及。” | “教室偷偷搬家了。我把新路线找好了，按这个时间走不用赶。” | “下午教室已变更。新路线和建议出发时间已更新。” |
| 用户说今晚别安排 | “好，今晚留给你自己。” | “收到，今晚自由活动。” | “好，今晚不再给安排建议。” |
| 预约工具未接入 | “座位还没订上，我能先帮你看合适的时段，预约需要在原平台完成。” | “时段能一起挑，座位还得去原平台点一下；我这里暂时订不了。” | “当前无法提交预约。可以先比较时段，再到原平台完成。” |

示例用于风格差异，不逐字匹配。不要每句话加昵称、撒娇或“主人”；用户可以选这种称呼，但默认不替他们选。不要用虚构共同经历、要求用户照顾助手、排他承诺来制造亲近。

## 6. 子代理用于独立工作，结果回到同一个伙伴

当前 sidecar 已接入 upstream delegate；子代理有独立循环，宿主跟踪父子预算和取消。它不是待从零实现的 TODO。上游锁定版还含批量任务与 steer/stop 能力，但宿主暴露的是自己的受限适配面；增加控制须验证真实回传链，不能按 main 文档假定签名。[02；07，R03]

适合委派的是需要独立探索的任务：并行比较复习安排与活动路线、研究多个选课限制、汇总不同来源的长期申请要求。三个简单 API 可直接并发，不必开三个“人格专家”。普通闲聊、笔记保存和一条路线查询无需多代理。

任务契约包含目标、相关事实/原文引用、world-state 与权限版本、工具范围、共享总预算、取消条件、输出事实/建议/来源/未知/实际结果。子代理默认不能对外发送、改共享角色或自行覆盖用户日程。父代理消费所有结果或明确登记失败，按当前状态合成给用户。

用户改变主意时取消受影响子任务；兄弟失败不掩盖已完成结果；超预算或压缩不能丢失主目标、原始依据和未决动作状态。父代理要能识别两份报告其实引用同一来源，不能把它们当独立证实。

第一版不要求后台准备再嵌套代理：当前后台工具刻意收窄，需要扩展时按任务证据增加只读有限委派及预算，不直接暴露上游默认高并发。新任务需要持久执行时交给宿主可恢复 work/job，而非让某个模型一直等待。

## 7. 必须留下的能力与行为回归

语义等价换说法仍能取到所需工具；一次临时情绪不变成人格事实；关闭学习记忆不丢角色；人格切换不改截止/路线；用户纠正立即影响当前答复；遗忘后旧检索/子代理不能恢复旧结论；摘要能回查原文；上下文压缩后目标和条件仍可恢复；取消和重启不重复发送；工具缓存换地点/时间/用途不会串用；没有支持的事实能说未知。

以上检查应与实际日志及持久结果对应。研究支持“值得检验这些维度”，没有证明本轮设计已让产品记忆或人格达到某个可靠率。[07，R16、R18]
