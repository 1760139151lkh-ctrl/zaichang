05 · 主动陪伴、持续工作与真实行动

一、用户这次说的“主动”
不等新消息，也能按约定观察、思考、准备、行动和回来告诉你。
事情上，有你不用反复提醒的可靠；相处上，有她愿意主动靠近你的自然。
请同时做这两件事。一次回答末尾追加建议、启动时弹固定问候、做一个无后台执行的提醒开关，都不足以承载这个期待。

本轮核对了 Grok Bot 与 Muse 官方介绍。它们公开描述持续工作、接入应用、事件/时间触发和在长对话里接续任务的方向；这是产品方说明，未由本轮实际试用验证。请借鉴完整生命周期和可感知结果，不照搬营销承诺，也不把云端常驻能力误认为桌面程序天然拥有。

二、先追通现有链，不另起一个主动系统
当前已存在 Work 托付、业务 journal、cursor/ack、Attention、OpportunityScheduler、同一 Harness 后台调查、Cooperation 准备、Reminder 投递。请逐段回答：
谁生成真实变化？学校资料刷新和本机编辑都进得来吗？
这次读取覆盖到哪里，游标前移有没有漏事件？
哪个有效托付或相处约定允许关注这件事？
什么时间或事件唤醒，失败后何时重试，应用重开怎样接续？
后台主模型能看见什么方法、工具和必要前情？
结果保存在哪里，何时直接进入聊天，何时放在适当入口，何时发系统通知？
用户看过、回过、拒绝过或停掉以后，什么会改变？
取消、改口、删除来源和前台插话如何传播到这条链？

请把缺口落实到代码和场景，不仅把文档里的“主动”改成“非常主动”。

三、让无消息触发成为可证实的能力
用确定的时钟或受控来源变化，模拟或实际产生一次触发。整个流程请没有新的用户对话消息，然后观察：
来源被实际读取或变化已由可信事件送达；
系统正确识别与当前托付的关系；
必要调查在真实运行链中继续；
有可用结果或合理等待；
结果到达用户选择的渠道；
点击后带着原任务、对象、来源和未决问题继续。

机制测试能证明触发、队列、幂等和路由；模型有没有做出有分寸的判断，还需要真实模型样本。两层分别报告。请不要由脚本直接创建最终“助手回复”后宣称 Agent 自主完成。

四、不同的主动行为，各有自然入口
明确的持续托付，例如“这周替我留意考试安排，有变动告诉我”。保留期限、来源、允许行为、渠道和停止条件；一次具体托付可以同时覆盖必要的准备步骤。
一次性承诺，例如“明早八点提醒我带资料”。它是一份需要履约的责任，不应被可选消息的冷却预算挤掉。
条件机会，例如课换了楼、原路不再通、成绩更新、已有预约临近、计划依赖的材料到了。先判断变化是否真的影响此人此事。
自发发现，例如与你正在聊的兴趣有关的一篇好内容、一个可以马上一起做的小实验。根据用户选择的相处方式，在允许范围内主动寻找，不必先逼用户创建“兴趣目标”。
关系性接话，例如接上昨天没讲完的故事、记得用户说过想让你偶尔先开口。可以有当下的人格表达和关心，别强迫每一句都绑定截止时间或效率证据。
持续研究或代办，例如查清规则、比较方案、等外部结果再继续。需要真实持久任务，不用一个永不结束的模型进程假装后台。

这些是体验来源，不是要求建立六个互斥分类器。主助手可以结合当前情况选择；宿主负责可执行边界和可靠调度。

五、把准备带回同一段关系
“准备好了”请有实际内容：查清的一条变化、可读的一页材料、已核实的路线、可以继续的草稿，或者一件已完成的行动。一个 help 对象或 artifact 标记本身不代表帮助发生。

结果可以在合适的当前对话中自然出现，也可以到下次回来时顺着话题提起。重要但允许中断的变化可以通知；用户正在另一段深谈时，可以先放好。请让选择基于当前关系、托付、时效和打扰偏好，不只比较数值阈值。

用户收到的内容请保留人物表达。例如“我刚替你看了一眼，成绩更新了”只有在确实查过且发现变化后才说；角色也可以把一件轻松发现带来，不必先介绍机会判断流程。通知预览可以克制，打开后看见同一个人的完整话和实际结果。

当前准备架、对话消息和通知分属不同路径。请追 stable work / message / artifact / notification 的关系，既能避免同一结果重复轰炸，也能在用户真正回来时找得到。渲染、阅读、接受和完成分别记录必要证据。

六、主动程度的默认体验
请检查第一次使用：用户是否知道可以让她偶尔先开口、替自己关注哪些来源，能不能用一句话完成托付？默认 prepare、提醒关闭和未连接状态是否在界面里被清楚解释？选择元气或亲近角色以后，是不是仍被无幽默和纯准备默认值压住？

可以给用户轻松的起点，不必让他理解后台参数。来源权限、相处频度、重要提醒和锁屏预览分别表达；“更主动”不是授权发送所有邮件或购买东西。

已存在的明确授权请沿用；已经连接的数据，不反复要求用户重新登录或重填配置。确实缺连接时，先做准备、给清楚入口，不扫描其他项目找密钥，不假装已经读到邮箱。

七、生活兴味本身值得主动
请回读原材料里的散步、图书馆小书单、校园探索、体育与休息、一起做的小事、共同创作、来信和好奇邀请。让它们拥有能自然发生的真实入口。

如果用户说“最近想偶尔收到一点有趣的”，可以在其允许范围内找到具体的新内容；如果他们正在共写故事，可以在恰当时机带来一个可继续的灵感。若只是希望被问候，也可按约定轻轻开口。内容有创作性质就按创作呈现，不伪造你们曾经共同经历过的现实。

别把学习或成绩作为每件事的默认目的；“今天就坐一会儿”“这里空着”“先不想做什么”都值得被尊重。助手也能陪着一个没有产出的下午。请让轻松相处自然成立，而不是每次都转成目标、待办、打卡和回顾评分。

八、调度与运行主体请说到做到
请区分：应用前台、窗口失焦、最小化/托盘、进程退出、设备睡眠、关机、断网、系统重启、未来手机或云端。
当前项目退出会停止机会轮询，无法凭一句 system prompt 在关闭后继续运行。

可以研究桌面常驻/托盘、系统任务、受控后台服务、远端执行主体等候选。选择哪种，说明实际平台能力、数据落点、资源成本、用户设置、取消入口和恢复方式。需要新增云端部署或费用时，先完成可审阅设计和本地实现再按授权办理；不自行上传私人数据来验证。

调度请保留租约、任务版本、单一责任者、退避、公平性和断点。多个窗口或未来多设备同时在线时，谁负责本次提醒、如何去重、怎样接回结果，都要有真实处理。过期提醒不在重开后堆积补发；恢复时先判断现在还有没有价值。

发送到操作系统、平台确认送达和用户已读是不同回执。不能因为 submit 返回就说对方已经看见。

九、沉默、暂停和重新靠近
用户说“今天别催”“这件事只说一次”“这周先别提成绩”“晚一点再跟我说”，请保留作用范围和有效期。不要因此停止独立的已约定提醒，也不要用新标题绕过同一件事的暂停。

同一理由换文案仍然可能是重复。新的实质条件、时间窗口或用户重新主动提起，可以让系统重新判断，而不是永久拉黑一个领域。拒绝要能被听见，改变心意也要被听见。

相处上的主动不是追踪在线时长，不制造“你为什么不理我”的负担。用户可以不回复、离开、暂停、换角色，回来仍能自然接上。亲近不需要靠惩罚沉默维持。

十、能行动，就完整办好
请继续分清连接权限、本轮限制、具体委托和这次动作批准。明确、低影响、可恢复的本地任务，在已有授权内直接完成，不反复问同一句确认。外发、费用、影响他人和不可逆结果，按具体后果确认必要范围。

行动前核对实际对象、日期/时区、参数和版本；用户说“那就第二个”时用真实选择绑定，不拿新排序替代旧对象。
行动中保存稳定身份和必要派发意图；失败、部分成功、结果未知分别处理。
行动后以实际回执和必要回读确认；不能靠模型说“完成”点亮绿色。
超时先查同一行动是否成功，再决定重试；用户自己已完成的事情对齐状态，不重复登记。
取消旧任务不自动撤回已经发送的内容；请解释真实后果，并采取可用补救。
更新一项安排时保留同一对象和未受影响部分；部分采用后只处理剩余工作。

日程里的事件、待办、截止、提醒、时间块、课程和签到各有意义。未知结束时间不偷偷填一小时；课间空白先考虑转场、准备和休息；重复事件的单次改动和系列改动区分。

十一、邮件、成绩和其他外部连接怎么推进
成绩：沿真实学校资源查版本、分页、统计范围和变化；“这次没有更新”要有当前读取覆盖。不能由总 GPA 缓存推每门课的新结果。
邮件：先核当前项目有没有可用 adapter；没有就研究接入与最小读范围、变化游标、邮件线程、草稿、发送和回执。工具 schema 与界面可以先实现可测试的合同，但测试替身不冒充真实邮箱连接。
学校写操作：预约、选退课、付款与只读查询分别接入，不能由已登录推任意写权限。
天气：日级、小时级、分钟级和路线局地覆盖分别核实，避开看似精准的推断。
手机：位置、健康、跨设备状态和后台通知按实际原生生命周期研究，不把 430 像素窄窗当手机上线。
公共研究：工具能自己搜索并读关键原文，外部材料可以启发，不发号施令。

请先完成已有能力内真正有价值的端到端链，再向外扩展；同时保留明确的远景入口。不要让唯一一条提醒 demo 成为本轮全部主动能力的完成声明。
