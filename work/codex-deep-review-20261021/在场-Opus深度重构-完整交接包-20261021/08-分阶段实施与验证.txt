08 · 分阶段实施、验证与持续修复

这是一条可调整的路线。请按真实依赖重排，不把阶段编号变成新的硬框架；一个阶段解决了什么，以产品行为和证据说话，不以报告篇数判断。

一、接手与保护
确认实际仓库、分支、工作树差异、未跟踪文件、当前运行构建和现有用户数据。保留 Gemini 或其他会话留下的有效修改，记录如何恢复。
分支/tag 只能保护已提交状态，未提交与私密资料另按现有流程保护。可回滚迁移保住原始记录、真实动作和删除屏障，回滚不把后来发生的用户事实抹掉。
请用当前 AGENTS 和 package.json 找命令，不猜某个脚本一定存在。原包内研究脚本先读用途，不因为随附件附带就执行。

研究基线 package.json 的有效入口包括：
npm run check
npm test
npm run test:hermes
npm run build
npm run dev
npm run start
这些是定位入口，不是本包已经运行的结果，也不是要求每次改一句文字全量重跑。某些脚本可能需要平台、依赖或数据，执行前读清实际作用。
dev:luna:test / start:luna:test 是历史显式模型代测入口；本轮不要求运行。deepseek:check / dev:deepseek 涉及已配置服务，不因它们存在就发起测试或消耗。

二、阶段 A：把产品全貌与真实断点放在一起
先读理念和本轮原话，再沿文件与调用链认识现状。对每项用户关心的体验，区分已有、接线未消费、只在设计稿、历史观察、当前验证和外部未连接。
选择能定位共同原因的连续经历：默认人物开始聊天；一句查询带工具；读一页笔记并继续讨论；无消息后的后台变化；一次自主动态呈现。
请取得模型实际输入构成、工具是否可见、结果是否回传、正文何时发布和状态怎样落地的必要证据。不要为此建立另一个无约束调试 IPC 或导出私有推理。

本阶段的出口，是足够支持下一步判断的事实与可回滚工作点，不需要把全仓每行都列成表。源码关键责任请真正读懂，全文原材料请通过本包章节与原文索引持续回读。

三、阶段 B：人格与交流的共同路径
先让选择的角色实际进入主调用，处理默认空核心、形象与人格采用、交互设置覆盖、保存与恢复。
整理提示组成和当前冲突，保持 Gemini 的好风格。
修正文/工具事件的发布链和稳定消息段，使用户可以被及时接住、看见有用发现、补一句和停止。
失败文字、系统状态、收尾重复和通知话术随同一条链修，不另设默认温柔改写系统。

本阶段请观察：一个角色从闲聊到查资料再到失败恢复是否保持一致；多个阶段的回复是否接续；用户的补充是否真正改变后续。工程验证能先完成传输与事件责任，模型体验证据不足单独保留。

四、阶段 C：理解与记忆真正被使用
围绕原文、条件、当前事项和共同经历补接缝：有材料却只看摘要、当前纠正没进入下一次请求、旧理由反复支配、返回后丢停点、生成被当已读。
比较少量锚点、直接查询、语义候选与有界调查，不默认全部常开。保证主助手可以继续搜索和回原文，工具目录也可继续发现。
修局部更正/遗忘、长文尾部、跨版本引用、迟到 worker 与分支恢复等会造成真实回归的关系。
保留不需要记忆的轻对话，不让每句输入先经过全量提取、总画像、规划和复核委员会。

五、阶段 D：主动服务有真实触发和交回结果
沿现有调度与托付接通一条没有新消息的完整任务，包含来源变化、模型判断、真实准备/行动、消息/通知与回到原事。
把生活兴味、关系性接话和当前创作工具的后台适用方式研究清楚，避免后台只会生产待办。
核对暂停、只一次、过期、拒绝、重开、取消和重复触发；明确约定提醒与可选消息分别管理。
评估退出后的执行主体。能在本次环境实现的完成；不能的给清楚平台依赖和下一步，别无声承诺全天常驻。

六、阶段 E：动态表达和跨功能关系
先把正常模型发现并使用 OpenUI 的路径打通，再扩展可组合动态表达。
地图、日历/时间、校园成绩/学分、天气、笔记和学习至少按实际缺口逐项核对；已有内容接好，不能仅用第一条纵切代替全范围。
围绕波形图和另一种陌生问题验证扩展路线，独立核算公式/数据，检查选择如何影响下一句话。
补齐视图身份、流式稳定、取消、历史快照、原生操作和恢复。真实生成的界面继续通过已有动作与资料桥，不扩大权限。

七、阶段 F：界面与图稿落地
后端单元有了可用合同，就按现有视觉资料修对应体验；不等整项宏大后端工程全部完成才让用户看到改善。
新增页面遵循已有 GPT Image 图像先行约定；保留暖灰金色与自然窗光，人物、纸面和数据各有位置。
逐项检查原截图问题，以及长文/公式/表格、窄窗、夜色、输入法、焦点、草稿、等待与中断。手机图稿是独立平台方向，不用窄窗截图替代移动实现。
本轮沿《产品深度重审与优化》的 Computer Use 限制，不使用该能力，也不换包装绕过它。优先使用被允许的实际渲染、已有可控脚本、CLI 与测试驱动；某项操作缺直接观察则保留证据缺口。

八、阶段 G：清理、迁移和文档归位
根据实际调用关系清理重复 owner、失效的分支、临时修补和互相打架的指令。大文件可以按职责拆，但拆文件不是目的。
先迁移真实消费关系，再删旧实现；兼容读取和恢复有清楚期限。不要删除暴露问题的测试换全绿，也别为了“整洁”擦掉历史材料、未提交稿或原始依据。
同步 README、AGENTS、导航、产品契约、架构、状态和接续。写清哪项在源码、哪项当前已经运行、哪项受外部资源限制。

九、验证分层，避免把替身当产品
L1  静态与构建：类型、schema、导入、锁定依赖、提示拼装、工具注册与前后端接口。证明代码关系可成立，不证明模型理解。
L2  机制与故障：时钟、队列、原文位置、版本、事件序列、取消、重试、未知结果、迁移与恢复。可以用隔离合成资料和可控传输，但准确标记。
L3  实际集成与呈现：从原入口进入当前构建，真实 renderer、IPC、数据库与共享地图，观察完整流程。不能只是直接调用底层组件。
L4  实际产品模型：自然选择能力、理解新说法、人格一致、动态 UI、自发判断和证据利用。只有真实配置和实际响应轨迹能支持。
L5  长期/平台：多天相处、资源增长、Windows/手机后台、真实外部服务和用户体验。当前环境测不到的明确留白。

本轮不要求 Luna，不等于 L4 已经得到证明，也不等于取消 L1–L3。请尽量把前面能完成的做到可审阅；没有获准模型通道时，交付 L4 的具体入口、数据前提和待判问题。不要选择另一付费服务绕过模型约定。

十、验证一个真实问题需要看哪条证据
输入：原话、来源限制、角色与当前对象到底是什么。
模型请求：合法工具与必要证据有没有实际进入，是否被压缩或裁剪。
工具执行：参数和来源正确，读取范围足够，返回状态诚实。
证据利用：后来回答或行动是否真的采用所得事实。
外部/业务状态：实际变更、幂等、回读和失败恢复。
显示：用户实际看到哪版文字和界面，能否继续指代。
后续：改口、重开、换话题与取消以后，旧东西会不会复活。

请优先找最早分歧。若工具结果根本没进下一轮，加角色台词不会修好；若来源正确而表达被收尾模板压平，就不必重建记忆库。

十一、少量但能分辨的对照
遇到具体失败时可比较：
相同合法资料下的轻量主循环与当前集成；
模型得到充分正确证据的诊断上限与正常自主取证；
有/无某种预填、摘要、子调查或语义候选；
保留 Gemini 角色、调整冲突指引之后的完整对话；
同一动态问题的固定组件与更通用声明。

这些不是强制全排列。必要边界不在真实资料上被移除来刷分。诊断上限不算正常产品能力；公开场景、同义改写和真正独立新故事也分开。

十二、每个失败这样继续
记录最小可复现经历与当前版本。
提出可反驳的原因，而不是“模型不够聪明”。
改共同机制，或删掉没有价值的增强。
走回原故事，看正常结果。
换表达、改变相关条件，再看邻近反例。
继续到下一轮、重开或后台返回，确认不是只修第一句话。
达到足够证据后收束，继续用户目标，不为测试而无限扩大工程。

错误评分器也值得检查：假的成功回执、目录当原文、工具路径当图像已读、同一行动重复、删源后晚写回、旧 Scene 被偷偷刷新，如果仍被判通过，先修判断依据。

十三、不把六个体验维度揉成一个总分
功能：事情是否真的办成。
语言与人格：这个人是否还能被认出，是否听懂。
视觉：内容、人物、层次与可读性是否协调。
操作：连续动作是否顺手，选择、返回、取消是否自然。
新手：不看架构文档能否开始、找到结果、理解当前状态。
长时间使用：草稿、历史、资源、队列、重启和恢复是否可靠。

这些维度可以共用同一段经历，但请分别观察。流畅不只帧率；温柔不只称呼；美观不只空白截图；可靠不只拒绝；完整不只文档目录。

十四、持续推进与结束条件
本次是一次完整的深度优化，不因第一轮报告、首条 demo 或一个模块修好就停止。按用户最新要求继续发现与修复已授权范围内的问题。
也请避免用无限研究、无限加功能或反复全量测试拖延交付。达到以下状态即可收束本次：
关键断点有一般机制修复；
本轮可实现的主要体验接入原入口；
已有有效能力与数据得到保护；
必要验证完成，证据缺口准确可复现；
原材料中的独立要求得到已落实、已保留、被新要求覆盖、需外部依赖、暂未完成或不适用的明确归属；
没有把未知包装成完成；
文档和下一步入口足够让人继续。

如果外部阻塞是剩下的唯一问题，请提交具体可运行成果和阻塞说明。不要把缺一个账号说成整个产品无法优化，也不要假装那条服务已经上线。
