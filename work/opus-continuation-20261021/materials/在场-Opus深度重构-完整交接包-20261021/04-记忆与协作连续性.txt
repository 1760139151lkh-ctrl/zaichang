04 · 记忆、理解、共同经历与渐进能力

这一卷串起六份历史 Harness / 生活融合文档、完整记忆讨论、协作记忆交接和 10/18 学生包。原文中更细的场景、反例、契约和历史批评仍请沿 sources 与章节目录逐项回读；下面是共同语义，不是要求照抄一组类名。

一、理解一个正在变化的人
在场可以记住用户，也可以理解过去为何这样选择；更重要的是，今天的原话能继续改变这个理解。用户可以矛盾，可以临时改变主意，可以只是抱怨，也可以一边难过一边明确托付一件事。

请保留开放的语义空间。模型直接看原话和相关前情，判断此刻需要倾听、解释、调查、一起比较或实际代办；这些帮助可以组合，不固定成几个互斥模式。程序负责清楚的身份、来源、参数、时间和后果，不靠 contains、regex 或一句分类标签替主模型决定整段交流。

日期解析、实体搜索、索引和业务校验仍有价值。请区分“帮助找到候选”和“不可逆地替用户定性”；也别把旧关键词表换成一张更大的 prompt 条件表。

二、同一个人的资料，有不同责任
请沿既有 owner 理清：
原始消息和材料：保留确实说过、读过的内容与版本。
条件化理解：对原文的解释，有主体、现实/假设、条件、例外和适用时间。
当前事项：正在一起处理什么、哪些是候选、哪些已拒绝、为何拒绝、还欠哪个明确结果。
业务事实：课程、成绩、安排、预约记录和动作回执，由原领域服务负责。
自由笔记：用户能直接写、改、找回的一页内容，不自动变成个人档案。
共同作品：虚构世界中的人物和经历，不并入用户真实生平。
角色设置：用户选择怎样相处，独立于模型猜测的人格。
索引与摘要：为了某个消费者快速找到资料的派生产物，不成为新的权威事实。

这些责任可以共用已有数据库和进程，不需要每一项另建服务。当前 code 中已经有的关系请优先复用。

三、原话完整，解释有依据
长输入的后半句、否定、量词、条件、未来生效日期、例外和理由，常常决定整件事。请追长消息、文件分页、模型上下文预算和压缩，别让“为了省 token”变成无声丢条件。

来源引用请明确不可变版本、解析/转换版本和位置类型。Unicode 码点、UTF-16、字节偏移不同；PDF 页、图像裁剪、表格单元格、音频时间也不同。选中文字在实际 RichText/公式 DOM 中无法精确映射时，请保留未知，不凭看起来一样的片段伪造定位。

“引文逐字相同”和“引文足以支持结论”分别核查。工具返回了可用句柄，模型可以引用；它不能凭空编一个来源编号。来源被删或撤权，旧引用保持不可访问，不跳到同名的新文件。用户点开时走原权限和版本链。

当前输入里的事实可以直接帮助这轮，不必先写成长期记忆才能使用。对于确有长期价值的理解，请继续采用候选、引用核验、语义核验、条件化变更和受控提交。请避免模型每轮重写整份 Profile。

四、让记忆自己找到入口
可比较的默认起点，是少量必要锚点加上随时可用的探索：
可信时钟与时区；
完整当前原话和明确控制；
当前引用的对象、版本与真正未决问题；
最新纠正和已接受的责任；
相关旧工作或材料的少量可回读入口；
当前合法能力的可发现入口。

这些锚点帮助开始，不替主模型预先写答案。预填线索无关时，主模型可以不用；不足时可以继续查。新话题不等于丢掉明确称呼设置，只用附件也不等于先偷读历史再假装没用。

找回路径请互补：全文与中文实体、时间/主体/事项导航、无关键词原文 browse、来源到已有工作关系、语义候选、必要的独立记忆调查。不同路径要能回到原文，不在摘要之间永远绕圈。

两种常见失败值得直接追：
“上次谈过”却搜不到：可能原文未索引、候选没进上下文、关键词太窄、权限范围不同、只搜断言没搜原话，也可能确实不存在。请区别这些原因。
“搜到了但没理解”：候选只剩结论，理由/例外在相邻原文；主模型没读到、工具结果被截断、子任务只给了泛泛摘要，都会造成错误使用。

负结果记录查询、范围、覆盖、来源与索引版本；新材料或纠正出现后重判。第一次空结果不宣告“你从没说过”。也不无限查找：预算不足时说明真正查过的范围，继续给能成立的部分。

现有 BGE 接线是候选能力，不是默认激活证据。请比较启用它、改进词法与导航、按需深读各自的价值。若向量增加污染或延迟，就调整或不用；不要为了“拥有长期记忆”先迁一套大图数据库。

五、让适用条件会进入，也会退出
请用完整后续验证“有点累，但这道证明请讲清楚”：
本轮按照用户想要的深度讲；
不把疲惫写成永久身份；
若确实保存临时解释，知道它服务哪件事、凭什么仍适用；
用户说恢复了，下一轮和相关后台候选立即重判；
旧条件不再成立，不等于确认了反面；
独立已授权的日程不被无关情绪变化误删。

同样处理“不是因为路远，是因为刚进入状态”“那是我朋友的情况”“我在写小说”“我只是比较，还没选”“从下个月开始”“考试周例外”。请让语义与真实主体、世界、时间一同保持，不给这几句建立专用分支。

拒绝理由可以随条件失效。以前不想某条路线，不等于永远禁止；原因改变后可以重新纳入比较，但不等于用户已经接受。高分、低分、少说话和沉默，都不足以自动推断人格或心理状态。

六、记得我们怎样一起做过
请把“共同经历”留在实际产物、事项与消息关系里：
原题或原材料是什么；
用户自己写过哪一步；
助手给过哪些提示、哪段解释；
哪版内容真正到达并可见；
用户明确说看过/理解/接受了什么；
现实结果有什么证据；
这次停点和回来起点在哪里。

生成、服务器发送、客户端收到、渲染、播放、阅读、理解、接受、完成，存在不同证据。没有回执就是未知；有渲染回执也不证明认知。请避免为了确认“真的读过”增加眼动式监测或每段问卷；使用最少的可观察事件和用户自然回应。

长内容部分显示、流式取消、折叠区、旧纸页、手机/电脑不同布局，都可能让“第二个”指向不同对象。请绑定当时真实视图的稳定对象和版本，保留当前选中/回复/片段引用；仅当确有歧义才问两个具体候选。

编辑或重新生成聊天可以产生新的叙述分支。实际已执行的动作有独立账本，不因改消息消失，也不跟着新分支重放。未采用建议不变成共识；晚到的标题、摘要和后台材料提交前检查当前版本。

这些信息也让成长更可靠：可以比较不同时期的本人尝试与得到过的帮助，但不从“听过一遍”推独立掌握，不从平台成绩评定全部能力。用户选择新的挑战时，旧标签不挡住。

七、摘要按用途存在，不反复总结整个人
导航标题帮助找；会话检查点帮助接；事项摘要保留决定和拒绝理由；主题线索帮助检索；本轮证据包服务当前判断；稳定偏好保留条件；助手帮助记录记得过去怎样提醒过。
可以共享实现，但请别用一段总摘要承担所有职责。

每个派生产物要知道消费者、来源版本、覆盖、更新时间、何时需要重建、何时可以退役。目录摘要不冒充原文。重建尽量回原源，避免“摘要的摘要的摘要”丢尽限定。

后台整理围绕实际需要：补索引、处理尚未归并的合法原文、刷新受影响的摘要、帮助某个持续任务。没有消费者的每日全库回顾，不因为叫“主动记忆”就保留。低频但关键的约束也不能只按点击热度遗忘。

临时会话、不保存、不使用某来源、只用附件、公开受众等控制，在相应读取、传输和持久化之前生效。可以保存独立明确委托的业务对象，不因此偷存整段私聊。旧材料的“全部先写入，以后再删”不能绕过这一点。

八、纠正、遗忘与恢复走完整链
更正事实、更正理由、停用一种理解、忘记一段原话、删除聊天和取消现实安排，是不同操作。请让用户用普通话完成，也能准确解释范围。

局部遗忘时，原文可归因片段、相关断言、摘要、索引、缓存、排队任务、已准备提醒和旧模型链的使用一起核对；同源独立无关片段不要一并毁掉。删除/权限 epoch 拦住旧任务晚写回，旧备份恢复也不绕回被忘记内容。

停止继续使用和清除备份、撤回已外发内容之间有实际差别。说明必要后果即可，不把每次纠正写成系统取证报告。请保留透明可恢复的本地迁移，不用新空库证明升级成功。

九、四种工作形式按需要选择
确定程序：时间运算、权限版本、聚合、索引、实际回执。
单次有界模型任务：中性标题、明确范围的转换或候选。
有界 Agent 调查：需要读工具反馈、换路、比较多源证据的工作。
持久任务：稍后继续观察或履约，由真实队列和调度器承载。

这是选择空间，不要求拆出四个新框架。工作者有实际消费者、目的、原话/来源范围、对象版本、预算、最晚有用时间和结束条件。返回证据与缺口，主助手能追问、回源或拒绝采用；工作者不直接改掉长期人格、不签新权限、不替用户接受方案。

总预算覆盖前台、子任务、后台、压缩、复核与重试。前台交谈可以先给真实帮助；后台索引或标题失败，不必阻塞独立回答。请保留足够收尾能力，也检查预算策略有没有早早移除关键工具造成“什么都做不了”。

十、能力、方法、证据和权限分别取得
能力概览说有什么、当前连没连；
完整合同说输入、输出、影响、错误和核查；
方法帮助模型怎样用；
证据来自实际读取；
权限来自用户与宿主有效范围。

第一次工具候选没有选中某能力，不应让它从本轮世界里永久消失。保留发现、分页、描述和重新查找。当前资料够用可直接答，复杂问题可继续扩展。

优先按运行时支持安装真实 schema；若需要 describe/call 网关，请限定已登记、描述过、版本匹配的能力，按真实 schema 校验。不要用任意自然语言或 shell 承担 do_everything。

可复用个人方法要保留来由、适用条件与反例，允许用户修改/停用；方法不是自动安装的高权限代码。现有 bundled 与个人方法最好在同一发现入口自然出现，不要求用户先学会管理 Skill。

受限大数据查询可以采用验证过的 AST；确有必要的计算才比较隔离执行。请控制网络、目录、凭据、运行资源与输出范围，返回输入版本、单位、分母、筛选和覆盖。一次程序跑完不证明口径正确。

十一、文件和多模态继续保持原件可回读
TXT/MD 的编码与源字节、PDF 文本/扫描/公式图像、表格公式/缓存/隐藏与筛选、图像实际像素、音频转写修订、ZIP 成员，按真实类型处理。尚未接入的 OCR、Office 或音频能力请按需求研究，不用扩展名冒充读完。

用户给一张图，产品要把正确图像送进实际支持该输入的模型或已授权感知路径，观察是否影响判断。路径存在、设置 seen=true、Codex 亲眼看过图，都不证明产品模型看过。

公开展示、通知、搜索标题、aria、悬停和导出也属于披露路径。请用适当投影承载必要内容；真实信息与权限责任保留在后端，界面不靠隐藏 DOM 假装从未暴露。

十二、用反事实理解收益
同一问题给充分合法证据时模型能答，产品却答不好，先找 Harness 的来源、选择和上下文问题。
改变真正相关条件，判断要有机会改变；加入无关历史，不该乱带方向。
用户纠正原因后结论仍可能一样，请看理由是否更新，不用表面改措辞评分。
少量锚点、全按需、全量预填、语义候选、独立调查和直接主模型读取，可按真实问题比较；有收益再留下。
不写临时情绪、不派子任务、不调用工具、不给提醒，也可能是恰当选择。明确可完成的委托真正办好，同样是必要的正向标准。
