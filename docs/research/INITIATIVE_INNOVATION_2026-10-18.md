# 主动性：准备、续接与生活中的好事

核对日期：2026-10-18。仓库研究起点为 `c7cff22884fe9a3050879067dd49012f685d8cfd`，本轮改动在此后叠加。本文只研究后端与相处机制，未读取前端参考图片。用户最新要求覆盖原有“必须先完成 Luna 验证才能做前端”的阶段门槛；机制检查、真实模型效果和界面体验仍分别说明。

## 1. 先看实际缺口

用户要的是助手自己理解情境、先把能做的事做好、回来时接得上。新增通知数量不能证明这个目标。`04-HARNESS-DESIGN.md`、`03-HUMAN-AND-WORLD-MODEL.md`、128 场景与 `harness讨论.md` 已经覆盖安静准备、等待、正向机会、留白和纠正。本轮不重写另一套生活分类器。

当前源码已经有有效托付、机会队列、持久唤醒、只读调查、真实材料准备、停止与失效、展示回执；`inspect_help` 也能跨对话发现材料。具体断点在 `runtime/context.ts` 的初始上下文：准备索引只读取当前 `sessionId`，`currentMatter` 也限于本对话。因此“已经做好、以后再给你”可能在换一个对话后失去自然入口。工具存在不等于主助手知道何时值得调用。

另一个容易忽略的细节是短标题也有来源。假设标题是“周三体测前的一段空档”，它已经携带日历信息；只因为没有附完整日历，不能把它记成纯 `work:self`。下一轮、输出留存和收窄权限都必须继续认识它的派生来源。

## 3. 九个可发展的点子

以下是本项目的综合设计，不是某个来源逐条提出的功能。“能沿现有工具表达”与“本轮新增并核验的后端机制”明确区分。

| 点子 | 用户能感受到什么 | 后端如何实现 | 本轮状态 |
| --- | --- | --- | --- |
| 回来就接得上 | 换了对话也知道故事写到哪、哪个比较还没决定，用户不必重讲 | 现有 `collaboration_frame` 的小型跨会话索引；完整内容用 `restore_collaboration`，不把历史下一步当新义务 | **新增机制与测试**：`continuity.ts` 的 `openThreads`，仅仍 active 且有 nextStep |
| 做好了，等你需要时拿出来 | 助手之前查好的路线、时间材料能在相关话题自然使用，不再从头查 | `preparedMaterials` 跨会话线索 → `inspect_help` → 当前版本读取 → `decide_help` 复用与呈现 | **新增机制与测试**：同一 WorkRecord，不复制正文；真实展示后抑制重复线索 |
| 出发前准备，回来后续接 | 去办事前准备材料，回来后接到原先在做的内容，不只是报出门时间 | 一个事项保留前置材料、真实占用、等待条件与返回断点；用现有日程、工作记录和准备材料 | 本轮补“准备与返回”技能；手机到达事件、自动物品感知尚未接入 |
| 给生活留一点空白 | 忙完以后允许散步、发呆、看一集动画；休息不会被下一批任务吞掉 | 规划器保留保护区间；主助手按本人当前意愿比较方案，固定提醒独立处理 | 现有规划保护留白能力，本轮方法与取舍说明加强；不把休息强制排满 |
| 记得你会高兴的事 | 喜欢的讲座开放、等待的公开作品更新时，先核实真正新增内容再顺势提起 | 由已有兴趣证据和有效托付发起有限公开查询；`newValue` 绑定新观察；可安静准备 | 沿现有机制与新方法可做；未新增全天候内容订阅服务或假造已订阅来源 |
| 想试试，不立一个新 flag | “有空想学一点钢琴”先留作轻盈愿望；出现合适时机才提出一次小尝试 | 笔记/探索事项与承诺分离；可为当前请求准备一个小起点，不自动创建日程和催办 | 本轮方法指导；不新增“愿望完成率”或压力看板 |
| 帮你把开始的门槛降下来 | 想写作业时，必要材料、地点与设备条件已经清楚，只留一个真实可开始的下一步 | 依现有 notes/materials/planning 查出缺口，保存准备产物；未知设备或开放时间保留条件 | 可使用既有能力；本轮未新增设备遥测或材料自动上传 |
| 学习断点也有记忆 | 知道上次卡在“复特征值重根取实虚部”的哪一步，尊重只要小提示的发现边界 | 原始证据记录尝试与已开放范围；事项 nextStep 提供入口，恢复后展开原文；看过/提示过/独立完成分别说 | `openThreads` 提供通用支撑；未声称自动评定用户掌握程度 |
| 只告诉你真正变了什么 | 一份安排有新变化时只解释影响与需要做的事，已完成部分保留 | 复用现有对象 ID、版本与回执；旧材料失效，新的有效材料才能成为新机会 | 现有 attention/planning 支撑；本轮加入对重复线索与来源继承的明确验证 |

本轮优先前两项，是因为它们直接补上“已经主动准备了，却不能自然回来”的真实调用链缺口；第三项以可发现的方法接入，能跨学习、出行、创作复用。它们不要求新账户，不依赖读取用户所有数据，也不增加新的后台发言者。

## 4. 本轮后端契约

`buildContinuityIndex` 使用现有数据库，没有新个人资料表。调用前仍须确认当前回合的读取用途；私有本人现实范围内，`relevant` 可以发现跨会话线索，`session_only` 仅本会话，其余 memory mode、第三人、虚构世界、群体受众、子代理或缺少工作资料权限时不读取。

准备索引必须连接真实 `AttentionService.expire()`，复用其课程、日历、笔记、来源与有效期失效逻辑；没有这个 hook 时不输出“当前可用”的准备材料。之后再检查当前许可、材料正文确实存在、时效、托付仍 active、来源绑定和权限。关联原文被删除或撤权后，现有 repository 过滤仍生效。只回传标题、ID、版本与时效，正文由 `inspect_help` 按需展开；Scene 不在这个索引里直接播放。

每类最多返回三项，读取有界分页并明确“还可能有更多”，不是全库清单。排序只参考当前会话与更新时间，不按“考试、跑步、约饭”关键词决定生活需要。主助手可以完全忽略与当前对话无关的候选；用户当前要求优先。

生成、OS 提交、渠道送达、真实展示、打开与已看不合并。只有同一材料 fingerprint 已有真实展示/打开/已看回执时，才不再把它主动放进索引；OS 提交仍标为未证实阅读。用户主动找回时原材料不被删除。标题与下一步的实际来源也进入 Context receipt，后续收窄来源不能通过旧助手消息绕回来。

## 5. 检查范围与剩余工作

新增 `tests/harness/continuity-index.test.ts`，七个机制与接线检查全部通过：实际本地日历读取后准备、跨会话发现、不输出准备正文、不新建日程或通知、仅本会话/禁用/限源、标题来源隔离、日历修订/停止/期限失效、展示与 OS 提交区分、重启持续、未接 hook 不假报新鲜，以及真实 Coordinator → ContextCompiler 的 pack 与来源回执。派生来源进入回执、需要先核实读取用途时不自动提供线索也已检查。TypeScript 检查通过。

上述检查验证宿主状态与调用机制，没有宣称真实模型会每次正确选择相关线索，也没有证明任意角色口吻已符合用户期待。后续实际对话需要覆盖：用户回来确实想接上；用户只是随口问完全无关问题；用户想休息；旧愿望已改变；准备材料当时可用但现在过期；明确提醒照常履约。允许模型在应当安静时不提索引，也允许用户回到旧事时继续读到完整原文。

源码已由 `ContextCompiler` 的 refresh hook 与 `RuntimeCoordinator` 的既有 AttentionService 连接，并纳入 `scripts/smoke.mjs`。本文件与测试单独保留，不以方案文本冒充真实模型或最终界面验收。全项目验证状态应以 `CURRENT_STATUS.md` 与本轮最终记录为准。
