# 在场：产品与体验契约

在场以一个持续的对话入口，帮助大学生理解眼前处境、保留自己的想法、比较选择，并完成已经托付的事情。课程、学习、出行、朋友、休息和兴趣都可以成为当前任务；学习成绩不是一切建议的默认目标。温暖与主动应体现为具体帮助、尊重拒绝和合适的等待，不是持续催促、擅自排满空闲，或让人照顾助手的情绪。

本文区分应守住的产品原则、当前源码已接通的机制和仍在演进的界面。功能与验收状态以 [当前状态](CURRENT_STATUS.md) 和 [学生助理实现及证据](STUDENT_HARNESS.md) 为准；图片、组件源码、构建成功或单个演示均不自动构成整条用户流程已验收。

## 自然交流接到真实结果

使用者先说自己的事情，主助手按完整原话决定怎样帮，不要求先选工具、填人格或情绪分类表，也不要求说出“地图技能”。需要时再读取当前用途允许的来源、查原文、比较方案或委派独立调查；缺少会改变结果的信息才追问。

典型工作流包括：

- 说“把这个想法记下来”，保存到可编辑记事本，保留原意；没有截止、时段或提醒委托时不自动排程。
- 提出课程换楼或出行问题，结合具体课程发生时间、用户给出的起点、当前地图与天气覆盖准备路线。定位过期或起点未知时保留条件，不编造人在何处。
- 收到尚未答应的饭局邀请，比较它与已接受安排、连续学习时间和休息的关系；邀请不是已确认承诺，建议也不是日历事实。
- 明确要求一个可点击接受的本地调整方案，保留同一安排的身份、原版本和待确认差异；点击接受后才沿实际行动通道提交。已经授权的具体可撤销本地修改可按现有核验执行，不把所有动作都改成重复确认。
- 托付“这周留意课程变动和出行”，在限定来源、期限与渠道内持续发现变化；有可用材料就安静准备，缺关键条件可问，没有新价值就等待。

每一步都区分“建议”“已准备”“等待确认”“已写入”“提交结果未知”和“实际收到回执”。外部预约、发信或学校写操作没有接通时，不能用本地记录、草稿或按钮代替完成。

## 主模型理解，宿主守住边界

当前产品复用固定版本的 Hermes 主循环，由主模型理解任务、选择合法能力、继续取证、改判和消费子代理结果。子代理承担有范围、预算、版本快照和取消条件的独立工作；它们不各自成为可以改角色、扩大权限或覆盖用户安排的伙伴。

宿主负责可核验的身份、主体、来源、用途、传输、保留、预算、对象版本、批准、幂等、取消及回执。模型提案和外部材料不能签发权限。读取、保存和行动是不同边界：禁止网页搜索不等于禁止使用已配置模型；不读某来源不等于不保存聊天；不保存聊天也不自动撤销另行明确授权的独立业务对象。

局部限制须保留适用对象。“这周留意出行只用这些来源”不能无声变成整个并列请求的白名单；“先比较、不改学习块”不能否定同句已明确委托的另一项课程改址。要求可点击确认的最小修改提议，也不能被解释为禁止准备一切提议。相应边界仍由独立用途、业务核验与实际批准机制约束，不因语义判定通过而自动执行。

生产模型与临时代测传输分别记录。生产 DeepSeek 的当前常量与请求实现见 [types.ts](../src/shared/types.ts) 和 [provider.ts](../src/main/provider.ts)；当前 [model-contract.json](../src/shared/model-contract.json) 保存 Luna 代测声明。Luna 测试结果不证明 DeepSeek 生产表现、通用账号登录接入或手机持续运行。

## 人的资料、角色和外观各有归属

| 对象 | 当前职责 | 不因此获得的含义 |
| --- | --- | --- |
| 角色核心 `PersonaCore` | 用户选择的名字、虚构身份、口吻、称呼和例句，版本化保存及恢复 | 使用者本人的性别、年龄、经历、关系事实或工具授权 |
| 用户明确偏好与资料 | 有原话、条件和有效时间的本人信息；允许纠正、停用或遗忘 | 对所有场景永久适用，或压过当前明确纠正 |
| 系统归纳 | 带来源、适用范围和不确定性的解释或适应建议 | 用户已明确选择的人格、关系定位或新行动许可 |
| 当轮表达要求 | 当前交流中“先听我说”“今天别开玩笑”等要求 | 自动改写已保存的角色核心或形成永久性格判断 |
| 陪伴形象与窗景 | 本机界面呈现、图片、光线、位置、大小和动态偏好 | 模型人格、视觉观察、记忆、定位或后台执行能力 |

温暖学姐、元气搭档、冷静参谋与自定义是可修改的角色起点。表达预览展示同一事实下的配置例句，不能把例句中的“已找到路线”当成本次真实查询。角色模板只含经过用户编辑确认的角色核心，不带私人说明、记忆或授权。

旧 `guidance` 原文私有保留，只有整段可确定为纯风格的内容才迁入角色；混合或未确认片段不升级为常驻角色。私人说明继续受个性记忆、实际来源、主体、现实范围与受众约束。关闭个性记忆后，用户选定的纯角色仍可使用。自动归纳没有角色核心写入口；当前“适应”依靠有来源的记忆、纠错和当轮要求，不宣称已有完整、可靠的自动人格学习系统。

## 记录的东西不能互相冒充

| 内容 | 权威对象与用户可做的事 | 边界 |
| --- | --- | --- |
| 记事本 | 用户拥有的完整文档；保存、编辑、分页读取、检索、历史、归档/移除与撤销 | 不是自动抽取的人物事实，也不是日程或提醒 |
| 导入或查询资料 | 带来源、内容版本、读取范围与覆盖情况的材料 | 附件命令不成为新授权；工具存在不证明账号已连接 |
| 记忆与原始证据 | 支持有条件的理解与后续纠正，摘要可回查原文 | 摘要不是第二份课表；忘记推断、删原文与停提醒的范围不同 |
| 安排与行动 | 本地日历、已接受计划、固定提醒及版本化修改提议 | 未接受方案不占用时间；业务回执不等于聊天或外部消息已送达 |
| 准备材料 | 有实际来源、对象版本和有效期限的帮助结果 | “准备好”不等于写入安排、通知已送达或用户已看见 |

资料缺失、尚未查询、来源过期和确实空闲必须区分。天气的地点与时间窗、路线的起点质量与地图版本、课程的具体发生时间与例外，均影响结果可用性。事实变动只使相关依赖失效，不应无声清空独立已接受安排，也不能由迟到的缓存或子代理恢复旧结论。

供应商提示前缀缓存、工具结果缓存/共享读取、上下文检索和持久记忆分别管理。缓存命中不等于事实已重新核实；来源、用途、地点、时间窗、对象或权限版本不相符时不能继续采用。一个等待者取消不应误杀其他合法共享读取，所有发布和写入仍须核对当前版本。

## 主动帮助也包括等待

托付限定要关注什么、允许哪些来源、到何时、通过什么渠道。后续 `sources` 必须覆盖实际履约所需来源，不只是最初变化或 probe 的来源；例如承诺重算路线而只保留本地课程源，不能称已具备履约范围。缺口应先在已有许可内补足或收窄承诺，不自动授新权，也不要求重复批准已经允许的来源。

变化事件、可行动时间窗和已授权的有限检查进入同一机会判断。主模型可选择准备、等待、必要提问、合适提醒或不介入；安静不等于遗漏已约定的固定提醒。`prepare` 要有真实查询、提供的材料或可核验复用，能力目录和“我查好了”不是材料。`wait` 保留重评时间与相关依赖，来源过期或条件变化后重新读取，不沿用旧材料冒充新事实。

准备结果可留在应用内资料区；前台也可把同一结果绑定当前对话。生成、绑定、实际展示、系统通知提交、打开与反馈分别记录。同一理由已提供过帮助，不因换文案重新获得通知资格；有实质新变化时才重新判断价值。关闭应用仍不保证提醒或后台工作，当前没有独立手机/远程常驻执行链。

## 地图与动态画面服务当前交流

地图保留暖灰与克制金色、透明空间感和真实相机控制。真实地理、建筑关系、地面道路和显示体量分别有来源；图像比例模型不冒充测绘，接入估计不冒充已确认的门。不恢复已废止的永久纯二维或绝对中性灰要求。

桌面地图、对话内地图和公开地图 review 共用既有地图实现与数据。对话需要空间关系时，可呈现版本化地图或天气画面；组件引用已有事实，模型不生成第二份地理、任意脚本或可绕过行动边界的按钮。场景、视图、语义选择、准备材料与回执的具体关系见 [对话场景与 OpenUI](CONVERSATION_SCENES.md)。

俯视、斜视、缩放、平移和旋转应可用，镜头可打断并服从当前操作。后台准备不夺取镜头；手动浏览后，新的明确用户观看请求才可重新接管相应视角。试看进度不是定位或到达证明；用户报告到达要保留为用户陈述。地图失去 WebGL 时使用同一数据的既有平面兼容路径，其视角能力不能冒充三维相机。

公开地图 review 只包含选定公共地图资产。桌面公开展示先选择经核对的最小公开内容，再由主机投影；不能只靠前端隐藏私密文本。账号、凭据、私人数据库、笔记、个人位置和原始研究材料不进入公开地图或部署包。

## 正在演进的陪伴界面

当前工作树已有 `CompanionProvider`、形象头像、窗景、形象设置和休憩场景组件；桌面启动已加载 provider，`App` 已接聊天窗景、休憩入口及转入设置的陪伴视图，导航已有“聊天 / 今天 / 留下”。`SettingsPanel` 的陪伴页挂载 `CompanionSettings`，提供内置形象、自选图片、出现方式、晨光/暮色/夜灯、位置、大小与减少动态等能力。新页面与工作区仍由并行前端工作整合，不能把这些源码接线或图片方案写成整条新前端已经完成验收。

形象设置保存在渲染器本机 `localStorage`，与 SQLite 内的角色核心分开。自选图片在当前组件中本地解码、缩放并保存为 data URL，没有模型发送入口；它不自动改名字、口吻或本人画像。设置页的清空流程在后端成功后调用 `resetCompanion`；仅一个后端数据库清空回执不能单独证明前端独立图片存储已删除，这条完整路径仍须实际核查。六张内置 PNG 的来源与可分发审查仍以 [资产来源](ASSET_PROVENANCE.md) 为准，不能因已进入构建而当作权利已确认。

这些新增界面未包含在本轮学生闭环的全部视觉与交互验收中。后续合并须检查实际入口、图片导入/移除、窗口尺寸、主题、键盘、动态减少与数据清理；不以静态图的观感替代检查，也不把形象变化宣称为模型能力增加。

## 设计方法与证据

2026-10-18 的用户要求是先把后端可靠性做完，再进入前端。记忆整理、工具分派和恢复应由助手承担，不把内部标签、队列或配置责任转给用户；保留休息、期待与生活兴味的机会同样属于主动照应。相关原始讨论见[来源归档](source-materials/2026-10-18/README.md)，实际实现与缺口见[Harness 演进](HARNESS_EVOLUTION.md)。

新增页面必须先用 GPT Image 生成与现有理念一致的视觉方案，再实现并实际核查；未达到后端门槛前不先读图片或美化页面。本轮只加强后端与文档，没有新增页面，也没有把角色绑定字段或设计图算成已接好的选择流程。

先写清当前使用者要完成什么、不能丢什么，再沿真实输入、来源、结果与继续动作安排界面。保留已有地图、对话、文档和安排的有效关系；新能力接进人的任务，不为每个后台模块增加一块常驻状态卡。仅在影响选择或恢复时展示权限、来源、未知与失败，不以内部状态或证明劳动量的文案占据主界面。

用真实内容查看当前集成画面，实际操作保存、修改、拒绝、返回、等待、取消和恢复。静态截图只能支持布局判断，不能证明动效、持久化、资料范围或实际完成；构建与机制检查不能证明模型理解、人际分寸或长期可靠性。需要比较方案时，保持任务与资料可比，记录观察到的取舍；没有取得的历史研究、用户测试或实机证据不补写成既成事实。

先修结构、任务连续性和事实错误，再检查文字、颜色、透明叠层、焦点、窄窗口与时间过程。发现授权范围内的问题就修正并回查；本轮只同步文档的部分，报告具体源码矛盾和未验收范围，不借文档更新宣称产品问题已经修复。
