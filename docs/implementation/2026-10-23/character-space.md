## 建议采用的空间合同

### 1. 同一个母图坐标系统

每一套可互动场景从一张完整、人物已正确坐在床/椅/桌旁的通过审阅母图开始。保留母图，派生以下同尺寸图层：干净背景、人物 RGBA、接触阴影、确需遮挡身体的前景（被褥/桌沿/椅扶手/植物）。人物提取不得改变母图中的面孔、姿态、比例或接触点；背景补全不得更换相机。用 Image 完成编辑，不能以代码裁切/调色伪装合格新设计。

场景素材记录至少保留 `id`、`characterId`、`moment`、`light`、`paletteFamily`、母图尺寸/hash、分层路径、分层来源、接触锚点和可移动表面。优先全幅同尺寸透明层；若为体积裁图，必须保存它在母图中的 crop rect，不能只保留新图片宽高。

Stage 只计算一次母图 → 显示区域变换，背景、人物、前景和阴影共享同一个 transform。响应式改变相机裁切/安全边界时一起移动；禁止背景 cover、人物 contain 分别适配。正文安全区由当前布局真实边界决定，不能继续依赖固定 51%/65% 渐变碰运气。

### 2. 坐姿移动沿可坐表面，站姿沿地面

每个通过审阅的姿态声明接触方式：seat/floor/desk。坐姿至少定义坐骨接触点与床/椅可坐边线；可沿已画好的表面移动，y 和投影比例随该表面求出，不能任意上下漂移。站姿定义脚底接触点与有边界的地面面片；只有资产确实支持时才允许深度拖动。桌旁阅读姿态同时声明桌沿遮挡层。

拖动沿 Stage 的逆变换把指针转换回母图坐标，在允许表面上投影。人物、接触阴影和需要跟随的局部道具同帧更新；前景始终在正确层级。限制真实移动范围：一幅坐姿不能靠平移穿过桌子，也不能沿床榻无限拉远。跨锚点时换已审过的相同角色姿态；不拉伸身体、扭曲面孔或用自由缩放冒充透视变化。

原“远近/高低”不能照原语义继续任意改立绘：坐姿的尺度服从相机和接触面，用户选择“近一些”应切到相应已审的近景/位置，或受同一投影约束。常规拖动不显示框与缩放角；轻点/键盘聚焦时显现当前一处操作。保留 Escape 还原、指针取消/失焦回退、键盘等价操作，拖动结束再原子保存，不在每帧写 localStorage。

### 3. 活动、光线与人的选择分开

建议场景分类由真实页面关系选择：chat（亲近但让开输入）、reading（退到内容外侧）、planning（不挡时间轴）、rest（完整空间）、play（更活跃但仍不挡内容）。night 属于 light，不应同时混进 moment；情绪不由用户聊到的关键词硬编码猜测。人物表情/姿态可以来自当前显式互动或模型有限呈现建议，不能将表情选择存成用户情绪事实。

一次只选择一整套光线资产，切换时整个空间一同过渡；没有昼夜擦除分界、左右箭头滑块或日景植物叠夜景床。换 palette 不得让人物肤色/原作发色被整体 CSS 滤镜染坏。浏览阅读区时安静退到对应锚点；用户选 hidden/corner 始终优先。

主页面正文不被植物侵入：近景植物归环境前景层，仅在空间区裁切；跨正文边界以真实布局排除，不用半透明白层把文字与植物一起洗淡。可保留窗外/窗旁适量植物制造景深。

1. 主代理亲选同一核心角色和统一母场景，先跑通跨分类与至少日/夜光线。确认母图人物青春感、辨识度、姿态和空间后才扩角色。

3. 产品默认与可选图库移除 mio/haruka/saku/nagi。历史/用户编写的人格文本、昵称、persona history 不删除；仅把已废弃的内置视觉 id 迁移到主代理选定的合格默认形象，保留自选图片及原收藏数据。旧 persona schema 仍能读旧版本；UI 不继续推广无关预设，不强制把已编辑性格换成祥子。
4. 新六人的 stable id 进入共用角色声明，渲染图库、persona visualBinding 与预设构造复用同一清单，减少 renderer/schema 重复拼写。只有核过并写完真实角色内容时才提供“采用相处方式”；单有图不能伪造人格预设。
5. 头像应来自同一个合格人物/场景包的明确头像裁框，不能指向品牌 mark。切图不动 persona；“采用角色相处方式”沿现有显式按钮/expectedRevision 保存，并保留用户 address；已有未保存草稿不能静默覆盖。现有 undo 继续产生新修订。

## 保存方案

沿 CompanionProvider 的单快照 owner 扩展到版本 3：保存当前角色、presence、light、reducedMotion、自选图/收藏/称呼，以及按 `scenePackId + surfaceId` 的有限位置参数。位置只保存 surface 参数/锚点 id 和必要版本，不保存屏幕像素或任意 transform。相同场景在设置预览/普通窗边/休息空间用相同参数；各活动确有不同站位时按实际场景保存，避免阅读退让覆盖用户闲聊位置。

迁移先读 v2，写 v3 成功后才采用新快照；写入失败保留旧值与当前可审阅选择。保留 legacy 大图引用策略、原图片预算、storage event 和“清空用户数据”覆盖视觉数据。写入应合并当前快照，避免主题、拖动和收藏同时改变时互相覆写。

Appearance 继续独立保存 theme/palette/readingScale/density，不因为换角色改主题，也不因为系统 light/dark 变化自动改 persona。宿主 persona 继续留在 SQLite 设置，不把场景位置并入模型人格、不增加模型或工具权限。现有数据库导出不含 renderer 图片；若本轮决定增加视觉导出，必须明确新增文件语义并走原导出入口，不偷偷把自选图片入 Git。
