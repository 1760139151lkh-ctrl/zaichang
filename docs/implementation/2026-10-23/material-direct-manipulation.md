# 原文拖入对话与批注移锚 · 2026-10-23

本轮从真实 App 中补齐两个原先只有选段按钮的直接操作：选中的原文可以拿到同屏聊天里，页边笔记可以指向同一文件的另一行。没有增加资料库、笔记 owner 或聊天输入。

## 已实现

- 原文选段浮层增加拖柄；鼠标与 Pointer Events 沿手势显示轻量引文、聊天落点与跟随反馈。放在对话区后，宿主沿原 `materialsQuote` 重读文件 SHA、页码和 Unicode 范围，确认同一会话与来源边界后才把地址放进原聊天输入。草稿和附件保留；离开、来源变化、失去指针、取消或放在外面均不提交。Escape 可以放回。原文页同时接入浏览器原生 `dragstart` 地址传递，drop 只接本阅读器当前内存里的选择，不从外部 dataTransfer 文字重建上下文。
- App 的聊天实际位于资料面板旁边，并不使用旧 children 插槽。新增一个共享聊天元素引用，把落点与回传接到真正的工作区；保留原阅读分隔线、同一输入与既有引用。
- PDF 页边笔记 pin 增加拖动、目标原文高亮和放下。目标来自原文字 run 的真实 Unicode 地址，不从屏幕坐标猜字或做相似搜索；没有可选文字的扫描页不伪造锚点。空格拿起、上下键换行、回车放下、Escape 放回；旧笔记版本变化会由宿主拒绝覆盖。
- `materialsMoveNote` 仅为本机直接操作：原 `MaterialsService` 重读 from/to 两个地址，要求同一文件与 SHA，再由 `NotesService` 用 note ID、expectedRevision 和旧出处事务更新同一条笔记的来源。正文、标题和笔记 ID 不变，产生新修订。放回原处走同一受检入口，只反向移动来源，不会回滚后来正文编辑或复活失效材料。

新方法没有进入模型工具表，也不因移锚授予材料的模型读取、业务执行或长期原件保存许可。

## 本机 PDF 边界

当前 Linux 云环境缺少 `dist-electron/material-runtime/manifest.json`。更关键的是现有 `scripts/material-runtime.mjs` 的 staging 明确只支持 Windows x64，PDF 主进程核验契约也要求锁定的 Windows canvas 文件。没有伪造清单、替换 PDF 解析器或绕开核验来制造通过。

因此本轮不声称真实 PDF 文件的“原生解析 → 文字层 → pin 拖动 → 宿主保存”完整链已运行。上面的原生文字拖聊、实际 owner 移锚边界及 PDF 组件交互是三类分别取得的证据；它们不合并成尚未发生的 PDF 端到端验收。
