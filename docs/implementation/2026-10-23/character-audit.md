## 需要修正的具体断层

1. `companion.tsx` 的爱音、灯当前均引用品牌 `mark.svg`。菜单和人格条目存在，实际人物资产未接入；它们不能算四位角色视觉已经完成。
2. 当前每位角色只有一幅基础图片。日间/暮色/夜间切换只改变房间背景与 CSS 滤镜；没有聊天/阅读/夜间动作。quiet 状态直接隐藏人物；非聊天主页面没有自己的角色场景接入。
3. App 原 `565–573` 行会在从未保存人格的 profile 中，因外观变化调用 `followDefaultCompanion`，进而直接替换默认 Core。这是形象与人格解耦的例外。主代理已决定移除这一 effect，保留初始澪和明确“采用性格”入口。
4. `selectCompanionPersona(..., 'use_character_preset')` 直接返回完整 preset Core，因此已约好的 `address` 会被清空。采用性格时应保护用户已有称呼；若要调整关系或称呼，应仍由原编辑入口处理。
5. 当前祥子/睦的 `readings` 是既存访谈解读，不是官方人物简介。它们与本次仅官方人物页的核对范围不同，不能把“傲娇、撒娇、恋人演绎”等项目选择标成官方设定。现有双方同意的亲密称呼和关系仍归用户。
6. 用户改动角色设定后，`personaGuidance` 仍能读取已绑定原作的 `establishedTraits`。它已说明用户设置优先；后续调整应继续保护这个优先级，不以新动作图恢复旧性格或覆盖自定义文字。
