## 已实现与已实际核对的部分

- 教务读取沿真实采集学期、原 bundle 和版本跨页继续；课程与无具体时刻考试分别保留来源完整性、当前页覆盖和未知时间，不从空页推断没有记录。
- 当前环境已再次正常刷新教务来源，沿同 bundle、同绝对时间范围与字段读到末页；刷新后的原 GPA 证明仍能定位同一历史版本。该来源复查和固定历史回读不冒充当前规划证明，私人课表留本机，详见[本轮教务复核](2026-10-23-stage02-academic.md)。
- GPA 的单科源行筛选在连接器实际执行前生效；主修汇总从同一保存资料的固定地址选择必要字段。真实 Luna 原问题已取得对应课程、总分母与主修分母并正确解释不同权重。最终后轮先找回原地址元数据，再沿同一 bundle/version 仅读五分均绩与分母；主代理亲核请求、两项结果、原地址及一次读取回执，实际响应型号为 Luna。原始个人数值和完整协议只留本机。
- Windows 原生位置与 Android LocationManager 连续流归同一 `WorkoutSessionKernel`。原始位置、因果滤波、几何候选、可信时间、暂停和每公里分段分别保留；模拟来源具有粘性。既有本地运动没有学校上传入口，学校有效次数仍须读校方结果。
- Android 位置桥绑定运动身份与订阅身份；进程退出后的停采、异运动拒绝、断线停止失败和重连确认已实际核对。停止需要同一运动的真实回读，不能把连接消失或租约等待当成停止成功。
- 本机运动草稿使用系统安全存储加密；撤回实时访问隐藏正文，取消删除正文、旧引用清理与远端停止各自记录结果。尚未完成的停采只保留独立加密的控制身份，不保轨迹、指标或原始时刻；重开也不能恢复已取消正文或猜测原设备。
- 真实 Electron 中已走断线取消恢复：本机正文退出后仅余加密清理控制；重开仍无运动正文、没有重开采样。明确重连原设备并以原引用重试后，取得同一运动的停止回读、零订阅/缓冲，清理键归零。主代理已亲读成员保存的有限状态与 SQLite 元数据证据；没有伪造旧无设备草稿来声称选择器已验。
- 地图运动控制先有 GPT Image 设计再实现组件；主代理已亲看设计稿与本轮独立预览。成员在该预览实际走完木木开始、暂停、键盘继续与结束，来源始终标为模拟。主代理随后正常重开同一加密 Windows 记录，核对暂停恢复、继续、弱定位不计里程、结束及原地图焦点恢复。
- 已接入唯一当前运动的有限只读摘要 `workout.current`，经来源、本人、现实、私下受众及当前用途核对；不含坐标、轨迹或设备身份，不开启位置，也不启动后台模型循环。真实 Windows 流与 Luna 对话已核：弱定位没有被说成零速度；取消对应运动后其回复与帮助退出，另一运动的合法历史保留。
- 原文要求的自动暂停已从静止标签补为真实控制：可靠低速与较好精度连续成立后，沿原 CAS/暂停/停采流程处理，继续仍需明确操作。真实 iOS 低速流已核自动暂停、计时点数冻结、明确继续与最终停止；主代理亲读原状态、有限摘要及原生零订阅回执。

## 正在完成的部分

2026-10-24 当前补记：用户要求像正常 MuMu 一样纯直连，现已修复把官方 HTTP 业务强改 HTTPS 的问题，并补齐场馆独立登录。现有连接器已完成新统一认证、本人资料、学期、锻炼汇总/流水和场馆订单查询；最终默认构建 helper 的资料与订单回读也成功，详见[纯直连恢复](2026-10-24-tiyi-direct-repair.md)。没有使用 WebVPN、改变默认读取许可或宣布十九项全部完成。下列旧 HTTPS 失败和 WebVPN 探索保留为过程记录，不再作为当前无法连接的结论。

用户已完成 Chrome 与内置浏览器的 WebVPN 登录。正常校方入口已生成体艺 HTTPS 代理地址；WebVPN 与代理内统一身份认证分别核对。原直接 HTTPS 业务回调的 502 是当时真实失败，不能据此继续声称用户未登录，也不能以功能目录或页面标题代替 19 项本人记录读取。连接器正在补独立的产品登录会话，现有浏览器 Cookie 不会被提取到源码或模型。

Android 真计步传感器链已接入，木木现场缺传感器，因此独立状态与步频保持未知；停止后位置、计步订阅和缓冲均实际核为零。iOS CoreLocation 桥已取得真实模拟器回调，始终标为模拟来源。持续一公里以上的模拟移动找出并修复了批量回调漏算时间的问题，修后公里分段与设定速度吻合。共享 MapLocationProvider 的最终入口、原生停止按钮与停采回执已实际核对；主代理亲看最终原生画面并核读有限回执。没有连接到 USB Apple 真机，不用模拟器结果证明真人位置精度。

用户随后确认没有使用 aTrust，而是添加 Clash 直连规则。主代理已亲看当前木木体艺主页、课外锻炼汇总和有效流水；原生读取已取得本人实际内容。当前 HTTPS 连接器路径仍单独核对，原生成功不自动证明这条路径成功。体测细项、个人历史和截图均留本机，不进入公共证据。

2026-10-24 用户要求按最新节点状态优先重试直连，现已重新执行产品连接器的认证与新资料读取。实际统一认证取得 200/302，体艺 HTTPS 业务回调仍为 502；无代理直出与当前 Clash 路径也分别复核相同结果。继续以直连优先，不把 WebVPN 手工登录作为本轮前提，详见[最新直连复核](2026-10-24-stage02-direct.md)。场馆的本人相关订单、培训和同伴 JSON 查询已据当前公开客户端源码实现，学校下一页另开新观察，原快照续读不联网。门锁密码、预约码与联系人身份字段在原来源边界精确去标；这些新个人接口仍未取得认证后的实际返回。

场馆发现与日期时段又补齐两条精确只读查询：先读学校原目录，在同一模式目录内重新核对场馆和场地原 ID，再查学校当地日期的时段；没有新增预约、取码、下单或支付。设施来源标记随保存快照续读，不把目录、时段或导航页改称本人记录。普通连接检查沿用已选方式，改回直连有明确入口；主代理已亲看关闭读取的新卡和两种入口，实际正常进程重开后 WebVPN 方式保留、两项许可仍关闭且不打开校方窗。认证后真实业务返回仍未取得。

MuMu 的真实 GPS 还暴露了开机时钟与 epoch 混用：现已保留原报告并把不可比时钟标为未知，GPS 不再因此误拒；GPS 与 network 的派生来源选择已在同一运动 owner 实现，全原始点保留。最新正常源流程实际保留未选 network 原点，自动暂停后点数与计时冻结，明确继续和结束均完成。先前短 API 流的原生 stream 身份与 Kernel 身份独立，其停止证据继续限于该 stream。主代理随后补齐普通产品 Native 同身份流程：自动暂停 24.936 秒、34 原点保持，卡片明确继续到修订 3、46 原点，再正常结束到修订 4、34.455 秒；同一 Native 身份回读零位置/计步订阅与缓冲，亲看暂停和结束画面。全部体艺动态正文仍未完成，因此不宣布本阶段完成。

实测又发现地图资源失败的原地重试缺陷，现已修复并沿实际阻断、解除、原按钮操作核到地图重新绘制，原地点选择、未发草稿和地图焦点保留。进一步修复公共入口误挂私人运动控件造成的白屏、两处本机出发入口及取消选路的临时起点残留，主代理亲核公开地点与路线详情，最新桌面运动入口仍在；详情见主代理桌面复核。最后一次既有全量检查为 282/282，Hermes 检查为 9/9；地图变更后专项 48/48、最终类型/完整构建及直接工作流通过。没有用检查通过代替认证后业务记录或真人户外定位。
