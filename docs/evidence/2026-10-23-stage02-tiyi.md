## 已实现

`src/main/tiyiAdapter.ts` 与 `src/shared/tiyi.ts` 是本轮开工前已有的未跟踪文件，保留并补齐。新增自有运行程序 `src/main/integrations/tiyi_connector.py`，由 Electron main 通过固定 JSON/stdin 调用，模型不能选择本机路径、账号、URL 或 shell。

- UAA 与体艺专用会话分别处理；复合体艺凭证按原五段合同拆分，过期后重新登录。所有认证请求仅走校方 HTTPS，证书校验保留。
- 19 个菜单 ID 与原项目一致，但本机支持目录与账号动态 `models/enable` 分开。运动汇总、原流水、审核状态、统计、运动详情、课程/逐次考勤、学期及规则有独立查询。
- 运动详情先查本人的 `sportId/tableName`，传原接口 `sportId/term`；课程先核学校的 `schoolYear/termId` 和本人的 `courseId`。不接受任意学生 ID。
- 学校汇总保留 `tips/datas`；流水 `isValid` 与每条 `validCount` 保留。有效一条流水不自动算一次评分；实践积分与本地手记不替代学校计次。
- 子系统 token 仅在学校菜单给出的同 origin/路径范围使用。场馆/体测等官方页面的文字、选择器和图片链接属于页面证据，`recordRead=false`；未运行页面 JavaScript，绝不据空页证明个人无记录。
- 完整响应字节、原业务数据、抓取时间、账号关联和会话均由 Windows CurrentUser DPAPI 保存于宿主私有目录。返回值去掉登录信息及已知身份值。分页固定同一 `snapshotId` 与 JSON pointer；离线续读不先强制重新登录。`coverage.extent=returned_response` 只覆盖收到的响应，不声称学校全部历史。
- 业务失败提示只使用连接器已知错误类的固定说明与恢复路径，不透传学校 `message/msg`、内部路径或票据。原始错误正文仍留在加密响应中；当前学期空记录保留为学校返回值，不改成登录或网络错误。
- 签名使用用户本机原兼容组件，通过 stdin 传入 secret。原 APK 二进制不进入公共仓库。宿主设置可传 `signerDirectory` 与 `signerDependencies`，或在私有目录 `connector.json` 写同名字段；环境入口为 `ZAICHANG_TIYI_SIGNER_DIRECTORY` 与 `ZAICHANG_TIYI_SIGNER_DEPENDENCIES`。

## 产品自持安全传输与当前路由

新增 `src/main/tiyiSchoolSession.ts` 与 `src/main/integrations/tiyi-transport.ts`。实现独立 `persist:zaichang-tiyi-school` Electron 分区、受限校方登录窗口、上游 origin/路径/方法校验、主进程持有 Cookie，以及通过 stdin/stdout 交接请求的窄桥；模型不能选择 URL 或读取 Cookie。没有导入 Chrome、Codex 或其他用户 profile。

`TiyiAdapter.getTransport()` 每次执行只捕获一次，由宿主明确选择 direct/WebVPN；默认无 transport 继续强制 HTTPS。WebVPN 方式才允许原学校 HTTP 地址在校方 HTTPS 隧道内传输，故不会静默回落公网 HTTP。取消或进程结束会一并停止宿主请求。仅在产品自持会话已经完成学校 SSO 时，也能消费该会话，不强制依赖旧客户端保存的密码。原始业务响应仍只入加密观察。

已亲读学校公开门户前端 `c68346a.js`，核定 `/user/info` 的路由参数与 ASCII `0` 补齐、AES-CFB/16字节段、IV前缀的编码合同。独立复核又发现 Electron 44.3.0 的 fetch/manual 重定向语义不能据标准 fetch 推断；该会话模块的专职审查成员负责修正，主代理负责 main/Bridge 接线。文件实现和检查通过不等于自持会话已经登录或19项资源成功。

用户后来明确当前成功来自 Clash 的直连规则，未使用 aTrust。本组未修改其规则、VPN 或权限。按这个新环境真实重查，canonical HTTPS 体艺回调仍502，`www` HTTPS API仍遇证书域名不匹配；这与原生 App 已经成功显示主页并不矛盾，当前官方2.9.7包仍含 HTTP `www.tyys.zju.edu.cn` 业务基址。仍优先核当下 direct HTTPS，不根据旧错误否定新现场，也不把原生成功冒充本产品 API 成功。

### 场馆动态记录的新增实现

随后进一步读取了当前公开 `/venue/` 首页及其实际 `chingo.2fa40da1.js`，并取得订单、培训与同伴页面的对应分块。这些均为不含任何用户认证的公开静态 GET；公共网络工具强制升级 HTTPS 后不能读取，由本机普通公开 HTTP GET 取得，未发送账号、票据或 Cookie。当前主 bundle 与原项目保存版本 SHA-256 相同，仍逐段核了函数和请求，未拿旧报告代替本次服务端数据。

已按源客户端实现 `/venue-server/api/orders/mine`、`/venue-server/api/venue/trains` 和 `/venue-server/api/buddies` 三项列表，以及下述两项场馆发现/时段精确只读 GET。场馆另有参数 MD5 签名，不能复用原生 cgapp 完整 URI 签名；连接器从当前校方 bundle 解码其公开配置，不执行下载 JavaScript，也不把签名常量硬编码进公共源码。账号菜单仍须开放相应入口；原 App JWT 仅用于源客户端明确支持的回退头，不声称它与场馆 access token 是同一个凭据。宿主桥只放开已确认的 GET 和其必要头，没有扩场馆 POST 或任意 URL。

订单保留“本人相关订单”语义，可能包括同伴关联订单；培训返回目录，不冒充本人已报名课程。订单和培训的 `upstreamPage` 是零基校方新请求，`coverage.upstreamNext` 只带资源、子页和下一页码；本机 `snapshotId/pointer/offset` 续读仍沿原响应，二者不混用。业务 code200 才采用记录，401、408、511、格式改变与空 `content` 分开。删除了仅凭源码出现 `rebuildToken` 就判过期的误判，只有实际登录表单、明确过期文字或独立登录跳转页才作相应说明。

独立复核又亲读了原页面实际消费的同伴电话、订单姓名/账号与 `doorPwd` 门锁密码字段，已在连接器与 Broker 边界补精确保护，原始值仍只在加密观察。预约码和门锁凭证不能随订单正文传给模型；通用业务 `code`、记录 ID 和业务状态保留。请求同伴列表 `page=-1/size=-1` 本身不证明完整，若返回总数大于实际内容仍标不完整；非法布尔/负数分页数量也不当作空记录。

当前自持 WebVPN 窗口正在完成独立认证，这三项产品动态记录尚待安全隧道内真实回执。一次正常公开配置 HTTPS 查询实际返回404，也保留为当前路径差异，未回落公网 HTTP 传认证。PFT、GMS、辅导站等尚缺经认证的实际业务 HTML/JSON；现存公开 PFT 页面只有统一认证跳转，不能猜测隐藏接口或将空壳标成已读记录。

### 场馆发现与日期时段

又直接取得当前公开 `chunk-7fcac090.46b26c39.js`（HTTP200、JavaScript、126,093字节），与原项目保存文件逐字节相同，SHA-256 为 `7f4b14c33069225955da83d014471eb31fcf0144abd118dba15e0974a26a0b64`。逐段核了 `getVenueInfo/getReserveDate/init` 和当前自有 query serializer，未发送任何认证信息。

保留 `reservationDateList/reservationDateSpaceInfo` 实际多日范围、`spaceTimeInfo/groupInfo`、容量、占用及限制原字段，token仍留在本机。`advanceReservationDays` 保留原值，0不被解释成“一天”或“无限许可”。日期按本项目学校 `Asia/Shanghai` 约定说明，不把源码没有声明时区的 `moment()` 当作独立校时证据。目录和时段均明确为设施数据，不能证明本人已入场、已有订单或完成运动；空闲状态也不单独证明可预约。

这两项产品查询尚需自持安全会话中的实际业务回执。当前源协议与实现已核，静态脚本返回200不算场馆数据读取成功。
