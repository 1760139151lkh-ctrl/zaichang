# 第二阶段：当前教务刷新与固定来源续读

2026-10-23。本页是主代理经用户已授权的正常学生信息 CLI 实际读取；不将学校排定课次当作实际出席，不含个人课程、地点、教师或成绩值。

## 本轮实际来源

在用户修正网络直连规则后的当前环境，正常 `quick classes --refresh` 重新取得两项课表来源，均有本次 UTC 采集时刻，来源完整性没有报告问题。这证明此时教务来源可正常读取，不能因独立体艺 HTTPS 业务失败概括为校园资料全部不可用。

首次有限结果保留原 bundle、绝对起止时间、所选字段、总匹配数、当前偏移和下一页。主代理随后使用同一 bundle 与同一绝对时间范围续读两页，未刷新，没有用重新求值的相对时间替换原窗口；末页为 `next_offset: null`。各页字段、时间范围及来源采集时刻一致，未出现嵌套截断。完整本人课表与逐页结果只留本机私有证据，不进入公共仓库。

这里的完整性说明当前查询及来源范围，不证明学生实际到课，也不扩大到所有年份、全部考试或未公布事项。本轮是 CLI 来源复查，不冒充最新桌面界面或真实模型再次读课表。

## 旧快照没有随刷新丢失

刷新当前教务头后，主代理沿此前 GPA 回合保存的原读取证明，通过现有 `CampusSnapshotProofs` 普通方法核对：状态为 `historical_snapshot`，原 bundle 对应的版本仍一致。该步骤只核本机来源身份和字节版本，没有解密或重新读取成绩值。

原快照回读与当前规划不同：回读可以继续固定历史版本；规划和行动仍需各自的当前来源证明，不用旧成绩或旧课表替当下安排签字。GPA 的真实模型后轮和两字段读取另见[专项记录](2026-10-23-stage02-gpa.md)。

本轮没有新增测试、fixture、runner 或临时功能脚本。私人结果与已有诊断资料保留，未做新增清理。
