# Stage02 主代理桌面复核

本页记录主代理自己操作的独立 Electron 预览，不将成员的操作写成主代理已验证，也不代表第二阶段全部完成。

## 加密运动草稿

成员在本轮私有预览中开始 Windows 本机记录，明确选择加密保存在本机并正常关闭。主代理随后只读核对 SQLite：轨迹条目仅有密文，头部保留运动身份与计数，没有输出、公开或传模型原始位置。

主代理使用同一数据目录正常重开应用，经菜单打开原校园地图和运动卡。实际取得同一运动身份、原测点修订与 63 条原观测；卡片先暂停，记录用时固定在 01:01、可信时间 00:00，显示已加密保存，不因关闭期间经过的时间继续计时。

明确点击继续后，Windows 实际位置重新到达，计时增长；系统报告约 2933 米精度，这些位置未计里程，距离仍为零、配速与步频未知。随后正常结束，实际经历停止中的状态，最终固定为 01:26，显示本次结束和再记一次，没有继续按钮，也没有学校提交回执。

Escape 收起运动卡，原地图仍在，焦点回到运动入口。主代理最后正常关闭自己的预览，进程退出 0。没有关闭或操作另一用户会话的产品窗口。

这证明本轮系统安全存储的正常关闭重开、同一身份继续与结束；不证明真机户外精度，也不将特殊停采失败的所有组合预填为通过。

## 体艺连接卡与真实问题

新卡先有 GPT Image 局部图，再做活组件。主代理亲看图稿及当前设置页，实际从校园资料进入直连检查，再点击停止。原始检查与停止操作有对应反馈，但停止导致隐私版本更新后，设置错误跳回阅读与节奏，丢失当前页和反馈。原界面成员修复后，主代理用新构建沿相同触发重走：停止后仍在校园资料页，旧检查结果退出，宿主实际读取开关显示已关闭；随后的 Tab 到达导入按钮，确认键盘可从原停止位置继续。只保留纯界面导航和按钮焦点，敏感草稿仍清空、组件仍重挂载。

首次通过卡片的只读学校会话检查，没有打开登录窗，实际取得暂时无法核清的状态。独立无凭据学校请求为 302、路径 `/login`；产品首次结果不能因此冒充已核登录过期。宿主修复把上传 Writable 的 close 误作 HTTP 失败的问题，并加入不含地址、正文或凭据的错误分类后，主代理用新构建的同一卡片再次检查，实际显示本产品的 WebVPN 会话需要登录，检查本身未弹窗。这个观察确认登录状态判断恢复；没有在该次 UI 操作中捕获原始 302 正文或头。

浏览器原有 WebVPN 登录与产品自己的会话分别持有，不读取浏览器 Cookie，不改用户 Clash 规则，也不以原生体艺首页成功代替产品连接器的成功。

后续独立成员经正常产品 Bridge 核到总校园读取关闭时的连接早退、单开总权限不自动授体艺子权限、撤回总权限关闭自有校方窗；主代理亲读有限返回与窗口计数。主代理随后在自己的普通隐藏启动实例，沿菜单、连接与资料和校园资料打开新卡，亲看关闭态：对应开关名称清楚，个人连接不可用，学校会话状态与停止仍可用。展开其他方式后，直连与 WebVPN 两入口、已选学校 WebVPN 均实际显示；宿主两项读取许可均为关闭，没有打开校方窗。连接方式保存在原宿主元数据。主代理以原应用退出入口正常关闭该实例，核对进程退出，再沿原数据目录正常重开：方式仍为 WebVPN，两项读取许可仍关闭，校方窗没有打开；仅在当前进程保留的运动正文已退出。用户正在认证的另一个自有产品进程始终保留。

## 当前产品的同一 MuMu 运动

为保留用户正在使用的校方登录窗，主代理通过原有 `--hidden` 正常启动自己的独立产品实例，没有测试模式、假轨迹或另建内核。经原 Bridge 开始 MuMu 步行，实际自动暂停在 24.936 秒、34 条原观测；多次后读和普通 renderer 重载后，该身份、修订、计时和点数保持不变。亲看卡片的静止暂停说明、模拟位置、未知配速和明确继续入口。

随后实际点击继续记录，原运动修订到 3，定位恢复 listening，取得 46 条原观测；再点击结束，修订到 4、计时固定 34.455 秒，卡片显示本次结束和再记一次。Native 端始终回读同一个运动 ID，结束后位置与计步订阅、两类缓冲均为零。原始双来源和未选点保留，模拟位置不变成真人里程或学校有效次数。

本次补齐当前 Native 服务、唯一内核与实际卡片的同身份证据；先前独立 API 工厂那次不同 stream ID 的证据仍按原有限范围使用。截图和原始回调仅留本机；隐藏窗口图像不证明户外精度、触摸或动效质量。当前留给用户的独立校方登录窗口保持打开，没有为这些复查抢走认证焦点。

## 地图载入失败后的原地继续

本次正常预览发现地图程序资源读取失败时，界面直接显示内部资源地址；旧重试只重读地图资料，也无法修复失败的程序。修复后错误态只保留具体标题和原重试入口，程序载入与绘制各自恢复，迟到旧回调不能覆盖新实例。

主代理在自己的产品 renderer 临时阻断本地地图程序资源，实际取得同一错误态；期间沿正常搜索选择东一教学楼，并保留一份未发送的聊天草稿。解除阻断后点击原来的再打开一次，实际地图重新绘出、错误入口退出、原教学楼选择与原草稿保留，焦点回到地图应用区域，没有重新加载整页或重启进程。主代理亲看失败与恢复后的图像；原观察只留本机，不把黑图、过时帧或构建通过算作绘制成功。

桌面与公共地图仍共用一个地图实现，单一构建入口保留延迟载入；显式模块重试才换本地资源查询部分，成功后继续复用。构建同时核对地图程序的 JavaScript 和 CSS 已在宿主依赖中，避免只换入口却遗漏依赖。上述操作证明本次实际资源故障恢复，不预填所有 GPU 或设备故障组合。

继续以正常公共预览入口运行时，主代理又实际复现白屏，浏览器报运动订阅方法不存在。根因是公开入口没有显式传 `publicOnly`，误挂载了只属于桌面的运动控件；修复入口后亲核错误退出。地点详情和路线细节中的本机出发入口一并限于私人地图，公开选路按 Escape 清掉临时起点并回到原地点详情。

主代理在正常浏览器重新走公开地图的本地程序资源阻断、地点选择、解除、原按钮重试：实际重新绘图，地点保留，焦点回到地图，页面无运行错误；该浏览器的资源记录实际取得带 `mapRetry=1` 的新请求。随后亲看取消后的原地点与路线详情，公开页没有设备出发或运动按钮；最新桌面构建仍正常绘图并保留运动入口。只在本机预览，未部署公共站点。
