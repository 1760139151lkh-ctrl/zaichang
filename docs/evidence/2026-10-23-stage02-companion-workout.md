# 第二阶段：让陪伴接到同一份真实运动

本记录对应本阶段的本地运动摘要与对话接续。当前运动仍由 `WorkoutSessionKernel` 单独拥有，地图控制和主助手读取同一对象；没有建立另一条聊天循环、轨迹库或定时鼓励器。

## 实现

`workout.current` 从已有运动取得一次有限摘要：运动身份、控制与测点修订、读取和观察时间、距离估计、配速、精度、暂停、最近分段、实际保留方式与学校未提交状态。它不开始、继续或修改采样，不提供坐标、轨迹、设备身份或任意文件地址。入口沿既有 Broker、来源范围、`evidence:read`、本人／现实／私人受众与本轮实际用途逐次核对。

没有合格测点时，配速保持未知，零距离估计不证明本人没有移动。测点时刻和收到时刻分别保留；旧点刚送到不会因此变成新观测。模拟测量、真实设备与未知来路由本次记录分别表达；Broker 的宿主是否为替身与测量本身的来路分开。学校有效次数仍归学校体艺记录，本地完成、实践积分和学校认定各有依据。

主模型自己理解这些观察，并按当前人物、关系与原话接话。既有 `campus-sports` 方法更新为区分体艺学校记录、教务实践材料和当前本地运动。点击开始记录本身没有建立持续托付；这里没有固定陪跑台词，也不会按每个测点启动模型请求。

方法第五版分别列出本地运动、单独体艺、教务实践和导入材料的可用路径。总体条件核对完整的跨来源学校进度；学校连接缺少时保留条件缺口，眼前本地运动仍可继续。体艺有效跑步次数不改由教务实践材料证明。

## 精确取消与来源接续

`WorkoutSourceProof` 只保留实际摘要的原运动 ID、版本与时刻，不复制运动正文。正常对话、旧回复回读、子调查采用、准备和帮助记录继承这个地址。新的测点、暂停和结束不会抹掉当时合法的观察；明确取消则沿 `workout:<uuid>` 的精确删除屏障撤回对应工具摘要、派生准备和后续引用。

宿主取得的证明沿本轮上下文进入保存路径，模型填写任意元数据不会成为新来源。原运动和记录在取消时各有自己的清理结果，正文删除、设备停止与原引用撤回分别表达。独立运动没有随另一条运动的取消被整类删除。

## 本轮实际观察

- 使用现有模块构建与正常 Node 入口，在独立私有 Store 中启动 Windows 系统真实连续定位，并经同一 Kernel、Broker 与 Harness 使用已授权 Luna。没有生成测点样本或新增测试代码、fixture、runner。
- Windows 本次报告约 2.9 公里的定位精度，实际没有可用于计距的测点，距离估计为零，配速与步频未知。主模型真实读取后准确说明了这些区别，没有将它说成本人没有走动，也没有查学校次数或新增监测。实际响应标识为 `gpt-6-luna`。
- 第二份独立运动再次通过正常 Harness 读取，并留下自己的摘要证明。先前运动的暂停、结束和新一次开始均未使原合法观察失效。
- 通过既有帮助 owner 保存第二份运动真实回复所对应的帮助记录，然后正常取消该运动：当前正文为空，该运动的证明不可读，相关助手正文清空，帮助记录不再开放；另一份运动的原证明与原回复仍可读。采样同时实际停止。
- 取消后沿同一对话继续真实 Luna，助手自然转向轻松的钢琴与猫的话题，没有新的工具读取，也没有恢复被撤回的运动证明或数字。
- 直接读取公开受众或排除运动来源的范围，均被拒绝，未带出摘要正文。
- 当前 TypeScript 检查通过；按既有构建方式重编译并运行工作方法专项，6 项通过，未改测试。完整项目最终检查及真实 Electron 控件结果由本阶段总记录汇总。

上述 Windows 观察验证了真实来源进入主助手与精确取消的路径，未证明户外移动精度、真实跑步配速、公里分段或所有人物长期陪跑效果。原始事件、对话、摘要和取消前后状态保存在本机私有证据目录，没有放入公开仓库。
