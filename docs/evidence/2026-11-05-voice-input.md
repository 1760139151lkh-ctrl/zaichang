# Windows 本地语音输入

本轮接续已有 Claude 实现，并按用户本轮纠正收敛为默认可用的离线听写。原会话全文、用户消息、调研附件、历史技能、每次工具输入与代码写入都保留在仓库外的本机恢复档案；这些私人会话材料不随源码公开。

## 交付行为

默认只有原输入框中的麦克风图标。点击后同一位置变为停止；原输入框内展开实际声音的历史波形、录音时长与取消图标。停止后恢复麦克风，按实际结果提供剪贴板恢复／复制和撤销。读屏名称、键盘与按需提示保留，界面没有语音弹窗、下载入口、偏好工具条或解释段落。

语音写进当前光标或选区。同一语段的 partial/final 原位更新，手动修改过的范围交回用户。取消或撤销恢复仍完整归属于本次听写的文字及最初选区；识别器撤回临时猜测时也恢复原选中文字。中文组字期间暂存识别更新，发送之前等待最后一句收尾。外部替换草稿后停止旧听写，避免迟到识别写进新对象。

结束时尝试保留识别文字。纯文字／格式文字的旧剪贴板在内存中短期保留，可恢复；图像、文件及其他复合格式保持原样，由用户按需点击复制。取消、公开展示和失效会话在原生写入前后复核；写入期间失效时，仅在剪贴板仍属于本次文字的情况下尝试恢复。语音本身不发送消息、不保存笔记，也不形成记忆。

## 识别与方案取舍

沿用固定 `sherpa-onnx 2.0.1 + SenseVoiceSmall INT8 + Silero VAD`。模型提供普通话、英文、粤语、日语和韩语；sherpa 官方给出 Windows、Android、iOS 及相应语言接口。[官方平台与语言说明](https://k2-fsa.github.io/sherpa/onnx/sense-voice/index.html)。

SenseVoice 使用有界音频窗口逐次重识别，最后按停顿定稿。它不是原生状态式流式模型；本轮优先保留已有可用识别和统一模型资源。Paraformer 的在线模型适合进一步降低首字延迟，增加第二条识别模型也会增加资源与维护成本。[在线 Paraformer 官方资料](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-paraformer/index.html)。Zipformer 是同运行时中的另一条流式候选；这里不把不同公开数据集的 CER 或不同硬件的吞吐混成绝对排名，也没有宣称本轮已实测优于 VoiceKey。[sherpa-onnx 官方实现](https://github.com/k2-fsa/sherpa-onnx)。

宿主、记忆索引和识别使用不同 ONNX Runtime 二进制。识别在独立 utility process 内运行，音频以 16 kHz 单声道小块进入，仅在内存中保留有限窗口。运行时读取随软件分发且通过锁定大小和 SHA-256 检查的模型文件，没有联网下载接口。构建时仅在源码检出缺少固定资源时准备公共模型；已有合格文件直接复用。

`scripts/speech-runtime.mjs` 将 worker、原生库、VAD、239,233,841 字节模型、315,894 字节词表及许可放进 `speech-runtime/`。开发和安装后的程序都从该资源目录的 `model/` 读取。`ZAICHANG_SPEECH_MODEL_ROOT` 是可选本地覆盖；旧用户数据目录中的合格模型仍能读取。具体协议与许可见 [speech lock](../../runtime/speech/lock.json) 和 [第三方声明](../../THIRD_PARTY_NOTICES.md)。

## 本轮已取得的观察

- 全新隔离数据目录首次启动返回模型 `ready`，未创建用户模型下载目录，未出现准备或下载对话框。
- 合成语音通过真实 AudioWorklet、Bridge、独立识别进程和输入框；文字写入“前文｜后文”的中间，partial 继续修改同一语段，停止后保留 final。
- 选择“原字”后录入并取消，原稿完整恢复为“前文原字后文”；结束后的撤销也恢复原稿。
- 录音中点击发送，发送前的“今天下午3点”经收尾成为“今天下午3点，我们。”，当前录音会话随后为空。
- 实际剪贴板包含复合格式时保持原样，显示按需复制入口；本轮没有为制造验证数据覆盖这份剪贴板。纯文字恢复沿已有宿主实现，本轮未以覆盖用户复合剪贴板来追加该分支实测。
- 已查看 1280×900 与 560×800 的实际录音画面、真实声波列和 5.59 秒操作截帧。波形和按钮外圈随采音电平变化，停止与取消立即收尾；没有播放装饰性假声波。
- 窄窗氛围页返回按钮原位于 112px 标题栏内，已移至标题栏下方并实际点击返回，原输入仍在。
- 根据用户明确选定的棕色整页，分别生成封面、聊天、搜索的完整页面稿并亲看。白色越界稿退回；聊天与搜索采用棕色承托、暖金控件，录音反馈进入各自输入区的正常布局。搜索标题、查询、波形和结果行互不遮挡，1280×900／560×800 的完整边框均已查看。
- Tab 离开搜索输入后，最后一句更新没有抢回焦点；手打“（手写保留）”后取消，只移除本次语音，保留手打内容。减少动态时过渡时长为 0。
- 通过现有音频入口注入非法块触发真实宿主拒绝：原 partial 保留，录音结束，撤销恢复“甲｜乙”。未用假成功掩盖错误，也未新增测试文件或 runner。
- 修复原生输入监听先于 React 更新而还原旧稿的问题：监听延至本次输入处理之后，并标记尚待同步的手动输入。停止听写后替换新稿及继续键入均保留新文字；原听写范围消失或发送清空后，撤销入口退出，不再作用于新稿。
- 通过 Chromium 原生组字输入接口在录音中将 `ni` 改选为“你好”并提交，识别继续在原位收尾；取消后仍为“前文｜你好后文”。这验证了浏览器组字事件与识别交错，未冒充实体 Windows 输入法候选窗操作。

## 全角色、页面和交互复核

本轮后续依用户要求扩大到逐项实际操作。十位内置角色分别选过四种手动氛围，共 40 个选择/采用画面；各自时间中性白天、夜间也分别查看，共 20 个画面。每位的采用、返回和重新进入保留选择。夜间分支只改隔离数据里的应用时区并暂关天气，之后还原，没有改系统时钟或开启定位。补齐的 35 幅场景及 11 张整页设计见[资产索引](../../前端视觉创新设计/2026-11-05-alignment/asset-index.json)。静态母图、完整场景转场、声波和独立人物动画分别记账，未宣称完成多活动人物视频矩阵。

发现并修复的实际关系包括：日间页面上下露出白底；爱音撑在坐垫上的手被右侧选择区遮住；完整母图因等待不存在的分离背景而没有报告人物边界；窄栏工具把输入挤成数行；设置的浅色面板、头像/氛围 Tab 顺序和采用后失焦；“更多”内容挤进中列、原生选择框变白；笔记目录与正文两次缩窄；共读聊天栏对比不足；选段工具压住原文；日程确认被拉成椭圆，以及窄窗关闭按钮被顶栏盖住。首次冷启动录屏还捕捉到头像逐步解码，已改为启动预解码十张头像，选择区在完整解码后统一呈现并恢复选中焦点。

实机操作范围与结果：

- 角色收藏/取消收藏保留当前对象；留在页角、暂时收起、只留灯光分别采用后复核。自定义图导入、三个位置/远近控制、取消及移除沿现有本地 owner 工作；没有新增下载动作。
- 中窗分区及窄窗的选择、设置四分区、留下、笔记、共读、日程编辑分别亲看。设置字号/间距离开重进仍保留，减少动态有独立实际观察。角色改名草稿在切换分区后保留，取消还原原值。
- 本机隔离数据里的记忆经新增、保存、暂停与删除复核；对照的是实际记录，非界面假卡片。成功反馈收敛为短暂图标与读屏状态，真实错误仍可见。
- 笔记正文通过真实识别进程听写、停止和撤销；保存、重新打开、收起后放回及窄窗点击保存均走正常入口。搜索输入的听写、撤销、分类、真实笔记命中及打开原页也分别检查。
- 录音中切到“今天”，当前采音停止，最后识别仍落在原光标位置；返回后的撤销恢复原稿。
- Python 操作真正的 Windows 文件对话框打开既有公共 PDF，真实读取页码、原页面、文字层、115% 缩放、鼠标选段、引用进草稿及阅读窗的鼠标缩放/拖动、键盘移动。重启暴露出待发送附件初始页覆盖固定阅读窗的问题，修复后重开仍为第 2 页、文字视图及 115%。文档内容未发送给主模型。
- 通过正常对话直接保存“检查语音界面”的 20 分钟本机安排，真实日程回执、时间轴试放、采用、撤回、编辑时间及取消均已操作。该次 `contextReceipt.provider.observedResponseModels` 实际返回 `gpt-6-luna`，不以配置名代替返回证据。
- 地图的搜索、建筑选中高亮、缩放、旋转、回北、全貌，以及基础图书馆到紫金港大食堂的两点路线实际操作完成；路线保留真实入口未知/估计连接含义。没有使用“定位到本机”、开启位置服务或登录大学账号。

以上采用 Python Playwright/CDP 与必要的 Python 原生窗口操作，没有使用 Computer Use。未新增测试文件、fixture、通用遍历脚本或 runner；项目原有 285 项检查、Hermes 9 项及构建均通过。本人发音/噪声准确率、实体输入法候选窗、外部账号、系统通知投递和手机真机仍不能从这些观察推出。

## 最终构建与 Windows 运行

`npm run build`、现有 `npm test`（285/285）和 `npm run test:hermes`（9/9）通过。通过既有 stager 和 electron-builder 生成本机 `release/voice-final-20261105/win-unpacked/`；源码同步与历史 GitHub EXE 发布分别处理。

实际从该运行目录启动，工作目录也设为程序目录；未设置模型覆盖路径。全新隔离数据目录首次返回 `supported=true`、模型 `ready`，没有用户模型下载目录和准备弹窗。分发目录的模型和词表分别为 239,233,841 与 315,894 字节，SHA-256 与锁文件一致，37 项语音运行资源及原始许可都在包内。合成语音经过包内识别进程完成出字、停止及取消。

另一次不带假设备／假音频启动参数，实际打开 Windows 麦克风：48 kHz、单声道；随后停止所有 track，状态为 `ended`。没有记录或读取这次真实麦克风的转写内容。合成语音的识别与界面证据仍不能替代本人发音、口音、噪声准确率或手机实测。

## 手机端

保留事件含义、语段 ID、取消与结束回执、16 kHz 音频约定和来源于同一编辑对象的写入语义。iOS 使用 AVAudioEngine 与原生麦克风权限，Android 使用 AudioRecord；接到 sherpa 的 Swift／Kotlin 接口，替换 Electron utility process 和 Bridge。模型作为手机应用的资源部署并验证，不继承桌面绝对路径或源码构建目录。

原生编辑器以 composing region／marked text 处理尚未定稿的语音，与系统输入法协作；跟随当前选区，用户编辑或切换对象立即收回旧写入权。移动端需重新实测音频会话中断、锁屏、蓝牙、耳机、后台、触摸取消和软键盘遮挡。

桌面重读窗口的功耗不能直接套到手机。手机可在同一事件契约下比较轻量流式 partial 与 SenseVoice final，依据真机延迟、温度和耗电决定。剪贴板分别适配 UIPasteboard 与 ClipboardManager，处理系统预览、粘贴授权、敏感标记和跨设备复制规则；当前桌面偏好不是跨设备记忆。手机实现及上述真机结果尚未交付。
