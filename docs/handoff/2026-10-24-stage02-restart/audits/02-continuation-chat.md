## 3. fork 新增回合究竟调查了什么

### 3.1 真实诊断链

新增回合没有沿用“统一认证成功就等于业务成功”的说法。沿现有连接器观察到 CAS 登录页/公钥 200、登录与接续 302，随后 canonical `tyys.zju.edu.cn/cgapp-server/cas/appLogin` 返回 502；已有会话读取 profile 也停在同处。它只读取加密诊断中的 host/path/status，没有把票据、查询参数、Cookie 或业务正文输出到公共文档。

同一 HTTPS 业务入口无代理直出与显式经 Clash 均为 502；TLS 本身校验通过。`www.tyys.zju.edu.cn` 的 HTTPS 入口出现主机名不匹配；证书仅覆盖一层 `*.zju.edu.cn` 与 `zju.edu.cn`，不覆盖这个双层主机名。旧 HTTP 业务入口只做了无凭据跳转观察，没有在该 fork 沿它传认证。

这证明的是**当时选用的 HTTPS 业务入口不可用**，没有证明学校所有业务不可用，更没有证明用户提供的 MuMu 正常现场不可信。fork 的源码审查已找到线索：旧桌面克隆使用 `.no_proxy()` 和原 HTTP 地址，而当时在场 direct 固定 HTTPS，并会将 HTTP 导航升为 HTTPS。
