# Architecture
Electron main owns credentials, SQLite, permissions and side effects. The renderer requests work through a restricted preload/IPC bridge. Harness owns the foreground run, shared budget, cancellation, current permission/version and result publication. runtime/hermes.ts sends framed stdio requests to the pinned Python sidecar; the real upstream AIAgent performs the model/tool loop while all model transport and tool execution return to the host.

A model-visible tool such as look_up resolves through ToolRegistry, RuntimeCoordinator and CapabilityBroker to an available provider. Providers implement specific resource contracts, source/coverage/freshness and permission checks. The external university connector remains a separate user-installed process. External writes need ActionRuntime authorization, idempotency, inspection/cancellation and an actual receipt; unsupported services are unavailable.

The host launch can explicitly select GPT-6 Luna Max through the existing Codex account transport. It remains a single-completion adapter: Hermes runs the loop and the host executes tools. The requested and returned model must agree. Network startup honors explicit proxy environment variables or the enabled Windows manual proxy, without changing system settings; PAC execution is unsupported by this Node route. The request deadline fits inside Hermes RPC and the run respects its actual scope expiry. Account transport output limits are enforced after completion, so they cannot cap upstream consumption in advance.

Public source semantics are explicit at control parsing: the local public map and fixed-city weather are distinct from personal records, private place roles and device observations. Excluding personal information does not itself exclude a requested public map. Actual source restrictions, private-role access and location-sharing checks remain authoritative.

Read caches are bounded to 64 entries and require a live expiry plus matching owner/workspace, subject/world, sources, grants, purpose, audience, retention, inference and policy/data versions. Session-only scopes never retain resolved read results in this cache. Cached and coalesced reads consume the caller's read budget and each create a receipt. In-flight work is shared only inside one scope; cancelling a waiter does not wait for the original request. Refresh discards that key's old entry. Public document handles bind scope, final URL and content hash, so identical documents in another scope cannot replace the current reader's handle. Provider prompt caching is separate: receipts retain reported cached input tokens and keep missing usage unknown. Privacy barriers clear capability and conversation protocol caches.

Memory keeps original evidence and derived assertions separate. ContextCompiler retrieves relevant evidence/assertions for the current scope. MemoryService extracts/reviews supported proposals and Repository applies versioned transactions; explicit correction, retirement and forgetting invalidate derived use. Turning off ordinary memory use is not equivalent to erasing stored evidence. Privacy fences must accompany recovery.

The map is a fixed public geographic database plus an optional explicit desktop overlay. CampusMapAdapter validates component hashes, resolves stable places, filters permissible access candidates and invokes WalkingGraph.shortest. Ground routing and display geometry are separate. MapSheet manages selection and uses the same camera/rendering engine in desktop and web. CameraOwnership rejects stale asynchronous view suggestions.

Review-web replaces only the map storage/desktop bridge boundary with immutable build-selected public files. It imports the real CampusMapAdapter, WalkingGraph, MapSheet, MapLibre engine and existing planar fallback. It has no IPC, account/assistant state, model requests, user filesystem, database or profile persistence. A browser storage read outside the allowlisted public files throws.

Build generates Electron code, renderer assets, the stdio map bridge and the isolated review surface. Windows x64 additionally stages its licensed native PDF runtime; Linux builds product JavaScript and the web surface. Hermes setup is pinned and separate, with locally generated receipts in ignored .runtime. Source, runtime dependencies, API/service access and real business success are distinct verification layers.
