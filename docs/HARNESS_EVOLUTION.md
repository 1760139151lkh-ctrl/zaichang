# 在场 Harness：记忆、主动照应与执行能力演进

日期：2026-10-18。起始源码为 `e16d3fe575feb4edef72f42bc6a129bc3d6b58fe`。本文记录本轮需求、修改与验证边界；全项目现状仍由 [CURRENT_STATUS](CURRENT_STATUS.md) 汇总，入口见 [PROJECT_NAVIGATION](../PROJECT_NAVIGATION.md)。逐项源码研究、版本和取舍见 [本轮研究记录](research/HARNESS_RESEARCH_2026-10-18.md)。

## 这次要解决的问题

在场主要服务个人。打开后应像来到熟悉、温暖而安静的地方：助手记得事情为什么重要，主动把能做的准备妥当，在合适时机参与，也能尊重休息与独处。用户不用反复说明工具名称、维护记忆标签、检查后台队列或承担工作分派。

本轮把记忆放在首位，主动调用、日程、工具与角色一致性随之完善。后台先可靠，前端后设计；后台只是有类型、能构建或通过合成检查，不足以放行新增页面。需要新页面时，仍须先按项目设计理念用 GPT Image 生成方案，再实现和实际检查。本轮后端阶段未读取前端参考图片，也未新增前端页面。

“主动”包括记得未完的话、准备资料、找到可行时间、分享用户期待的好消息、保住一段休息和在合适时机跟进；不是只增加提醒次数，也不把每次倾诉都转换成计划。

## 原话如何成为可继续使用的记忆

原始聊天或资料先保存为有来源的证据；模型提出带主体、条件、时间、引用和操作类型的理解候选，宿主校验后才生效。当前纠正可立即改变当轮回应，不必等后台整理全部结束。日历、笔记和学校记录仍各有权威对象，不能在记忆里复制一份当前课表后让两份事实竞争。

这次独立审计复现了五类具体断点：预算耗尽后尾部内容不再恢复；先截前50条再筛有效期导致有效记忆被挤掉；提取数组换序导致新事实被旧幂等键吞掉；只更正一句却让整段原文失去可搜索性；更正已保存但依赖旧解释的主动准备仍可用。修复针对这些连接，不推倒既有记忆系统。

候选身份改由证据定位及候选语义决定，不由数组位置决定。检索把权限、验证状态和有效时间放在排名分页之前，原文分页作用于完整可读集合。更正使用 Unicode 字符位置，不复制另一份私人正文；读取旧内容时带上历史和替代标记。依据服务在恢复、重新登记与复查时核对精确片段，停用受影响解释及其候选；其他有效事实和独立接受安排继续存在。

旧数据库升级到 schema v6 增加原文限制定位表与记忆恢复元数据表。恢复按持久尝试时间公平选择，暂时传输失败退避，避免第一项持续失败饿死后续新原文。旧版本软件不能直接打开较新schema；回退需遵守现有备份和隐私恢复屏障，不能把旧备份恢复成被用户要求忘记的状态。迁移不把旧记录缺失的位置猜成已知。

## 主动工作沿同一主循环继续

来源变化、时间节点和有效托付进入现有机会服务。调度器只负责何时重评、合并与不并发运行；生活意义由同一主模型判断。失败退避、下次复核时间和期限在持久对象里，进程重启可重新算出最近唤醒，不依赖内存定时器记得之前发生了什么。

不同托付之间轮转，临近最后可行动时刻的事项优先；高频来源不应长期挤掉其他事项。明确的固定提醒继续走自己的持久调度，不被普通机会预算吞掉。前台繁忙或模型不可用时不刷空推理；恢复后重新核对，错过窗口也不能谎称按时完成。

后台复杂调查可以使用有限只读子任务。任务指令和变化信号都不是新的用户授权；子任务只拿父托付实际允许的来源和必要原文片段。上下文在序列化和回执前应用来源投影，只有片段授权时不能放出完整派生摘要或片段之外的限制名称。它们不保存记忆、改日历、发通知或再次委派。父任务采用报告前还要检查原托付、范围、版本、取消状态与证据；子代理的文字摘要不单独构成真实准备完成的凭据。

最终参与仍可为安静准备、当前对话顺势提起、等待、必要询问、提示或不介入。用相同理由重写文案不产生新通知权。温暖应通过已经做妥的帮助与合适的分寸体现，而不是暴露后台状态面板。

## 按需技能如何使用实际能力

`discover_skills` 返回名称、描述和版本；`read_skill` 返回该方法的完整内容和当前能力需求。六个内置方法为：

| 方法ID | 帮助完成什么 |
| --- | --- |
| `memory-investigation` | 找回前情、展开原文、核对时间与例外、组织有界独立调查 |
| `schedule-planning` | 比较可行时间、保留连续块、接已有日历与回执 |
| `contextual-outing` | 结合具体承诺、地点、天气和空气质量准备出行 |
| `campus-sports` | 核对体育真实记录与计次口径，比较自愿运动窗口 |
| `quiet-initiative` | 根据已有准备、新价值、窗口和限制选择参与时机 |
| `recover-action` | 核查失败阶段、未知提交、原动作回执与可恢复成果 |

目录搜索只筛选文档；没有命中某个词不证明相应能力不存在。简单任务可直接完成，不必先读取指南。指南本身没有网络、安装或执行脚本副作用，`available` 也只说明当前入口与连接已知可用，具体数据覆盖和动作授权仍靠每次真实操作核查。

## 规划从“给建议”到可复核草案

`planning.preview` 继续核验少量明确方案；`planning.draft` 从有时区的窗口、任务时长区间、依赖、资源可用窗口、保护时间、准备/收拾、休息和交通成本构造多任务草案。已接受的可移动安排仍占用时间，不能未经授权移走。未接受邀请是情境，不是硬承诺。

草案使用已声明时长上界并保留原区间；未知估时不默认填一小时。分段须明确允许且满足最小连续时长。没有排入的任务带原因和剩余量，不能因构造器没找到位置就宣称全局无解。输出保留日历版本、依赖、条件和 `applied:false`；`PlanningApplicationService`给出绑定完整占用的采用提议，准备/收尾并入工作块，转场、休息与保护留白也有真实占用。

采用时按`acceptanceProposals.order`保留完整参数与`planRef`，经既有授权动作入口逐项提交。每一步在SQLite事务保存前重新核对日历全指纹、身份、策略、顺序、精确参数及来源版本；缺少外部版本复验器时，依赖该来源的方案阻断采用。票据仅存在本进程内，最长15分钟，重启或过期须根据真实日历重算。整组不是原子提交；提交后进度记录真实部分完成，不因后续失败把已保存安排说成不存在，也不重复创建。

这样的输出支持“这一段实际能安稳坐下多久”“今天少安排一些”“顺路准备一件小事”等帮助。后两者若涉及自动调整、实时馆藏或外部预约，仍需真实授权和对应连接，不能只凭创新点子写成已完成服务。

## 角色、事实与相处连续性

角色核心描述助手如何出现和说话，个人记忆描述用户提供或由证据支持的事情，日历与动作回执描述真实业务状态。三者不能互相替代。用户当轮说“今天别开玩笑”先影响当轮，不自动改掉长期角色；更多行为观察也不能把系统推断升级成用户明确设定。

`visualBinding` 记录用户明确选择的形象ID、角色名和撰写说明，已有外观ID有稳定文本映射。换图本身不读图片、不推断人物原作设定、不改用户身份，也不授予新权限。字段可随角色配置保存、恢复和模板导入导出；对应前端选择流程尚未接线。

人格示例现在同时提供其事实前提，例如“日程保存失败”或“路线确已准备”。不同风格可以表达同一事实，但不能因为例句写着“安排好了”就捏造当前成功。风格差异需要真实模型验证；本轮配置检查只能证明参数、版本和事实前提没有丢失。

用户希望选定具体人物后可以辨认出相应性格。现有祥子、睦等外观ID只是稳定关联入口，不构成完整角色知识库；具体人物、原作版本和用户希望的演绎应由明确配置提供。未取得设定时不能凭名字或图片编造人物性格，更不能把经典剧情写成与用户真实经历。

## 验证层级与当前门槛

验证分为类型检查、真实SQLite等宿主机制、锁定Hermes加合成模型回调、真实模型加合成生活事实、真实外部来源、长期使用与前端体验。前一层通过不能替后一层背书。

本轮启动时重新执行基线检查：类型检查通过，既有机制141/141，锁定Hermes 9/9。Node为24.19.0、npm为11.9.0，与仓库声明的24.18.0/11.16.0有差异；31项直接依赖版本一致，Hermes固定0.21.2、commit `d595e636c83aa0b9606d4e914e1140ae9c796897`，Python3.13.16，锁及既有补丁经过核对。基线数字不冒充新增功能验证数字。

本轮新增机制检查和整体复查由 [CURRENT_STATUS](CURRENT_STATUS.md) 记录最终命令、数量与范围。新增人格/技能6项、记忆连续性6项、依据限制3项、机会调度7项已分别执行通过；其他并行修改须以整体最终复查为准。真实模型测试限定现有Luna代测通道；当前环境缺少可用入口，未调用真实Luna或生产DeepSeek，未认证学校账号。

因此本轮不能宣称“记忆和人格长期可靠”“助手在所有场景会主动调用”“后台完全完备”。新增前端门槛尚未通过；下一步应先补真实模型纵向验证、外部连接和必要恢复证据，再进入图像先行的界面工作。
