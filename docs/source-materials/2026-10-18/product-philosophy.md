## 二、我怎样对“大学生和他所处的世界”建模

我把建模落实为一种**有依据、能变化、允许不知道的理解**。它需要回答：这个人此刻重视什么，已经承诺什么，哪些选择实际可行，什么还不清楚，以及助手怎样参与才有帮助。

模型包含十二个互相作用的维度：

| 维度       | 需要理解的具体内容                   |
| -------- | --------------------------- |
| 身份与角色    | 学生、室友、组员、朋友、家人、兼职者等并行责任     |
| 当前重视的事情  | 学会东西、守住承诺、休息、收入、陪伴、探索、玩乐、独处 |
| 目标与愿望    | 长期追求、短期目标、试试看、正在比较、已经暂停     |
| 承诺与进行中的事 | 具体课程、作业、考试、聚餐、申请、等待回复       |
| 时间与生活节奏  | 每一次实际课次、临时调整、连续学习块、休息和转场    |
| 身体与可用精力  | 本人自述、授权设备记录、覆盖缺口、当下能承受的负担   |
| 学习与创作过程  | 卡在哪里、试过什么、需要哪些前置知识、材料和设备    |
| 关系与边界    | 想不想赴约、有没有答应、共同空间、分工、公私表达    |
| 空间与可达性   | 起点质量、目的地、入口、路线、天气、开放时间      |
| 金钱、物品与设备 | 预算、到账时间、证件、材料、电量、网络、工具兼容    |
| 制度与数字能力  | 学校规则的适用范围、工具是否接入、权限和数据完整性   |
| 相处方式     | 助手角色、称呼、语气、幽默、鼓励方式和主动偏好     |

例如，一个学生说“最近不想去图书馆，因为施工太吵”，系统应该记住**这个原因、适用时段和条件**。施工结束后，原来的否决理由可能已经消失。不能只存成“用户不喜欢图书馆”，之后长期把图书馆排除。

同样，“朋友约吃饭”也需要分清：收到邀请、想去、已经答应、对方改期、自己想取消。这些状态会带来不同的规划和沟通动作。用户尚未答应时，助手可以比较安排、起草回复；不能先把它当作已经成立的社会承诺。

这套模型也保留了空白：位置没变不代表孤独，日历空白不代表精力充足，接口没返回不代表现实不存在，过去几次的选择也不自动成为永久性格。

每条都有至少三个情境事实，以及目标冲突、触发事件、所需证据、预期行动、表达示例、反事实和可观察验收。

其中有 **25 条静默、18 条等待**。这个比例只是迫使评测认真检查时机，绝不作为产品的通知配额。其余也包含陪伴、好消息、探索和庆祝，避免把学生生活全部写成作业和风险。

几个典型的判断分岔：

- **朋友约饭。** 学生想见朋友，明天展示还需半小时准备，地点在校内，可以形成留有返程余量的方案。把地点改成往返两小时，结论就应改变。
- **考试换楼。** 最新考场通知可以使旧路线失效，助手应准备新路线和出发建议。若入口信息缺失，就只能确认到楼，不能编一个入口。
- **十二天还差三次体育打卡。** 你的例子被保留，并补上后续窗口、计次规则、天气不确定性和身体自述。如果以后仍有几个可用时段，就不能说“今天必须跑”。
- **一直待在宿舍。** 没有不开心的自述时，不从定位制造情绪标签。如果学生主动说孤独，才接着原话提供陪伴或社交选择。
- **切换人格。** 改成安静简洁后，表达应更新；课程、已接受计划、事实和权限仍连续。
- **撤销来源访问。** 正在工作的子代理、缓存和待发布材料都要重新核对范围，旧结果不能迟到后又恢复被撤回的用途。

另外的 **12 条连续时间线**专门检验“一开始判断正确，后面还能不能跟得上”。它们包括调课后约饭、天气再变化、用户选择、任务完成、撤销、重启和迟到结果。每一步只开放当时可见的信息；未来事件和期望答案留给评测者。

## 四、这份包怎样定义主动性

我采用的定义是：

> **在已有了解和适用授权下，自己发现与这个人有关的机会，先完成有用准备，选择合适的参与时机，并根据后续变化继续负责。**

要做到这一点，最关键的是下面几件事。

### 1. 一次广义托付可以持续生效

学生可以说：

> “这学期帮我留意课程变化和出行，能先准备就准备。”

系统就可以在这个范围里派生关注、查看已接入且获准的来源、准备路线。无需每一项都重新要求“调用地图”“调用课表”。

这解决的是你最在意的问题：助手生活在有时间、空间和持续事项的环境里，能力应随需要自然被发现和使用。

### 2. 同时发现已知变化和陌生机会

只盯已经登记的关注事项，会漏掉此前没想到的需要。因此方案同时保留：

- 已有计划所依赖的事实发生变化时，定向复查。
- 新来源或未关联的有效变化进入有预算的语义判断，寻找新的关联。
- 时间窗开启、临近最后出发时刻等节点，即使数据没更新，也重新判断。

这里的便宜筛选只负责版本、重复、时效、范围和预算。**“这对学生意味着什么”继续交给主模型理解。**

### 3. 先准备出真正可用的东西

主动出现时，应尽可能已经带着结果：路线、核实过的考场、几个可行时段、整理好的笔记、可以接受的日程修改方案。

例如，以下表达成立的前提是路线确实已经准备好：

> “明天换到东边那栋了。我把新路线放好了，出门时间也重新算了一下。”

这种热情来自确实替人省了心，而不只是多加几句鼓励。

### 4. 选择怎么参与，也继续处理后果

可以安静准备、在当前对话中顺势提起、等下课再说、问一个关键问题、适时提示，或者不介入。新的事实到来后，还要撤销旧路线、停止失效建议、修订受影响的计划。

同时，**用户明确设定的定时提醒有自己的约定**，不能因为模型觉得“现在保护专注更重要”就擅自取消。我在场景审查中专门修正了这类混淆。

日程变化也分两步：先形成同一对象的修改方案；当前指令或既有授权允许自动调整时再提交。朋友改时间本身不会自动替用户授权改日历。

## 五、人格、记忆、缓存和子代理的安排

### 人格：用户设定的角色，与助手学到的理解分开

方案允许你说的小姑娘、学姐、虚构角色或动漫角色风格，也允许完全自定义。包里提供了“温暖学姐、元气搭档、冷静参谋”三个起点，以及可留空以后补的角色细节。

我将它们拆成三部分：

- **角色核心**：名称、身份呈现、口吻、例子，由用户编辑，能预览、保存和撤销。
- **自动适应**：从互动中形成带证据和条件的相处建议，用户能纠正。
- **本轮需要**：“今天温和一点”“先听我说”“直接给结论”，先照顾眼前语境。

更多行为观察可以增强某个推断的依据，但只有用户确认或编辑，才能把它标成“用户明确设定”。

这里有一项实际审查后才补上的重要设计：旧 `guidance` 可能混着角色口吻和私人经历。因此不能为了让人格始终生效，把整段文字改成常驻提示。方案保留私有原文，只迁移确定的纯角色内容；混合部分继续遵守原有资料范围，角色导出和预览也不夹带私人内容。

### 记忆：保留原文、条件和更正后的效力

系统需要能够回答“为什么这样理解”，也需要在用户纠正后真正改变后续行为。摘要负责帮助检索和节省上下文，原文仍能回查。

LongMemEval 的实验发现，用抽取摘要或事实完全替代原会话，可能因信息损失影响细节问答。这支持保留原始证据，但论文结果不能直接当作在场已经具备可靠长期记忆的证明。[proceedings.iclr.cc](https://proceedings.iclr.cc/paper_files/paper/2025/file/d813d324dbf0598bbdc9c8e79740ed01-Paper-Conference.pdf?utm_source=chatgpt.com)

遗忘也按对象处理：“忘掉这条推断，聊天留着”，就撤回推断及相关派生，防止再次提取同一结论；不会反向把原聊天全删掉。

### 缓存：节约重复工作，同时让新事实及时生效

包里区分了供应商提示前缀缓存、工具事实缓存、检索与情境缓存、在途共享请求。

它们都需要合适的范围和版本。例如天气缓存要区分地点和预测时段；用户换了起点，旧路线不能继续复用；权限改变后，已有缓存也不能成为绕过新范围的通道。实际缓存收益看供应商回执与耗时，不凭提示词看起来相似就报命中率。

### 子代理：沿用已有接入，给独立工作使用

复杂而独立的研究、方案比较适合委派；几个简单查询可以直接并发，普通聊天和一条笔记不必拆成多个代理。

每个子任务需要相关上下文、来源与权限版本、共享预算、取消条件和结果契约。父代理必须消费结果、处理冲突；用户改主意后，迟到结果不能又把旧计划写回来。当前接入和相关测试源码已经存在，包里要求 Codex 在此基础上验证和扩展，没有把它写成从零开发。

## 六、外部研究怎样影响了方案

20 个来源条目都写明了实际阅读范围、版本、支持什么、不能证明什么。主要借鉴如下：

- **Muse 与 Grok Bot**提供了长期目标、持续工作、自然交流和主动跟进的产品方向。它们的官方发布材料没有公开完整调度与记忆算法，因此我没有假装可以照搬其内部架构。[about.fb.com](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/?utm_source=chatgpt.com)
- **OpenClaw、Khoj**提供了可静默的后台工作、个人资料与自动化共存、结果投递等实践参考。方案吸收这些机制，继续使用在场已有的宿主和引擎。[OpenClaw](https://docs.openclaw.ai/gateway/heartbeat?utm_source=chatgpt.com)
- **混合主动交互、JITAI**帮助把“需要帮助”“现在是否适合接收帮助”“直接做、询问或等待”分开。这些研究给出判断维度，不能直接证明某种通知频率适合大学生。[out.doc](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz-1.pdf?utm_source=chatgpt.com)
- **ProActor**把动作是否合适和时机是否合适分别评估，推动我加入行动窗口和连续时间线；本包没有把论文效果迁移成在场的性能承诺。[ACL Anthology](https://aclanthology.org/2026.acl-long.832/?utm_source=chatgpt.com)

手机路线也作了实际约束核对。当前桌面定时器不能直接变成手机全天候运行；Android WorkManager 的周期任务至少十五分钟，且执行时间不精确。因此移动版需要单独验证持续运行的宿主、位置、通知和恢复机制。[developer.android.com](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work?utm_source=chatgpt.com)

你提到的 ChatGPT 登录同样单列了里程碑：目前有官方集成路线，但应用授权、账户状态和所选模型的实际调用需要分别验证，不能把现有测试通道改个名字就算完成。[OpenAI Developers](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server?utm_source=chatgpt.com)
